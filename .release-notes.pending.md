## Breaking changes

- **`xorDistance` is removed.** FRET now measures with a single metric everywhere — ring distance,
  `min(clockwise, counterclockwise)` — exported as `minDistance`. A bit-XOR metric is not
  interchangeable: it treats the identifier space as a bit-tree, so it maximizes exactly where arc
  length minimizes, and its magnitudes are incommensurable with the ring-circumference-derived
  thresholds (cluster span, near-radius) it was being compared against. Callers modelling the ring
  should switch to `minDistance`; results will differ, because the old ones were wrong near the
  wrap-around seam.
- **`seedDiscovery` is removed.** It dispatched `peer:discovery` straight at the node object, which
  reaches application listeners but never libp2p's own peerStore — libp2p's event forwarding runs
  internal → node, never node → internal. `FretPeerDiscovery`, exposed through
  `peerDiscoverySymbol`, is now the single emission path.
- **`FretService.importTable` is now `async`** and returns `Promise<number>`. Capacity enforcement
  needs the self ring coordinate (a SHA-256 of the peer id) and import is commonly called before
  `start()` has cached it, so enforcement awaits the hash rather than skipping it. Callers must
  `await`; a fire-and-forget call races enforcement against whatever runs next.
- **`FretPeerDiscovery` takes a lazily-resolved snapshot source** (`DiscoverySnapshotSource`, a
  `{ store, selfId }` thunk) rather than a captured store reference. libp2p reads
  `peerDiscoverySymbol` during node construction, so the discovery object must exist before the node
  it reads its store from. A bare `DigitreeStore` is still accepted.
- **`SerializedPeerEntry.avgLatencyMs` is `number | null`.** `null` means no round trip has ever
  been timed, and scores neutrally. Previously `0` doubled as the "no data" sentinel, which made a
  genuinely fast peer (localhost measures 0 ms on Windows' ~15 ms clock) score *below* one measured
  at 300 ms — and relevance drives both next-hop preference and capacity eviction. A field absent in
  an older snapshot reads back as `null`.

## Added

- `openRpcStream` and `releaseRpcStream` are exported from the package root, along with the `Stream`
  type they trade in. `openRpcStream` is the connection-selection helper that filters to open
  connections, prefers a direct connection over a relayed one, and sets
  `runOnLimitedConnection: true` / `negotiateFully: false`; `releaseRpcStream` is its mandatory
  partner — it aborts once the caller's signal has fired and `close()`s otherwise, because `close()`
  against a stalled remote is unbounded. Note `negotiateFully: false` defers an unsupported-protocol
  failure to the first read, so a caller that never reads must treat "opened" as "not negotiated".
- `deadAfterFailures` config knob (default 3).
- `DEDUP_TTL_MS`, `SizeEstimateOptions`, `PeerPatch`, `RingCursor`, `RingWalkPage` are now public.

## Fixed

Two nights of ticket work, ~70 commits. Highlights:

- **Inbound RPC handlers leaked a connection slot on malformed input.** A handler that failed
  partway through — which a malformed or misbehaving message could cause — left its stream neither
  closed nor aborted, holding the slot forever. Found by codec fuzzing. Every inbound handler now
  goes through one registration seam (`registerRpcHandler`) that closes a stream the handler left
  open on success and aborts it on error, so the leak is unrepresentable per-handler rather than
  patched at five call sites.
- **Ring-distance consolidation.** One metric — `minDistance` — for neighbor walks, next-hop
  selection, the payload-inclusion heuristic and the relevance sparsity model. Coordinates straddling
  the wrap-around point are now adjacent, as they should be.
- **Membership classification strength.** A weaker or staler signal can no longer overwrite a
  stronger, more recent one. `member` is set only by positive proof and cleared only by repeated
  direct proof of absence; a single failed protocol negotiation is evidence, not a verdict.
- **Store index/tree invariant.** Exactly one tree entry per peer id, with the id index pointing at
  it. All mutation funnels through one write seam, and coordinate width is enforced there — a
  wrong-length coordinate used to sort into an arbitrary ring position with no error anywhere.
- **Pooled maintenance.** A stabilization tick's 14–20 RPCs run concurrently under one tick-wide
  budget instead of serially, so one hung peer costs the tick its budget rather than costing every
  peer behind it its turn. Warm-up passes share the same pool.
- **Selector forward progress.** Only candidates strictly closer to the key than the forwarding node
  are eligible, so messages cannot drift backwards with only breadcrumbs and TTL to stop the loop.
- **Discovery coverage.** The emission sweep resumes rather than restarts, so the whole table drains
  in `ceil(N / batchSize)` ticks for any population; previously, past the tracking bound, roughly half
  of known peers were never announced — always the same half.
- **Hot-path allocation.** `coordToHex` measured 38% of total CPU in the N=100 simulation; it now
  uses a 256-entry lookup table. It runs on every store write and every ring walk.
- **A leaked async operation** that held the Node process open after the suite passed, plus an exit
  watchdog so a future leak fails the run loudly instead of hanging.

Test count went 285 → 655.
