## Fixed

- **Inbound RPC was refused on relayed connections.** Peers reachable only through a circuit relay
  — phones, browsers, laptops behind a home router — could call every FRET protocol but answer
  none of them, leaving them connected yet effectively unroutable (the ring-maintenance and lookup
  RPCs are how a peer is found). libp2p will not carry a protocol over a *limited* connection
  unless both ends opt in for that protocol; FRET opted in when dialing out and not when
  registering its handlers. `runOnLimitedConnection: true` is now baked into `registerRpcHandler`
  as a constant, so all five protocols — and any protocol added later, or registered by a consumer
  through the exported seam — inherit it.

  This is the second half of a fix already landed in `@optimystic/db-p2p`: with only that side
  fixed, a relay-only peer can answer every Optimystic protocol and still never be located, because
  the FRET lookup that would find it cannot complete. **Downstream consumers resolve `p2p-fret`
  from npm, so they need this published release before they see the fix.**

- **`registerRpcHandler` no longer overwrites libp2p's stream-cap defaults with `undefined`.** When
  a caller supplied no `maxInboundStreams` / `maxOutboundStreams`, those keys were passed through
  as `undefined` and spread over libp2p's registrar defaults, replacing 32 / 64 with no cap at all.
  Absent caps are now omitted. FRET's own registrations always supply real numbers, so this only
  affected outside callers of the exported seam.
