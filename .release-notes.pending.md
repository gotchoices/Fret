## Breaking

- **The peer-dependency floor is now the libp2p 3.3 line.** `p2p-fret` requires `libp2p` ^3.3.11, `@libp2p/interface` ^3.3.0 and `@libp2p/peer-id` ^6.0.15 (previously ^3.1.3, ^3.1.0 and ^6.0.4). A consumer still on libp2p 3.1 or 3.2 must upgrade libp2p before taking this release.

## Changed

- **Runtime dependencies moved to the releases libp2p 3.3 itself uses:** `uint8arraylist` ^3.0.2, `it-length-prefixed` ^11.0.1, `multiformats` ^14.0.5, `uint8arrays` ^6.1.1, `uint8-varint` ^3.0.0, `@libp2p/utils` ^7.4.1, `@libp2p/logger` ^6.2.13 and `@libp2p/peer-record` ^9.0.16. A libp2p 3.3 project now resolves one copy of each, with two effects:
  - The exported `readFramed` is typed over the same `uint8arraylist` 3 lists a libp2p 3.3 `Stream` yields, so passing one needs no type assertion.
  - A FRET checkout can be portal-linked into a libp2p 3.3 workspace again. Before, Yarn refused the link because FRET's `it-length-prefixed` and `uint8arraylist` ranges conflicted with the parent's.
- `main-event` (^1.0.1), which FRET's peer-discovery module imports at run time, is now a declared dependency. It used to resolve only because libp2p happened to install it, which a strict package manager (pnpm, Yarn PnP) would not allow.
- Ring coordinates are unchanged: `multiformats` 14's SHA-256 produces byte-identical digests, so every peer and key keeps its position on the ring.
