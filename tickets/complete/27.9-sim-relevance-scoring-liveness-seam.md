## What the implement stage changed

Two files, both under `packages/fret/test/simulation/`. Nothing in `src/` moved.

- `liveness.ts` — `LivenessDeps` gained `modelFor(selfId)` and `coordOf(id)`.
  `recordContactSuccess` / `recordContactFailure` each gained a leading `selfId` argument and now
  call production's `recordSuccess` / `recordFailure` from `src/store/relevance.ts`, writing
  relevance and the health counters back through `store.update`.
- `fret-sim.ts` — a `models` map (one `SparsityModel` per peer, created in `addPeer`), the new dep
  members in the `LivenessModel` construction, and `current` threaded into `handleRoute`'s two
  scoring calls.

Net effect: the simulation's stored relevance is now real scoring output rather than a field
every entry left at 0.

## Review findings

**Fixed in this pass (minor)**

- **Two clocks.** `recordContactSuccess` scored at an injected `now()` while
  `recordContactFailure` scored at its `time` argument. Those two disagree on the scheduler's
  `processEvent` and `advanceTo` paths, so success and failure scoring would have been stamped
  against different times in the same run — a determinism hazard. `recordContactSuccess` now takes
  `time`, both call sites pass it, and the `now` dep is gone from `LivenessDeps`, the private
  field and the deps literal.
- **Docs were stale.** The *Testing strategy* routing bullet in `docs/fret.md` still claimed the
  simulation's eviction is degenerate because "every entry ties at relevance 0" — no longer true
  after this change. Rewritten: eviction is still degenerate, but for the store *shape*
  (unbounded stores plus a per-tick full-window gossip merge), not for tied scores. Rest of that
  section read and confirmed to match the code.
- **Nothing asserted the scoring does anything.** Every existing simulation assertion holds just
  as well with all relevance parked at 0, so the change was unpinned. Added
  `contact scoring writes real relevance, reproducibly` to
  `test/simulation.partition.spec.ts`: after a seeded run it asserts every stored relevance is a
  finite number, at least one is non-zero, and a second run at the same seed reproduces the
  per-peer values exactly. Added inline rather than filed, since none of the three downstream
  tickets on this theme (`28-sim-relevance-scoring`, `27.95-sim-relevance-scoring-merge-sites`,
  `28.5-sim-metric-guard-case`) covers it.

**Recorded at the code site, not filed (tripwires / accepted tradeoffs)**

- **Per-tick whole-store scoring cost.** The sweep scores every reachable entry every tick, so
  cost is O(peers x store size) per tick. Fine at the sizes the simulation runs; a `NOTE:`
  tripwire at `recordContactSuccess` states the revisit condition.
- **`reprobeDeadEntries` applies no success scoring**, where production's dead arm scores an
  answered re-probe. Judged out of scope and left as an accepted-tradeoff `NOTE:` on
  `reprobeDeadEntries`. The divergence is one tick of deferred success credit, not a permanent
  loss: `contactSweep` runs before the re-probe pass on every tick, and a restored entry is no
  longer `dead`, so the next tick's sweep contacts and scores it. Changing it would rewrite
  stored relevance and `lastAccess` — the key the re-probe rotation and any future
  capacity-bounded eviction order by — for one tick of credit.
- **Non-null assertions** in the two new deps (`modelFor`, `coordOf`) bang on map lookups. Both
  unreachable as crashes today: `handleLeave` only sets `alive = false` and nothing deletes from
  `peers` / `stores` / `models`, and both deps are only called with an id the harness is itself
  sweeping or routing from. Stated in a comment at the deps literal, and `handleLeave`'s existing
  "reclaim here if memory runs out" `NOTE:` warns that reclaiming would turn both into crashes.

**Checked and clean, with reasons**

- **Resource cleanup** — the only new long-lived state is the per-peer `models` map, which shares
  the lifetime of `peers` / `stores` and is documented alongside them. Nothing else allocated.
- **Error handling** — no new failure paths: both scoring calls are pure local writes through
  `store.update` against an entry the caller has already read.
- **Type safety** — no `any`, no widened types; `npx tsc --noEmit` clean at the final tree.
- **Source hygiene** — both files stayed small, the new functions are short, and the comments
  added state reasons rather than restating code. No size-debt to report.
- **Modularity / DRY** — the change *removes* a divergence rather than adding one: the simulation
  now calls production's `recordSuccess` / `recordFailure` instead of leaving relevance unwritten.
  `src/store/relevance.ts` was consumed as-is and is not in the changeset.
- **Correctness details** — omitting `avgLatencyMs` from the success patch is correct per
  `recordSuccess`'s own doc (only a measured one-hop round trip is a latency sample);
  `lastAccess: time` in the failure patch is redundant but deliberate.
- **No major findings**, so no new `fix/` or `plan/` tickets were filed, and nothing was blocked.
