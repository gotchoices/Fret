description: A simulation test that was supposed to prove new peers spread out around the ring did not actually detect the problem it was written for; it has been replaced with one that measures crowding directly and that re-proves on every run that it can still catch the old bug.
files: packages/fret/test/churn-scenarios.spec.ts, packages/fret/test/simulation/fret-sim.ts

Follow-on from `sim-joiner-placement`. The guard that shipped with that fix measured the largest
gap between adjacent peers, which does not move when joiners pile into one sliver — the surviving
evenly-placed initial peers still hold the largest hole down. On the batch-join case the buggy and
fixed placements produced bit-identical readings, so the guard was vacuous.

## What shipped

**`test/simulation/fret-sim.ts`** — one new `PlacementStrategy` variant, `'clumped-joiners'`,
reproducing the pre-fix placement on purpose: initial peers spread evenly, joiners land at
`index / (index + 1)` of the ring. Kept as a negative control.

**`test/churn-scenarios.spec.ts`** — the largest-gap case is gone. Two cases replace it (batch
burst at `churnRatePerSec: 0`, steady trickle at `churnRatePerSec: 2`), both driving one shared
helper `assertPlacementSeparates`, which for each of five seeds runs the scenario under both
placements and asserts **both** directions: the shipped placement reads at or under the threshold,
the clumping placement reads over it. Statistic is `maxPeersInOneSpacingArc` — the most peers any
even-spacing-wide arc contains.

Threshold 7, calibrated at n=40 / k=15 / m=8 / 10s over seeds 8008, 8009, 8010, 4242, 99.

## Review findings

### Verified, not taken on trust

- **The negative control is faithful.** Read `git show 7568f2a` (the `sim-joiner-placement` fix)
  and traced `handleJoin`: `const index = this.nextPeerIndex++` runs before `addPeer`, and the
  pre-fix `uniformCoord` used `this.nextPeerIndex` as its population — so the old joiner coordinate
  was exactly `index / (index + 1)`, which is what `'clumped-joiners'` spells out. Initial peers
  used `nextPeerIndex` too, which the constructor sets to `config.n`, so the strategy's
  even-spread initial arm is also byte-identical to pre-fix. The control reproduces the bug it
  claims to.
- **Every number in the handoff table reproduces.** Ran the file; readings came out
  `batch burst: uniform 3 / clumped 11` at all five seeds, `steady trickle: uniform 3,3,3,4,3 /
  clumped 18,18,16,16,16` — exactly the handoff's table, which was itself an independent
  re-measurement of the ticket's. Three measurements now agree.
- **`maxPeersInOneSpacingArc` is correct, not merely plausible.** Anchoring the scan window at each
  peer in turn is sufficient: any maximum-density arc of fixed width can be slid until its leading
  edge coincides with a peer, so anchoring at peers cannot miss the maximum. Wrap handled by
  `(other - anchor + ringSize) % ringSize`. Degenerate inputs (empty set) return 0 before the
  division. No duplicate coordinates are reachable in either arm (`index/(index+1)` is injective
  and cannot collide with `j/40`), so the count is not inflated by ties.
- **Lint and tests pass.** No lint step exists in this repo (`AGENTS.md`: `yarn check` is the gate,
  and `yarn format` is documented as not-runnable). `npx tsc --noEmit` clean.
  `test/churn-scenarios.spec.ts`: **9 passing (40s)**. No pre-existing failures surfaced.
- **The coarse-cadence judgment call holds.** `stabilizationIntervalMs: 5000` is justified in the
  handoff on the grounds that `handleStabilize` touches neighbor sets and stores only — coordinates
  are assigned in `addPeer`, aliveness cleared in `handleLeave` — and was verified empirically at
  both cadences. My run at 5000ms reproduced the table that was also measured at 500ms, which is an
  independent confirmation of the same claim. Accepted; the call-site comment states both the
  reasoning and the measurement.
- **Docs checked, not assumed.** `docs/fret.md`'s simulation bullet documents the partition/heal
  harness, not the placement strategies; no placement strategy has ever been named there. Nothing
  in the change makes any existing line stale, so no doc edit was needed. (`packages/fret/dist/`
  holds a stale `.d.ts` copy of the old union — that is build output, regenerated by `yarn build`,
  not a source of truth.)

### Major — one, filed

**Two sibling simulation tests have exactly the defect this ticket exists to remove**, in
`test/message-bus.spec.ts`'s `Placement distributions` block:

- `clustered placement: peers cluster around centers` asserts `largestGap > medianGap`, which is
  arithmetically true of any not-perfectly-even coordinate set — an evenly-spread ring passes it.
- `clustered placement: inter-cluster routing takes more hops` sets **no `placement` at all** (so
  it runs the default even spread despite naming its variable `clusterSim`), never reads a hop
  count, and asserts only `routingAttempts === 10`.

Climbed the architecture ladder before filing: the root cause is one class — a placement statistic
asserted against a threshold with no control arm — and the invariant that retires it already
exists in the tree as this ticket's own `assertPlacementSeparates` (run both a control and the
strategy under test, assert both directions). So the ticket filed is a `debt-` one to generalize
that helper across the block, citing both instances as evidence, rather than two point tickets.
Filed as `backlog/debt-sim-placement-guards-no-control`. Site-claim grep over all open stages
returned only `implement/15.6-sim-route-local-selector`, which names `message-bus.spec.ts` solely
inside a test-run command line and does not claim the `Placement distributions` block, so a fresh
ticket was correct. The third case in that block (`skewed placement`) is *not* affected — its
comment explicitly reasons about, and rejects, the weaker assertion that would also pass for a
uniform layout.

### Minor — none fixed, and why

Nothing rose to a fix-in-this-pass change. Two things were weighed and left:

- `placementReading` carries `durationMs: 10000` and a loop bound of `10000` as two literals that
  must agree. Every other case in this 453-line file does the same, so extracting a constant in one
  case only would make this case the odd one out; the file-wide cleanup is not this ticket's scope.
- The handoff lists `'clumped-joiners'` becoming "public surface on `PlacementStrategy`" as a known
  gap. On review that is overstated: `PlacementStrategy` lives in `test/simulation/fret-sim.ts` and
  is not exported from the package, so the only callers are specs in this repo, where the strategy
  is documented in place as a deliberate defect. No action.

### Tripwires

None recorded. The handoff's remaining known gaps — threshold calibrated at one config, five seeds
rather than a generated property, `maxPeersInOneSpacingArc` being O(peers^2), and the statistic
being a maximum and so blind to a two-sliver placement defect — are each stated in the source at
their own site, are unconditionally true today rather than "fine now, only matters if X", and are
bounded to a test that hard-codes its config. They are limits of the guard's scope, already
written down where a reader meets them; nothing further to park.

### Considered-and-declined

None encountered — no accepted-tradeoff `NOTE:` sits at any site this change touches.
