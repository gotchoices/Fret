## What the change was

Before it, the "walk `m` peers either side of a coordinate" idiom was copy-pasted across
`fret-service.ts` with three defects baked into every copy: a walk anchored exactly on a stored
coordinate spends one slot on that entry (so a self-anchored walk at `m` returns only `m − 1`
other peers per side); a cap applied to `[...successors, ...predecessors]` eats the *second*
walk whole; and side-major ordering means any downstream truncation loses one entire side. The
implement commit replaced them all with one helper that over-fetches for the anchor and for
excluded ids, and returns the two sides **interleaved**.

## Review findings

### Checked and sound — no action

- **G = 2m holds arithmetically in both directions.** With the anchor id supplied, each side is
  asked for `m + 1`: self present in the walk → `[self, s1..sm]` and the drop reclaims the slot;
  self absent → `[s1..s(m+1)]` and the trim removes the surplus. Either way the size-estimator
  window is self + m successors + m predecessors → 2m gaps.
- **`exclude` is passed *into* the helper at all three sites that use it**, never filtered off
  the result; the helper's `+ exclude.size` over-fetch is what keeps a blanketed side from
  starving.
- **`test/size-estimator.spec.ts`'s parity case discriminates** rather than passing vacuously:
  evenly spaced coords → cv = 0 → cvEff = 1 → confidence = 0.5 + 0.5(1 − 1/√G) = 0.875 at
  G = 16, against 0.8664 at G = 14 and 0.8821 at G = 18 — both outside its 1e-12 tolerance.
- **The `preconnect-concurrency.spec.ts` change is not tautological.** It calls the helper only
  to choose which ring positions to block, then asserts on pool concurrency and the
  dialable-first budget rule.
- **`src/index.ts` re-exports nothing from the moved module**, so the layering move below needed
  no public-surface change.

### Defect found and fixed — the half-specified anchor (applied pass 5)

`SizeEstimateOptions` carried `selfCoord` and `selfId` as two independent optionals, and
`collectGaps` fell back to `selfId ?? ''` when only the coordinate was supplied. The empty-string
id matches no stored peer, so the walk's anchor-drop never fires and each side silently returns
one fewer real peer — the window loses one gap per side (G = 14 instead of 16) with no error
anywhere, which is exactly the off-by-one the helper exists to retire.

Fixed by making the pairing unrepresentable rather than defaulted: one field
`self?: { coord: Uint8Array; id: string }`. All four `fret-service.ts` call sites updated,
including `getNetworkSizeEstimate`'s deliberate fallthrough to the whole-store path when the
self coordinate has not been hashed yet. Six `test/size-estimator.spec.ts` sites had been
running degraded on the old fallback and now supply the id, so they exercise G = 2m = 16.
Verified: 53 passing, including the `> 0.8` eclipse assertion and the `> 0.6` / `< 0.6` pair at
the confidence-tracking case, which both still hold at the widened gap count.

### Cleanups applied this pass

- **Self-id recompute (DRY).** `this.node.peerId.toString()` was recomputed at **26** sites in
  `fret-service.ts` (measured with `grep -o 'this\.node\.peerId\.toString()' … | wc -l`; the
  earlier passes' counts of 27/28 predate the pass-5 reshaping). Retired as a class rather than
  site-by-site: a `private readonly selfIdStr` bound in the constructor immediately after
  `this.node = node`. `node` is readonly, so it cannot go stale. All 26 replaced.
- **Redundant self in `exclude`.** `announceNeighborsBounded` built `new Set([self])` and
  `announceOnDeparture` built `new Set([self, departedId])`, while the helper drops self
  unconditionally — so self was excluded twice and an over-fetch slot was spent on a peer
  already dropped. Numerically harmless, but it invites a reader to believe the helper does
  *not* drop self. The bounded announce now passes no exclude at all, departure passes
  `new Set([departedId])`, and `announceTargetsAround`'s doc comment states that self is the
  helper's job so `exclude` carries only the extra ids.
- **Layering.** `estimate/size-estimator.ts` imported `service/ring-walk.ts` — estimate → service,
  inverted against the rest of the layout. No cycle (the module is a leaf over store types only)
  and `tsc` was clean, so this was a maintainability finding rather than a defect; moved rather
  than ticketed because the importer set is exactly four files. `git mv` to `src/ring/`
  (beside `distance.ts` / `hash.ts`, the neutral home), four import paths updated, plus the
  path named in `docs/fret.md` and the source tree in `AGENTS.md`.
- **Docs.** The *Network size estimation* section still named `selfCoord` as the window
  selector. Renamed to the paired `self` field, with one added sentence stating *why* it is one
  field and not two optionals — the failure it forecloses is silent, so the reasoning is the
  part worth keeping.

### Test gaps — disposition

- **Added**, `test/ring-walk.spec.ts`: a pin that a `fanout`-sized slice at `fanout = m` still
  reaches **both** sides (4 successors + 4 predecessors, not 8 successors) — the headline
  behavior change of the whole ticket, previously covered only indirectly.
- **Added**, same file: a pin that a self-anchored window at `count = m` includes the **m-th**
  neighbor on each side and nothing beyond it — the over-fetch's whole purpose, and what the
  capacity-protection set and `isNearNeighbor` both depend on.
  - Both are written against `ringNeighborsBothSides` rather than through
    `announceTargetsAround` / `isNearNeighbor`, which are private and reachable only through a
    service rig. That is one level below where the prior ticket asked for them: the pins cover
    the arithmetic (interleaving survives a slice; the over-fetch reaches the m-th peer) but not
    the wrappers' own composition — `announceTargetsAround`'s connected/non-connected partition
    sitting between the walk and the slice is still unpinned. Each test names the service method
    it stands in for. Stated as a known limit of this pass, not as coverage it does not have.
- **Declined**, with reason: the `NOTE:` at `getNeighbors` claiming `both` at `wants = m` is
  successor-biased. That describes `getNeighbors`' *own* `wants` contract — per-side count **and**
  total cap — which is deliberately a different contract from this helper's and is untouched by
  this ticket. It documents an adjacent method; it is not an untested claim of this change.
