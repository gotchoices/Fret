## What the implement stage delivered

`test/iterative-lookup.spec.ts` — the digest-only probe test now asserts a deterministic
`exhausted` terminal, no `complete` anywhere, at least one `probing` whose target is always another
node, and at least one `near_anchor` carrying non-empty `anchors` *and* `cohort_hint` (which is what
separates a real in-cluster reply from the empty `staticReject` shape). The activity test now counts
handler invocations per service and asserts the total is exactly 1 with the initiator's own count at
0. Two blocks driving `routeAct` — breadcrumb rejection and correlation-id dedup — were deleted as
testing the wrong layer, with a header comment naming where each behavior is actually pinned.

`test/profile.behavior.spec.ts` — the `Preconnect budget` describe (2 tests) was deleted; both put
an empty-store service into active mode and asserted `pingsSent <= budget`, which holds for any
budget when the count is 0. A comment points at the spec that asserts the budget exactly.

`test/fret.mesh.spec.ts` — rewritten from a smoke test into the real spec for FRET over a live TCP
transport: `waitFor` on a convergence predicate instead of a fixed 1500 ms sleep, mutual `member`
classification proved through `pingsOk > 0` rather than assumed, and a third libp2p node hosting no
FRET service as a negative control.

### Claims verified against the source, not taken on trust

- **`exhausted` is genuinely the unconditional terminal.** Read `iterativeLookup`
  (`fret-service.ts:2721-2930`): only `complete` returns early; both `wasCancelled` breaks and every
  other path fall out of the attempt loop into the trailing `exhausted` yield. The test comment is
  accurate.
- **The initiator can never run the activity.** `visited` is seeded with `selfId`
  (`fret-service.ts:2748`) and every path sends over the wire; there is no local-handler branch. With
  `k=7` on a 3-node ring every peer is in-cluster, so nothing forwards back to the initiator, and a
  message carrying `selfId` in its breadcrumbs would be rejected as a loop anyway. `fired[0] === 0`
  is a real property, not an accident of the run.
- **`total === 1` holds for the right reason.** The two delivery shapes — payload attached to the
  first probe, or probe-then-resend to a named anchor — each invoke exactly one handler, and the
  source `NOTE:` on the resend confirms a repeat to the *same* peer is answered from its dedup cache
  without re-performing the work. Agreed with the implementer that this is observed rather than
  forced; see *Gaps accepted* below.
- **Both replacement-coverage claims check out.** `preconnect-concurrency.spec.ts` asserts
  `pingsSent` equals 6 exactly (Core) and 3 exactly (Edge) against 16 seeded peers, plus that the
  budget is spent on dialable peers rather than wasted on undialable leaders — strictly stronger than
  the `<= budget` tests that were deleted. `pick-anchors.spec.ts:175` drives `handleMaybeAct` and
  asserts the empty static shape. `maybeact-dedup-phases.spec.ts` carries seven tests covering both
  phases, the refusal-is-not-cached rule, and an end-to-end find-then-act lookup.

### Minor — fixed in this pass

- **Teardown ran outside any `try`/`finally` in all three `iterative-lookup` tests.** A failed
  assertion skipped the stop calls entirely, leaving three libp2p nodes and their stabilization
  timers live — so the mocha exit watchdog would fail the run a *second* time with an open-handle
  dump, burying the assertion message the developer actually needs. The ticket added a `finally` to
  the mesh spec but not to the lookup specs it rewrote with far more assertions, so the two files
  disagreed. Added a shared `teardown(mesh)` helper next to `makeMesh` and wrapped all three bodies.
- **`await Promise.all(services.map(s => s.stop()))` is not failure-safe.** One rejecting stop
  strands the remaining services and the nodes underneath them. The helper uses `Promise.allSettled`
  before `stopAll` (which already swallows per-node errors).
- **The mesh spec's own `finally` had the same shape**, as five sequential `await`s: a throwing
  `serviceB.stop()` skipped `serviceA` and all three TCP nodes. Changed to two `allSettled` groups,
  services before nodes.
- **The third lookup test still threw bare `Error`s** while its two rewritten siblings used chai
  with an interpolated event trail. Converted for consistency, including the "no key found" guard.
- **`test/README.md` described the deleted smoke test** — "3-node mesh with TCP transport / Validates
  discovery and stabilization". That is now wrong in content, not just stale: the spec runs two FRET
  nodes plus a service-less negative control and validates membership classification. Rewrote the
  bullet. The separate "67 passing" claim on line 158 is left alone — it is explicitly owned by
  `plan/21-cleanup-tests`, which also questions whether the file should survive at all.
- **A comment cited `preconnect-concurrency.spec.ts:173-216`.** Line-number citations rot on the next
  edit to that file; changed to name the two "active tick:" cases instead.

### Major — one, filed as an arm on an existing ticket

The teardown leak above is an **instance of a class**, not a one-off. Measured by listing spec files
that call `stopAll` with no `afterEach` anywhere in the file: `maybeact-dedup-phases.spec.ts`
(7 teardown sites), `proactive-announce.spec.ts` (5), `network.isolation.spec.ts` (3),
`route.maybeact.integration.spec.ts` (2), plus `profile.behavior.spec.ts`. Fixing each by hand is
the point ticket; the invariant that retires the class is a shared `withMesh(n, fn)`-shaped helper
that makes the leak unwritable.

`plan/21-cleanup-tests` already owns mesh-setup boilerplate consolidation across these same specs, so
per the site-claim rule this is an **arm appended to that ticket**, not a new one. No new ticket
filed.

### Conditional / speculative — no tripwires added

### Considered and declined

The four `expect`s after `waitFor` in the mesh spec can never fire — the `waitFor` predicate already
requires every one of those conditions, so it throws first. They are dead as assertions. Left in
place deliberately: they state the spec's claims at the point a reader looks for them, they cost one
poll's worth of nothing, and deleting them would leave the file's intent legible only inside a
predicate. Not worth the churn.

### Not found

No correctness defect in the new assertions, no assertion that would pass through the regression it
names, and no over-tight assertion that would flake. Specifically checked and clean: the digest-only
terminal is deterministic rather than racy; the `probing` peer-id assertion cannot pass on an empty
event list (the terminal assertion fails first); `nearAnchor` is a real optional field on
`RouteProgress` so the `?.` chains are typed, not defensive noise; and `docs/fret.md` needed no edit —
it describes service behavior, none of which changed, and the only test file it names in these areas
(`test/iterative-lookup.spec.ts`, cited at `fret-service.ts:2475` for the originator-filter rule) still
pins exactly that, in the third test this ticket left intact.

## Gaps accepted as stated

The implementer listed six known gaps. Verdicts:

- **`total === 1` observed on a live ring rather than forced by a stub** — accepted. The property is
  real (argued above) and a duplicate-injection rig is a larger piece of test infrastructure than this
  assertion warrants today.
- **Fixed warm-up sleeps** — accepted, boundary confirmed, owned by `plan/21-cleanup-tests`.
- **Mesh spec is the only TCP-binding spec** — accepted. Ran in 1552 ms against a 20 s `waitFor` budget.
- **Negative control asserts `!== 'member'` rather than `=== 'unknown'`** — accepted. Pinning `foreign`
  needs three time-separated negotiate failures (~7 s) and buys a distinction the spec does not exist to
  make.
- **Replacements verified by reading, not mutation** — closed, see *Verified by mutation*.
- **`test/README.md` out of date** — partly closed: the bullet this ticket's change invalidated is fixed
  here; the passing count stays with `plan/21-cleanup-tests`.
