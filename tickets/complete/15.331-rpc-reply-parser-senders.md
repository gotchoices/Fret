## What shipped

The three outbound RPCs that read a reply validate it with the parser written for it in `15.31`
instead of casting the decoded JSON. Each sender's decode is now
`async (b) => parseOrThrow(parseX, await decodeJson(b))`; `parseOrThrow` raises a named
`ReplyRejectedError` (with `isReplyRejectedError`, matching the `isFrameTruncationError` /
`isPayloadTooLargeError` house rule) which `rpcRequest` classifies as `decode-error`.

| Sender | Reply parser |
|---|---|
| `sendPing` | `parsePingResponse` — the `Boolean(r.ok)` coercion is gone; `ok: 1` is now `decode-error` |
| `sendMaybeAct` | `parseMaybeActReply` |
| `fetchNeighbors` | caller-supplied on the options bag (`opts.parse`); `FretService` passes `makeSnapshotParser(this.mergeSnapshotCaps())` |
| `announceNeighbors`, `sendLeave` | write-only — unchanged |

`rpcRequest` itself is untouched: the adapter was chosen over teaching it to read a returned
`undefined` as `decode-error`, which would make `undefined` unreturnable as a legitimate reply for
every consumer of a publicly exported helper.

## Review findings

**Implement diff read in full** (`git show e598b35`) before the handoff summary, across two prior
runs cut short by the token budget; this run resumed from the recorded notes rather than re-reading.

### Fixed in this pass (minor)

- **`parseMaybeActReply`'s certificate arm projects, and the asymmetry read as an oversight.** It
  returns a fresh `{commitCertificate}` where the NearAnchor arm beside it spreads `{...msg}`.
  Confirmed harmless by reading the consumers — `RouteProgress.result` is declared
  `{commitCertificate: string}` (`src/index.ts:86`), `routeAct` returns the same union, both read
  sites test `'commitCertificate' in …` and read nothing else, and `dedupCache` stores only
  locally-produced results so no parsed reply reaches it. Added the rationale to the parser's doc
  comment. No behavior change.
- **The double JSON parse of every reply body was stated but not tagged.** This ticket made it more
  load-bearing (three senders now unconditionally `await decodeJson(b)` after `decodeReply` already
  parsed for its busy check). It was already accepted in prose at `src/rpc/request.ts`, so it is
  **not a new finding and was not filed** — retagged as a greppable `NOTE: accepted tradeoff` with
  the structural alternative (hand `decode` the parsed value, changing a public helper's signature)
  and a revisit condition.
- **Two `NOTE:` paragraphs said the same thing at length.** `registerNeighbors`' `snapshotParser`
  and `fetchNeighbors`' `opts.parse` both explained the `Infinity`-caps default at ~5 lines each.
  Shrank the second to a pointer at the first plus the one genuine difference (options bag, so
  making it required later costs no signature reorder).

### Test gap closed (minor)

- **The `commitCertificate` arm was never exercised as *wired*.** `WIRED_SENDERS`' `sendMaybeAct`
  entry serves a NearAnchor only, so the arm carrying the actual work result — and the arm whose
  shape this ticket changed — was covered as a parser but never through the sender. Added two cases
  to the Phase 5 block of `test/rpc.codec-properties.spec.ts`: a legal certificate reply is `ok`
  and projects to exactly the declared shape (an extra field is dropped), and a
  `commitCertificate` of any non-string type is `decode-error` with no `value` property rather than
  a wrongly-typed certificate reaching `routeAct`'s callers.

### Checked and found correct

- **Reply-cap arithmetic re-derived from the producers**, not taken from the handoff. `pickAnchors`
  (`fret-service.ts:2458`) returns `[first, second].filter(Boolean)` — at most **2** anchors, from
  both call sites. The widest cohort-hint producer is `buildNearAnchor` (`:2607`):
  `right.slice(0,4) ∪ left.slice(0,4)` — at most **8**; `nearAnchorOnly` (`:2436`) emits at most 4.
  Against caps of 8 and 16 that is 4× and 2× headroom, so a cap provably cannot refuse this node's
  own legal reply, and a test pins the widest case.
- **Merge-cap arithmetic.** `mergeSnapshotCaps()` is Core 16/16/8, Edge 8/8/6, and
  `fetchAndMergeSnapshot`'s merge loop slices to exactly those — the wired parser truncates nothing
  the loop would not.
- **`decode-error` scoring.** `noteRpcFailure` decays relevance only and records no contact strike,
  which is the right classification: a reply that arrived over the namespaced protocol is
  membership evidence whatever its body says. A busy reply is unaffected — `rpcRequest` tests the
  busy shape before `decode` runs, pinned by a wired test across all three senders.
- **`docs/fret.md`'s *Wire-shape parsers* section** matches the shipped code: the parser table, the
  sender→parser table, the adapter rationale, and the export list all read true against
  `src/rpc/validate.ts` and `src/index.ts`.

### Left in place deliberately

- **The dead `slice(0, caps.*)` in `fetchAndMergeSnapshot`'s merge loop.** Now redundant given the
  parser wired above it, and it is `15.332-rpc-snapshot-cap-single-point`'s arm. Removing it here
  would make the single-point argument twice.
- **`sendLeave` / `announceNeighbors` read no reply at all**, so a busy or malformed answer from
  those protocols is still invisible. Pre-existing write-only gap, documented in `docs/fret.md`,
  parked with the leave-authentication work.

### Not fully verified (stated, not silently omitted)

- **The one behavior change with real blast radius was not exercised against a live peer.**
  `fetchNeighbors` used to return `ok` for any JSON object and now rejects a snapshot whose `from`
  is not a parseable peer id or whose `timestamp` is not finite. The suite is green so nothing
  depended on the old leniency, and the `decode-error` arm of `fetchAndMergeSnapshot` is a scoring
  no-op, but no two-node interop case beyond the existing suite was driven.
- **`yarn build` was not run** in this pass; `npx tsc --noEmit` compiles the same sources with the
  same config but does not exercise the emit step. `yarn check` covers it before release.
- **The wired mutant generator is still shallow** — one top-level field per mutant, no nested
  fuzzing (a `sample` entry with a bad `coord`, a `cohort_hint` of objects). Those shapes are
  covered as *parser* properties elsewhere in the same file, so this is depth, not a hole.
