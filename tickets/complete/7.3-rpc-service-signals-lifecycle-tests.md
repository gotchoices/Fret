Service-level half of the test work for `rpc-service-signals` (Phase 4 of `7-rpc-abort-deadlines`).
The implementation under test was already landed (commits `4592351`, `6d93373`); this ticket added
only tests, plus one `NOTE:` tripwire in the service. The review pass added a fourth test and
hardened two of the three original ones.

## What landed

**`packages/fret/test/service-lifecycle.spec.ts`** — four tests appended to the existing
`FretService start/stop lifecycle` describe, two module-level helpers, and a module-level read of
the service's `private static SHUTDOWN_BUDGET_MS` / `LEAVE_NOTICE_TIMEOUT_MS` off the class (so the
bounds track the constants rather than restating `3000` / `1500`).

Helpers (added in review, shared by the two shutdown tests):

- `createGhost(node)` — starts an in-memory node, merges its multiaddrs into `node`'s peerStore,
  stops it, returns its id. A peer libp2p holds an address for but that nothing answers at. Seeded
  through the peerStore rather than the service's `addressKnown` set because `seedFromPeerStore`
  rebuilds that set wholesale every tick and would drop a directly-poked entry.
- `hangGhostDials(node, ghosts)` — overrides `node.dialProtocol` so a dial to any ghost settles
  **solely** on signal abort (libp2p's `AbortOptions` contract; same shape as `hangsUntilAbort` in
  `test/rpc.protocols.spec.ts`), and returns `{ attempted, unsignaled, restore }`.

Tests:

1. **`stays inside its shutdown budget when a dial hangs, and still notifies reachable neighbors`**
   Two in-memory nodes plus one ghost. The stopping node holds `svc`; the other runs its own started
   `FretService` on the same `networkName` and is dialed so it is `connected`. `svc.stabilizeOnce` is
   stubbed to a no-op so the tick's probe passes do not race the assertions (`seedFromPeerStore` is
   deliberately left real — it is what puts both peers in the ring). Delivery is counted by wrapping
   the receiver's `handleLeave` — `registerLeave` bound a closure at `start()`, so a later override
   is picked up.
   Asserts: elapsed across `await svc.stop()` ≤ `SHUTDOWN_BUDGET_MS + 1500`; `attempted >= 1` (the
   hang was actually exercised — what keeps the elapsed bound from passing vacuously); `unsignaled
   === 0`; and `leaves === 1` via `waitFor`, because `sendLeave` is write-only and does not await the
   remote handler. Measured elapsed: **~1546 ms** (the ghost costs one `LEAVE_NOTICE_TIMEOUT_MS`).

2. **`cuts the whole leave fan-out short once the shutdown budget expires`** *(added in review)*
   Five ghosts, no reachable neighbor. Both self-scheduled dialers are silenced (`stabilizeOnce` and
   `proactiveAnnounceOnStart`), so every counted dial belongs to the leave fan-out. Five hanging
   notices cost 7500 ms of per-notice timeouts, so `SHUTDOWN_BUDGET_MS` is what has to bind here —
   which is exactly what test 1 could not pin.
   Asserts: `GHOSTS * LEAVE_NOTICE_TIMEOUT_MS > SHUTDOWN_BUDGET_MS` (the premise, stated as an
   assertion so a constant change fails here rather than silently making the test vacuous); elapsed
   ≤ `SHUTDOWN_BUDGET_MS + 1500`; `attempted >= 1`; `attempted < 5` — the fan-out abandoning notices
   it never reached, which is the clock-independent evidence the whole-fan-out budget fired;
   `unsignaled === 0`. Measured elapsed **~3026 ms**, `attempted` 2.

3. **`issues no dials and strikes nobody when stop() lands mid-tick`**
   Parks `seedFromPeerStore` — the only awaited seam ahead of every `runSignal` capture. `start()`
   awaits it once itself before arming the loop, so the stub parks on its **second** call (the
   tick's). The stub does no real seeding on purpose: the real one rebuilds `addressKnown` wholesale
   from the peerStore and would drop the synthetic target. A well-formed address-known `member` is
   seeded into the store first, and the test asserts it is in `getNeighbors(selfCoord, 'both', 8)`
   **before** unparking, so the passes have a genuine target. `stabilizeOnce` is wrapped (not
   replaced) to count completions.
   Asserts after unpark: `ticksCompleted === 1` (the tick resumed and ran to completion — kills the
   "never resumed" vacuity), **0 `dialProtocol` calls**, `pingsSent`/`pingsFail` unchanged, the
   target entry still present with `contactFailures === 0` and `state !== 'dead'`, and
   `backoffMap.get(id) === undefined`.

4. **`mints a fresh run signal per start and leaves the stopped run aborted`**
   `runSignal` is `undefined` before the first `start()`, `.aborted === false` while running,
   `.aborted === true` after `stop()` (the aborted controller is deliberately kept), and
   `.aborted === false` again after a restart.

**`packages/fret/src/service/fret-service.ts`** — one added `NOTE:` block at the
`mergeNeighborSnapshots` call site in `stabilizeOnce` (~line 1764), recording the tripwire below.
No behavior change. No source changes were made during review.

## Deviations from the ticket, and why

- **The ticket's `diag.snapshotsFetched` assertion was dropped** and replaced with a direct
  `dialProtocol` call counter. `fetchNeighbors` **catches** the abort and returns an empty snapshot
  rather than rethrowing, so `mergeNeighborSnapshots`'s `wasCancelled` break never fires and the
  counter still ticks for a fetch that opened no stream. Counting dials is the stronger and more
  literal form of "issues no dials" anyway. The reason the counter moves is written into the test
  as a `NOTE:` so a future reader does not "fix" it back.
- **Ghosts are seeded through the peerStore, not via `(svc as any).setAddressKnown(...)`** as the
  ticket suggested — see `createGhost` above for why.

## Review findings

Reviewed the implement diff (`820735f`) with fresh eyes before the handoff summary, then read the
implementation the tests pin: `stabilizeOnce`, `stop()`, `sendLeaveToNeighbors`, `openRpcStream`,
`readAllBounded`, `sendLeave`, `deadline`, `sendAnnouncementsRateLimited`.

**Fixed inline (minor):**

- *Test 1's hanging-dial stub turned its own guarded regression into a 30 s mocha timeout.* The stub
  returned a forever-pending promise when a dial arrived with **no** signal — which is precisely the
  regression it exists to catch (dropping `signal` from `openRpcStream`'s `NewStreamOptions`). The
  run failed, but as an opaque timeout that names nothing. The stub now counts such dials in
  `unsignaled` and rejects them, and both shutdown tests assert `unsignaled === 0`. Verified: with
  the signal removed from `openRpcStream`, both tests now fail in **68 ms** naming the counter,
  instead of hanging. This also closed the implementer's stated "no mutation check was run against
  test 1" gap — that mutation is now runnable and was run.
- *The whole-fan-out shutdown budget was not pinned by any test* (the implementer's own top-listed
  gap: with one ghost, `LEAVE_NOTICE_TIMEOUT_MS` binds and `SHUTDOWN_BUDGET_MS` never does). Added
  test 2 above. Verified non-vacuous: widening the fan-out budget to 60 s (leaving per-notice
  timeouts intact) fails it at **7563 ms vs the 4500 ms bound** — a 3 s margin, so the assertion is
  not resting on scheduler slop.
- *Test 3 waited on a fixed `delay(100)`* for the resumed tick, which is a flake on a loaded box for
  no benefit. Replaced with `waitFor(() => ticksCompleted === 1, …)` — the same completion signal the
  assertions already depend on, so a slow box makes the wait longer rather than the test wrong.
- *Test 3's `store.getById(targetId)?.state` passed vacuously if the entry were missing.* Now reads
  the entry once, asserts it exists, and asserts against that.
- *Duplicated ghost setup and dial-stub code* between the two shutdown tests was lifted into the two
  module-level helpers described above (DRY), rather than copied into the new test.

**Major findings: none.** No correctness defect was found in the diff. The `NOTE:` the implementer

## Known gaps — carried forward honestly

- **Both shutdown tests' elapsed assertions are wall-clock-sensitive.** They join the small set of
  such assertions in the repo (see the `NOTE:` at the top of the timeout block in
  `test/rpc.protocols.spec.ts`). Test 2's margin is measured (7563 ms vs 4500 ms); test 1's is not.
  If either ever flakes on a loaded box, raise the slack — do **not** swap it for a bare "stop()

  so the interaction between a live probe pass and the shutdown fan-out is not covered — only the
  fan-out in isolation.

  routing table for that run. Nothing asserted depends on self being present, but a reviewer adding
