Documentation half of the cancellation-evidence work for `rpc-service-signals` (Phase 4 of
`7-rpc-abort-deadlines`). The test half, `rpc-cancel-evidence-tests`, landed first
(`tickets/complete/7.4-rpc-cancel-evidence-tests.md`).

## What shipped

**`docs/fret.md`, four sites.**

- *Stream management* (libp2p integration). Corrected the stale claim that the read deadline is
  "one overall budget per read (`readAllBounded`, 5s default)". The budget covers the **whole
  outbound RPC** — dial + stream open + write + read — via `RPC_TIMEOUT_MS` (5000ms, exported from
  `src/rpc/protocols.ts` so the four outbound RPC families cannot drift apart). Documented the
  per-call-site overrides and why each differs: `MAINTENANCE_RPC_TIMEOUT_MS` (2000ms) on
  maintenance pings and announces; `sendMaybeAct` deliberately left at 5s because it is a *route*
  budget, not a link one; `SHUTDOWN_BUDGET_MS` (3000ms) for the whole leave fan-out with
  `LEAVE_NOTICE_TIMEOUT_MS` (1500ms) per notice, which cannot reuse the run signal because it runs
  after that aborts. The "no per-chunk idle timer" reasoning was left intact.
- *Stabilization and churn handling*. New bullet: a run-signal abort (our own cancellation) records
  no contact failure, no backoff, no ping-failure diagnostic — only the RPC's own timeout does.
  Explains why the caller's signal is the discriminator (the sender's deadline is a *child* of it,
  so the child fires on both a timeout and a cancellation while the caller's own signal fires only
  on a cancellation) and therefore why no new error type was needed. States the one loop where the
  rule's early-exit does not fire (`fetchNeighbors` behind `mergeNeighborSnapshots`) and why that
  is harmless today.
- *Service shell & lifecycle (A1)*. The run-scoped `AbortController` (`runAbort`) is minted with
  `runGen` on `start()` and aborted on `stop()` right after the loop timers are cleared and before
  the leave fan-out — which carries its own budget, so aborting does not silence it. Kept rather
  than nulled, so a late read from an interrupted tick reports "cancelled" rather than "no signal".
- *RouteAndMaybeAct pipeline (A5)*. `RouteProgress` has no `cancelled` variant by design — it is
  part of the public `FretService` interface — so `{ type: 'exhausted' }` covers both "the ring had
  no more hops" and "the run was cancelled under us". A caller must re-check service state before
  concluding the ring was exhausted; an undelivered activity is one possible outcome.

**Added during review** (see findings): status annotations on two stale threat-doc findings, and a
one-line correction to an existing accepted-tradeoff `NOTE:` in `fret-service.ts`.

## Review findings

**Verification of the implement diff.** Every claim in the four `docs/fret.md` sites was
re-derived from current source rather than read back from the ticket. All check out:

- `RPC_TIMEOUT_MS = 5000` in `src/rpc/protocols.ts`, consumed as the default by all four sender
  modules (`leave.ts`, `maybe-act.ts`, `neighbors.ts`, `ping.ts`).
- `MAINTENANCE_RPC_TIMEOUT_MS = 2000`, `SHUTDOWN_BUDGET_MS = 3000`, `LEAVE_NOTICE_TIMEOUT_MS = 1500`
  in `fret-service.ts`, used at the call sites the doc names (announce, four ping paths, leave
  fan-out); `sendMaybeAct` passes no override.
- The parent/child deadline claim: `deadline(ms, parent)` in `src/utils/deadline.ts` aborts on
  whichever of the timer or the parent fires first, so the child is aborted in both cases and the
  parent only on a cancellation. Exactly as documented.
- The "harmless today" claim: `openRpcStream` throws on an already-aborted signal *before* choosing
  a connection or dialing, so a cancelled `mergeNeighborSnapshots` walk opens no streams.
- `stop()` ordering: `runGen++` → `clearLoopTimers()` → `runAbort.abort()` → listeners → unhandle →
  leave fan-out. The doc's ordering claim is right, including that the controller is not nulled.
- `RouteProgress` in `src/index.ts` has no `cancelled` member, and the matching code `NOTE:` at the
  `iterativeLookup` `exhausted` yield exists (landed with the sibling ticket, correctly not
  duplicated in the doc).

**Minor — fixed in this pass.**

- `docs/fret.md` carried `fret-service.ts:1770`, the only line-number citation in the whole
  document; every other reference anchors on a symbol (`the NOTE: at farWeights in
  src/selector/next-hop.ts`). A line number in a design doc rots on the next edit to that file, and
  this one was already one line off from the ticket's own earlier citation. Replaced with a
  symbol anchor.
- The same sentence read "Enforced at seven of the eight guarded call sites". "Guarded call sites"
  was coined vocabulary the doc never defines, the reader has no way to enumerate the eight, and it
  is slightly wrong: all eight loops carry the check — at the eighth it simply cannot fire, because
  the sender swallows the error. Restated as the plain fact (every loop re-checks the signal before
  scoring; one exception, named, with its consequence and why it is harmless).
- `docs/threat-analysis.md` §3.7 and §8.4 and `docs/threat-rir-mitigated.md` §8.4 all still
  described `readAllBounded`'s **100 ms idle timeout after first data** — the same stale mechanism
  this ticket corrected in `fret.md`, in the sibling documents it should have swept. §8.4 is
  entirely about that timer, so `threat-rir-mitigated.md` was carrying it as an open Low residual
  risk that no longer exists. Annotated all three in each document's existing status-line idiom:
  §8.4 obsolete; §3.7 partly overtaken (the trickle variant is gone — there is no idle window left
  to pace bytes inside — but a stalled inbound stream still holds a handler for the full 5 s, which
  is what the `readAllBounded` `NOTE:` already records the intended fix for).
- The accepted-tradeoff `NOTE:` above the `mergeNeighborSnapshots` call claimed the swallowed
  cancellation's "only effect is the overcount". There is a second effect: `fetchNeighbors`'s catch
  also emits one error line per remaining id. Bounded at 4 (the pass's slice) and pure log noise,
  so the tradeoff itself is unchanged — but a blast-radius sentence a future reviewer will trust
  should be true. Corrected in place; no behavior change.

**Major — none.** The diff is prose plus one comment; there is no code path to get wrong, and every
factual claim in it was independently re-derived above.

**Tripwires — none new.** Nothing in this change is a "fine now, matters if X later" concern. The
