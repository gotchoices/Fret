## What this ticket was

`diag.rejected.rateLimited` went from a flat number to a record
`{neighbors, ping, maybeAct, leave, announce}`, with the maybeAct inflight-cap rejection moved out
to a sibling field `concurrencyLimited`. Split 2 of 3 was to re-key ~17 assertion sites in
`test/rpc.codec-properties.spec.ts`.

The implement pass made **zero source edits** and handed over a no-op, on the grounds that the
sibling ticket `rejection-counter-split-test-callsites` had already re-keyed every site. That claim
is **true** — verified here, not taken on trust. But "every site compiles against the new shape" is
not the same as "every site asserts what the new shape now makes assertable", and one did not.

## Review findings

### Fixed in this pass (minor)

- **The five-path test summed its counters, discarding the attribution the split created.**
  `test/rpc.codec-properties.spec.ts` drains all five buckets, drives one rejection down each, and
  asserted `sum(five fields) - before === 5`. A sum of 5 also passes when one path double-counts
  and another counts nothing — i.e. exactly the mis-keying the split newly makes possible (a
  `rateLimited.ping++` in the leave handler). Before the split a sum was the only assertion
  available; after it, per-field deltas are free and strictly stronger. The test now asserts each
  of the five sub-fields moved by exactly 1, with a per-field message, and is renamed to say so.
  It stays non-redundant with the four single-bucket tests above it (those drain one bucket each)
  and with the independence test below it (that drains only maybeAct).
  - The `before` snapshot spreads the **counter record**, not `rejected` — `{ ...rejected }`
    shallow-copies, so `before.rateLimited` would alias the live object. Same hazard the wire-level
    test at ~1544 already carries a comment about; noted at the new site too.
- **`test/helpers/rate-limited.ts` deleted** — `sumRateLimited` had exactly one consumer (the two
  lines above) and now has none. It also hand-declared its own `RateLimitedCounts` interface rather
  than deriving from the service's diagnostics type, so a sixth bucket added to `src` would have
  left it silently under-summing while still compiling. Deleting retires that drift hazard rather
  than filing a ticket to keep two copies in step. Repo-wide grep confirmed no other reference.

### Checked, nothing found

- **Every `rateLimited` read in the spec is keyed.** 20 hits, all `.`-suffixed after this pass.
  Line 1647/1661 (the wire-level leave-asymmetry test) is keyed to `.leave`, which is the bucket
  that test actually drains — checked, not assumed.
- **Attribution is correct in `src`.** Each of the five handlers increments the field matching the
  bucket it took: `handleNeighborsRequest`/`bucketNeighbors` → `.neighbors` (1293),
  `handlePingRequest`/`bucketPing` → `.ping` (1301), `handleMaybeAct`/`bucketMaybeAct` →
  `.maybeAct` (1384), `handleLeave`/`bucketLeave` → `.leave` (1841),
  `handleAnnounce`/`bucketAnnounceInbound` → `.announce` (2002). This is the property the
  strengthened test now actually pins.
- **`concurrencyLimited` is covered elsewhere** — `test/inflight-concurrency.spec.ts:168,201`
  asserts its delta and states the `rateLimited.maybeAct` vs `concurrencyLimited` split in a
  comment. Not re-pinned here; the codec spec only needs to *exclude* it, which it now does by
  enumerating the five fields inline rather than by a helper's doc comment.
- **No stray site.** No read of `rateLimited` outside a keyed access anywhere in
  `packages/fret/src`, `packages/fret/test` or `docs/`. `rpc.handler-fuzz.spec.ts:1195,1197` read a
  *local variable* named `rateLimited` assigned from a keyed delta on 1194 — correct. Nothing to
  hand to `31.7`.
