## What landed

Last slice of `debt-local-limit-arms-untested`. The counting half (8 table rows that **do**
increment `diag.streamLimit`) shipped earlier; the two write-ups of the non-counting half (the
accepted-tradeoff `NOTE:` at `FretService.countStreamLimit`, the `local-limit` clause in
*Stream management*) shipped in a second slice. This slice added the missing test rows and the
docs sentence that could only be written once they existed.

### The two rows

A new `describe` (`non-counting — an outcome that is not our own ceiling counts nothing`) appended
to `packages/fret/test/rpc.stream-caps-local-limit-arms.spec.ts`, **after** the capped block so it
cannot perturb that table's diagnostics deltas. Both rows drive a sender directly and hand the
returned `RpcOutcome` to `noteRpcFailure` — the same shape the existing "shared noteRpcFailure
seam" row uses — so no new private surface and no widening of the `priv()` cast.

- **`cancelled`** — abort an `AbortController`, `sendPing(..., { signal: ac.signal })`, assert
  `out.kind === 'cancelled'`, hand it to `noteRpcFailure`.
- **`skipped`** — a third `createMemNode()` that is never dialed, driven with
  `rpcRequest(..., { dial: 'never' })`, assert `out.kind === 'skipped'`, hand it to
  `noteRpcFailure`. `sendPing` exposes no dial mode, hence `rpcRequest` directly.

Each row drives `REFUSALS` (4) times with the contact-failure spacing rewound between drives, and
asserts `contactFailures === 0`, `state !== 'dead'`, membership / relevance / `failureCount` /
`successCount` unchanged against a pre-loop copy, `negotiateFailures === 0`,
`backoffOf(svc).factor(id) === 0`, and `after.streamLimit - before.streamLimit === 0` as a
**strict equality**.

### Docs

The *Stream management* `local-limit` paragraph in `docs/fret.md` now states that the table also
pins the two non-counting outcomes and that the counter assertion is an equality, not a "did not
decrease". The unpinned-arms list went from two arms to three.

## Review findings

### Checked

- **Read the implement diff first** (`git show 2b7c081`) — 114 spec lines plus a one-line docs
  edit — before the handoff summary. The two earlier commits on this slug touch only the ticket
  file.
- **Are the rows vacuous?** No, and the reason is stronger than the handoff claimed. Each row
  asserts `out.kind` explicitly before scoring, so a drive that silently succeeded or classified
  differently fails the row. Beyond that, `cancelled` and `skipped` land in `noteRpcFailure`'s
  `default:` arm (`packages/fret/src/service/fret-service.ts:888`, `// ok / busy / cancelled /
  skipped are the callers' to handle`) — read directly rather than inferred. So the rows pin a
  real arm: an edit that gives either outcome its own scoring `case` fails here.
- **Cap independence** — the stated reasoning holds. `cancelled` takes `rpcRequest`'s entry exit
  before `openRpcStream`, so no protocol cap is consulted; `skipped` targets the third node, which
  has no connection and `dial: 'never'` maps to `requireExisting`, so no stream is attempted. If
  the capped block is ever reordered ahead of the control block, both rows still hold — but the
  *control* block would break first, which is already stated in that block's own comment.
- **Third-node hygiene** — started in the inner `before`, `stopAll`-ed in the inner `after`, which
  mocha runs before the outer `after`. The exit watchdog would have failed the run otherwise, and
  did not.
- **The `skipped` row rewinds the right peer.** `expectCountsNothing` takes the row's `id` and
  calls `store.update(id, …)` itself rather than the module-level `rewindSpacing()`, which is
  hard-wired to the capped remote.
- **Docs are current, not assumed current.** Re-read the `local-limit` paragraph in `docs/fret.md`
  against the shipped spec: it names both non-counting outcomes, states the equality assertion and
  why a "did not decrease" would make the counting rows vacuous, and lists exactly the three arms
  the spec's own comments declare unpinned. No other doc section describes this spec, and the
  change touches no source file, so nothing else was owed an update.
- **Validation** — `npx tsc --noEmit` clean; `test/rpc.stream-caps*.spec.ts` **31 passing**, both
  new rows green. There is no lint step in this repo (`yarn check` is typecheck + build + test;
  `yarn format` is documented as not-runnable, see AGENTS.md).
