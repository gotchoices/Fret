Review of the `sim-routing-guard-spec` implementation (implement commit `5f906d6`), carried across
several runs that each crossed the soft token budget; this is the archived result.

## What shipped

`packages/fret/test/simulation.routing.spec.ts` guards the deterministic simulator's routing
quality: route success rate and p90 hop count over successful routes only, measured on a dense
200-peer ring, a sparser 1000-peer all-edge ring, and that ring under churn — plus one direct
assertion on the shipped `chooseNextHop` selector. `packages/fret/test/helpers/ring.ts` holds the
reference ring arithmetic (`toCoord`, `refMinDistance`) the spec uses to pick its cases.

Measured on the final run: dense n=200 100% success / p90 2 hops; sparse n=1000 95% / p90 2; the
same ring under churn 99% / p90 2; the selector case ~12s.

## Review findings

**Major — one case was vacuous; fixed in this pass rather than filed.**

The fourth case read "a route whose originator is already the peer nearest the target still
succeeds". It completed all 20 of its routes at hop 0 and never called the selector at all —
deleting the from-hop-2 `selfCoord` split at `test/simulation/fret-sim.ts:887`, the thing the case
was written to pin, left it passing 20/20.

Root cause: `handleRoute`'s anchor check (`test/simulation/fret-sim.ts:844-850`) runs before any
hop is chosen, and a peer that is locally nearest a coordinate *is* that coordinate's successor or
predecessor in its own store — so "locally nearest" implies the route terminates at hop 0. Nor can
any rewrite reach that split through a route: if the originator is *not* the anchor, its store's
successor and predecessor of the target are both in the candidate pool and at least one is strictly
closer, so the strict-improvement floor cannot bite at hop 0 either — unless every nearer entry is
`dead` (the candidate pool is `notDead`-filtered while the anchor check deliberately is not), which
is a partition-shaped case rather than a routing one.

The case is now `an originator already nearest the key has no strictly-improving first hop` and
calls `chooseNextHop` directly: supplying `selfCoord` strands the originator (`undefined` hop),
withholding it yields a hop. That is the actual reason production withholds the node coordinate
when originating, stated as a property of the selector instead of as an unreachable route outcome.

**Major — two documentation statements were wrong; both corrected.** The spec's header comment and
the *Testing strategy* bullet in `docs/fret.md` (~line 842) both claimed the case pinned the sim's
from-hop-2 `selfCoord` split. Neither claims that now; both state that the split is unobservable
through any route in this spec and say what would make it observable.

**Judgement calls, both decided and left as-is:**

- *DRY between the spec's case selection and `src/ring/distance.ts`.* Kept separate: the spec picks
  its cases with the reference arithmetic in `test/helpers/ring.ts`, so choosing a case is a
  cross-check on the shipped selector rather than an assumption about it. Sharing the production
  function would make the test agree with the code by construction.
- *`report()` writing to `console.log`.* Kept. The sibling simulation specs
  (`churn-scenarios.spec.ts`, `sim-profiles.spec.ts`) print their measurements the same way, and a
  measured guard whose numbers are invisible is harder to retune.

**Tripwires: none.** Nothing in this diff is "fine now, breaks if X" — the one conditional-looking
concern (that the sim's thresholds do not discriminate one plausible ring metric from another) is
already stated in `docs/fret.md` under *Testing strategy*, with its condition (the sim's eviction is
degenerate, so stores are near-uniform slices of the ring) and what would change it.

**Aspect sweep — nothing further found.** The diff is three test/helper files plus a docs bullet:
no resource handles, no error paths, no public surface, no `any`. Files are small
(`simulation.routing.spec.ts` ~230 lines, `helpers/ring.ts` ~40); functions are short and named.
Docs were read rather than assumed and needed the one correction above.

**Validation.** `npx tsc --noEmit` clean; `yarn build` clean. `yarn test` from `packages/fret/`:
**1077 passing, 6 failing** — all six are snapshot *sample*-merge assertions in
`test/announce-rate-limit.spec.ts` and `test/rpc.handler-fuzz.spec.ts`, failing at a clean HEAD and
in a subsystem this diff never touches. Reported in `tickets/.pre-existing-error.md` for triage; no
test was skipped or loosened. `yarn check` from the root was not run separately — it is typecheck +
build + test, all three of which were run individually above, and its test leg would fail on those
same six.

**Cross-check requested by the handoff:** the deterministic-replay case at
`test/simulation.partition.spec.ts:476` still passes with `successfulRouteHops` added to
`SimMetrics` (both scripted runs carry it identically). `simulation.partition.spec.ts` is 9 passing.
