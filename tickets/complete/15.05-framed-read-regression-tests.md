Regression tests for the fix in `framed-read-false-truncation`, which made `readFramed`
(`packages/fret/src/rpc/protocols.ts`) dispatch on the source type and deleted the 20 ms
`EOF_POLL_MS` poll that used to raise `FrameTruncationError` for a reply that had in fact arrived.

## What landed

- **Forced-race seam test** in `test/rpc.protocols.spec.ts` (`RPC deadlines` block): *"readFramed
  returns a buffered frame even while the stream reports itself finished"*. A stub holding
  `readBufferLength: 0` / `remoteWriteStatus: 'closed'` for the whole test while handing over a
  real length-prefixed frame; asserts the decoded body comes back rather than a truncation, and
  asserts `iterated === false` so the stream path is provably what produced it.
- **Restored close-then-read shape in `sendRaw`** (`test/rpc.handler-fuzz.spec.ts`): the half-close
  now runs before the read, and the stale comment describing the now-fixed defect is gone.
- **Codec pull-count measurement re-checked** — `countingSource` in
  `test/rpc.codec-properties.spec.ts` is a plain async generator, so it stays on the iterable path.
- Deferred: the two-node smoke matrix, split out as `implement/framed-read-two-node-smoke`.

## Review findings

### Verified — the handoff's biggest stated gap, now closed

The implement ticket flagged that *"the new test's failure under the pre-fix code was never
executed"* and invited a direct check. Executed it:

- Copied `git show 377c8fe:packages/fret/src/rpc/protocols.ts` in beside the real module and drove
  the new stub through that revision's `readFramed` from a throwaway spec.
- **Pre-fix result:** `FrameTruncationError: stream ended before a whole framed message arrived`,
  with `iterated === true` (the iterable path, racing `lp.decode` at ~50 ms against the 20 ms poll,
  exactly as the handoff reasoned).
- **Post-fix result:** returns `{"ok":true}` with `iterated === false`.

The guard bites. Temporary files removed; `git status` clean apart from the board.

### Verified — stub fidelity, against the library rather than the comment

Read `@libp2p/utils/dist/src/stream-utils.js` rather than trusting the test's own account:

- `byteStream`'s EOF gate is `isEOF(stream) === (remoteWriteStatus !== 'writable' &&
  readBufferLength === 0)`. The stub's two constants satisfy that on **every** `read()` — both the
  one-byte prefix reads and the body read — so the gate really is armed throughout, which is what
  makes the synchronous-dispatch requirement in the test's comment load-bearing rather than
  decorative.
- One correction to the test's doc comment, recorded here rather than edited (it does not change
  what the test does): `byteStream`'s own `isValid()` requires only five functions and *throws*
  `InvalidParametersError` when one is missing — it does not fall through. The silent fall-through
  to the iterable path is FRET's `isMessageStream`, which additionally requires `closeRead`. The
  `iterated === false` assertion pins the right thing either way.

### Fixed inline — one tripwire recorded at its site

`sendRaw`'s reordering is safe, but for a narrower reason than its comment gives. In-band framing
is not what saves it: `stream.close()` and `readFramed(...)` sit in the same **synchronous** block,
and `readFramed` -> `readFramedFromStream` -> `byteStream(stream)` registers the `message` listener
before its first `await`, so no transport dispatch can interleave. Insert an `await` between those
two lines and a reply landing in the window is dropped, presenting as a flaky `eof`. Added a
`NOTE:` at the site saying so. No behavior change.

### Filed as an arm on an existing ticket — coverage, not a new ticket

The *converse* invariant is only loosely covered: `test/rpc.stream-errors.spec.ts:386` accepts
either `FrameTruncationError` or `UnexpectedEOFError`, so it pins that an end-of-stream error came
back, not that it came back **promptly** — which was the deleted poll's entire job and is the
replacement's central claim. A read that sat out its full deadline would still pass. Same seam and
same file family as the deferred smoke work, so appended as a second arm to
`implement/framed-read-two-node-smoke` rather than filed separately.
