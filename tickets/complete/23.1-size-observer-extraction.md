Item (b) of the former `plan/23-fret-service-decomposition`.

## What landed

`packages/fret/src/service/size-observer.ts` — a `SizeObserver` class owning the observation array
and the four maths methods that were inline in `FretService`. It reads nothing but its own array
and an injected clock; the caller's *local* FRET estimate is passed **in** per call
(`LocalSizeEstimate`), which is what makes it store-free and unit-testable.

```ts
class SizeObserver {
	constructor(opts?: { windowMs?; maxObservations?; now? })
	report(estimate, confidence, source?): void
	blend(local: LocalSizeEstimate): BlendedSize          // { size_estimate, confidence, sources }
	churnPerMinute(): number
	detectPartition(local: LocalSizeEstimate): boolean
	observations(): SizeObservation[]                     // defensive copy
	clear(): void
}
```

`FretService` holds `private readonly sizeObserver = new SizeObserver()` plus a private
`localSizeEstimate()`; the four public methods (`reportNetworkSize`, `getNetworkSizeEstimate`,
`getNetworkChurn`, `detectPartition`) are one-line delegations. Public surface unchanged;
`SizeObserver` is deliberately not exported from the package root.

Maths carried across verbatim, with two deliberate changes: `stop()` now calls
`sizeObserver.clear()` (a start→stop→start cycle is a fresh run), and `report` refuses a non-finite
estimate or confidence, because one `NaN` in the array makes every later blend `NaN` while slipping
past the `totalWeight === 0` guard.

The private-field test seam is gone rather than relocated: nothing in the repo names
`networkObservations`, and nothing casts to `sizeObserver`.

## Review findings

Reviewed the implement diff (`8c16721`) first, then the handoff.

**Checked and clean.** Delegation faithfulness — all four service methods produce the same values
the inlined code did, argument-for-argument. The implementer's claim that the `oldAvg` "quirk" from
the plan ticket does not exist is **correct**: `slice(-5).length === Math.min(5, length)` holds for
every input, so numerator and divisor agree and it is a plain mean. Type safety — no `any`, the
cross-module type import is `import type`, `tsc --noEmit` clean. Resource cleanup — `clear()` on
`stop()` is placed alongside the existing backoff / departure-debounce clears and the observer holds
no timers or handles. Source hygiene — new file is 205 lines, single purpose, comments explain
*why* rather than restate code; `fret-service.ts` shrank by ~130 lines. Docs — the `docs/fret.md`
*Network size estimation* section was read in full and now matches the code, including the `stop()`
clear and the non-finite refusal.

**Test coverage.** The 28-case spec covers happy path, both sides of every boundary
(`windowMs` cutoff, count bound, `< 10`, `< 0.3`, the 3-old floor), error paths (non-finite input),
degenerate cases (all-confidence-0, non-advancing clock, all-stale) and the two regressions the
maths exists for. Verified the drop-arm cases are shaped so they genuinely fire rather than passing
vacuously. Nothing further needed at this level.

**Fixed inline (minor).** Both constructor options degenerate silently at 0 — `windowMs: 0` makes
the age filter drop the observation just pushed, and `maxObservations: 0` is a no-op because
`slice(-0)` returns the whole array. Neither is reachable in production (the service always takes
the defaults) so this is recorded as a `NOTE:` tripwire on `SizeObserverOptions` rather than
validated, with the condition under which validation should be added.

**Filed as a ticket (major).** `tickets/backlog/bug-wire-confidence-range-unchecked` — the
`confidence` field on inbound snapshots and ping replies is checked only for finiteness, never
against its documented 0-to-1 range, so a peer reporting an enormous confidence outweighs every
honest observation and dictates this node's blended size estimate (and with it cluster span and
near radius). Pre-existing and carried across unchanged by this ticket, not a regression it
introduced. Filed at the parser seam (`src/rpc/validate.ts`) rather than as a patch to
`SizeObserver`, because that module is documented as the single home for wire-shape rules and a
range-checked helper there makes the bad value unrepresentable past the boundary for every consumer.
Checked the site first: the one open ticket naming `validate.ts`
(`debt-maybeact-activity-cap-no-edge-split`) covers the maybeAct byte cap, a different rule.

**Recorded as tripwires, not tickets.** Two conditional concerns, both already stated at their sites
by the implementer and left as they are: `blend` does not trim, so a long quiet period leaves stale
observations weighted (negligibly) in the array; and `churnPerMinute` divides by the fixed half
window regardless of how the observations are actually spread, so it under-reports when the array
holds only stale entries. Both are pre-existing, both are harmless at the shipped constants, and
both only matter if the reporting cadence changes materially.

**Considered and declined.** The implementer's note that `detectPartition`'s drop arm is less
sensitive than it reads — the blend includes the observation history, so a low `local` against high
observations does not produce a low blended size — is accurate and is a property of the pre-existing
arithmetic. The ticket scoped arithmetic changes out, the spec's helper documents the behaviour, and
changing the sensitivity is a design decision rather than a review fix. No ticket.

**Declined from the handoff's own "known gaps".** Property-based (`fast-check`) coverage was
suggested; the example-based cases already pin both non-finiteness and the confidence clamp at their
boundaries, so a generator would add cost without adding a distinct failure mode here. Removing the
unused `observations()` accessor was also offered; it is the spec's only read path and its defensive
copy is itself pinned, so it stays. The two constructor options being test-only is intended (they
were `readonly` fields before) and is now covered by the tripwire above. The silent non-finite
rejection lacking a `diag` counter is real but sits behind the parser fix filed above — once
out-of-range values are refused at the seam, a poisoned value reaching the observer would mean a
parser bug, and that is the layer where the diagnostic belongs.
