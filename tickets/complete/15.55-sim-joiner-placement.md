## What shipped

Root cause (unchanged, and correct): `uniformCoord` divided by `this.nextPeerIndex`, which
`handleJoin()` incremented *before* placing, so each mid-run joiner landed at fraction
`index / (index + 1)` of the ring and packed tighter as the run went on. `initialize()` was
unaffected (`nextPeerIndex` fixed at `config.n` there).

Fix in `test/simulation/fret-sim.ts`: `addPeer(index, isJoin = false)` branches placement;
the initial population keeps `uniformCoord(index, population)`, a mid-run joiner gets
`randomCoord()` — a seeded random ring coordinate, which models placement-by-hash-of-peer-id and
removes the dependence on a mutable counter. Reviewed and accepted as-is: the population is now an
explicit parameter rather than a counter read at a distance, and the two other placement
strategies (`clustered`, `skewed`) never read the counter, so they are correctly untouched.

## Review findings

**Fixed in this pass**

- **All seven pre-existing churn tests had their seeds overwritten with `8008`** (1001, 2002,
  3003, 4004, 5005, 6006, 7007 → 8008), in the final implement commit `45c631f`, in the same
  commit that tightened the new test's threshold, and not mentioned anywhere in the handoff. The
  suite is seven scenarios that deliberately sample seven different random draws; collapsing them
  onto one seed throws away that coverage and looks exactly like seed-shopping for a green run.
  Restored to the original distinct seeds and re-ran `test/churn-scenarios.spec.ts`: **8 passing**,
  every threshold met (batched-leave coverage 87.5%, batched-join coverage 87.5% / 0 orphans,
  mixed-churn 87.5%, dead-neighbor ratio 0.0%, routing 95.0% success / 0.9 avg hops, continuous
  churn 40 alive, replay determinism). So the rewrite bought nothing — the handoff's claim that no
  recalibration was needed was true, and the seeds never needed touching.

**Filed as a ticket**

- **The new regression test does not fail against the bug it guards** → `fix/15.56-sim-placement-test-vacuous`.
  Verified by temporarily restoring the pre-fix placement and running only that case: largest gap /
  even spacing came out **6.25**, against a threshold of 10 — it passes. The fixed code reads 5.00
  at the same seed, so the two arms are 1.25x apart and no threshold on that statistic separates
  them. Largest-gap is the wrong measure here: the surviving evenly-placed initial peers bound the
  largest gap regardless of where joiners clump. Measured a candidate replacement (peers falling
  inside any one even-spacing-wide arc) at 4, identically across seeds 8008/8009/8010/4242/99,
  where largest-gap ranged 2.81–5.00 over those same seeds — recorded in the ticket as a lead, not
  a conclusion, since its pre-fix value was not measured. The ticket's acceptance step is
  explicitly "restore the old placement and watch it go red", because calibrating only on fixed
  code is how this shipped.

**Checked, nothing found**

- Source hygiene of the harness change: `fret-sim.ts` 936 lines, functions small and single-purpose,
  `randomCoord` documented with why (models hash placement), no dead code left behind.
- Style conformance of the new test: the manual event-pump loop, `console.log` diagnostics and
  `throw new Error` (rather than chai) all match the surrounding cases in the file — not nits, this
  is the file's idiom.
- `coordToBigInt` at the foot of the spec duplicates the inverse of `fret-sim.ts`'s private
  `bigintToCoord`. Left alone: one test-local reader of a private encoder, and hoisting it into the
  harness would widen that module's exported surface for a single caller.
- `randomCoord` draws from `this.rng` on every join where the old arithmetic drew nothing, shifting
  the draw sequence for every churn-enabled test. Confirmed harmless by the full re-run at the
  restored seeds above.

**Not run**

  `test/churn-scenarios.spec.ts`, which I re-ran in full (8 passing). `npx tsc --noEmit` likewise
