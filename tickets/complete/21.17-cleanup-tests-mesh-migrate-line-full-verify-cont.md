Closes the `cleanup-tests-mesh-migrate-line-full-verify` chain (21.15 → 21.17). The chain migrated
`packages/fret/test/proactive-announce.spec.ts` off hand-rolled per-test libp2p node/service setup
onto the shared `buildMesh` helper (`test/helpers/mesh.ts`), and fixed one real leak the migration
had introduced. No production code (`src/`) was touched anywhere in the chain.

## What shipped

- **`63f9ce3`** — the migration itself: 137 lines of per-test node/service boilerplate replaced by
  `buildMesh` + `addServices` + `connect`.
- **`fd81cf4`** — the leak fix. The `peer disconnect triggers proactive announcement` test stops
  node 2 abruptly mid-test to simulate an ungraceful departure, then means to skip only that
  already-dead *node* at teardown. `Mesh.stop({ skip })` skips **both** the service and the node at
  each index (its documented contract), so the migration silently dropped `service[2].stop()` and
  left that `FretService`'s stabilization timers armed past the end of the test — caught by the
  exit watchdog as a nonzero exit, not by any failing assertion. Fixed at the call site; the shared
  helper was deliberately left alone.
- **This review pass** — two further fixes in the same file, below.

## Review findings

### Checked

- The implement diff read first, against the pre-migration file (`git show

- The gap the implement ticket flagged as unaudited — *do other specs using `mesh.stop({ skip })`

  are correct**: each stops the service *and* then the node before recording the index, so
  "skip both" is the right contract for them. `proactive-announce.spec.ts` was the lone odd case,
  which is why a local fix rather than a helper change is the right shape. No further ticket.
- Type-check (`npx tsc --noEmit`) — clean. Targeted spec — 4 passing, **exit 0** (the watchdog
  check that matters here). There is no lint step in this repo; `yarn check` is the gate and
  `yarn format` is documented as not-to-be-run (`AGENTS.md`).

### Found and fixed in this pass (minor)

- **The explicit `services[2].stop()` was not exception-safe.** Teardown in this file is inline at
  the end of the test body, not in an `afterEach` — so a throw from that one stop would skip
  `mesh.stop()` entirely and strand the other four nodes and four services, surfacing as an exit
  watchdog dump stacked on top of the real error. (The other two `skip` call sites are immune
  because their teardown lives in `afterEach`.) Wrapped in `try { … } finally { mesh.stop(…) }`.
- **The migration introduced a timing skew against its own assertion.** The `edge profile sends
  fewer announcements than core` test used to interleave the two clusters' construction; the
  migration serialised it, so the edge cluster ran for the whole of the core cluster's setup before
  the shared 4 s sample window opened. Measured at **186 ms** of head start (instrumented
  `buildMesh(6)` + `addServices` + `connect('full')`, run under the same loader) against the 1500 ms
  passive stabilization interval — so roughly one run in eight handed edge a whole extra announce
  round, in the direction that *breaks* `coreTotal >= edgeTotal`. The two clusters are now built
  concurrently via a small local `announceCluster(profile)` helper, which also removes the
  duplicated four-line setup.
