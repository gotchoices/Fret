Test-only change plus a one-clause documentation fix found in review.

## What landed

**`packages/fret/test/rpc.handler-fuzz.spec.ts`** (+234 lines, the whole implement diff):

- **A pull counter on the inbound stub.** `inboundStub` gained `pulls`, incremented at the top of
  its async iterator's `next()`, so "the body was never pulled" is a measurement rather than an
  inference from the absence of a crash.
- **Two helpers promoted one scope level, no behavior change.** The per-subject `drive` /
  `expectDropped` moved up to the parent describe; `drive` became a generic
  `driveWith(protocol, register, chunks)` and the per-subject one is a closure over it. `Hooks`
  gained `lastLeave`, so the new rows can assert *what* reached the handler body rather than only
  that it ran.
- **Leave notice field matrix — 24 rows.** `from` (7 rows) and `timestamp` (5 rows) **reject**:
  `{closes: 1, aborts: 0}`, no reply, `onLeave` never ran, `onMalformed` reason exactly
  `['parse']`, zero identity mismatches. `replacements` (12 rows) **normalizes**: served, answered
  `{ok: true}`, `from` untouched, and either the key is *absent* from the notice
  (`'replacements' in notice === false`) or it equals the exact normalized list.
- **Frame-level abort arm — 2 rows.** Body-level drops close; frame-level failures abort. A
  truncated frame raises `FrameTruncationError`; an over-cap frame (8192 bytes against
  `registerLeave`'s fixed 4096) is refused in `readFramed`'s `onLength` hook, asserted as
  `{closes: 0, aborts: 1}` **and** `pulls === 1`.

**`docs/fret.md`** (review fix): the wire-shape parser table's `parseLeaveNotice` row now states
that `sanitizeReplacements` applies its 12-entry cap *before* the parse check.

## Review findings

### What was checked

- **The implement diff, read first and in full**, before the handoff summary. One file, 234 lines,
  no source file touched.
- **The four source sites the new rows pin**, read in full rather than trusted from the summary:
  `parseLeaveNotice` / `sanitizeReplacements` (`src/rpc/validate.ts`), `registerLeave`
  (`src/rpc/leave.ts`), `registerJsonHandler` and `registerRpcHandler` (`src/rpc/protocols.ts`).
  Every expectation in the matrix matches what those functions actually do — in particular
  `'replacements' in notice === false` matches the parser's `delete out.replacements` rather than
  a `[]` write, and the reject rows' `['parse']` matches the seam's `onMalformed('parse')` arm as
  distinct from its `'decode'` arm.
- **Fixture aliasing**, the failure mode that makes a table-driven matrix pass for the wrong
  reason. The peer-id seeds are disjoint across rows and against the file's fixtures — over-cap
  20–34, mixed 40–42, past-the-slice 50–52, versus `PEER_CLAIMED` 1 / `PEER_ACTUAL` 2 — so no row
  can pass by two ids colliding. `wellFormed` spreads its override *last*, so every row's
  corruption actually lands rather than being overwritten by the well-formed default. Row names
  are unique, so no two `it`s share a mocha title.
- **Assertion strength.** Every row pins the release *arm* (`{closes, aborts}` as a pair), not a
  release count — a count alone passes for an abort and would prove nothing about the
  close-vs-abort rule the whole describe exists for.
- **That `pulls === 1` measures what it claims.** The over-cap frame is handed to the stub as two
  chunks split at the varint boundary; merged into one chunk the assertion would read 1 for the
  wrong reason. The split is present and is the load-bearing part of that row.
- **The rig promotion.** `driveWith` / `expectDropped` moving up a scope is behavior-preserving:
  the per-subject `drive` closure passes the same protocol and register function the inlined
  version did, and the existing leave/announce subject rows continue to pass unchanged.
- **Documentation, treated as out of date until read.** `docs/fret.md`'s parser table and its
  three "decisions rather than mechanics" bullets were checked against `validate.ts`. One gap
  found (below); everything else — the 12-entry cap, the reject-vs-normalize split, the
  `undefined`-means-absent rule, and the frame-level-abort / body-level-close rule — already
  matched.

### Minor — fixed in this pass

- **The slice-before-filter ordering was undocumented.** `sanitizeReplacements` caps to 12 and
  *then* parse-checks, so parseable ids sitting past the twelfth entry are discarded along with
  the junk that displaced them. That is exactly what the matrix's load-bearing row
  (*"replacements: valid entries sitting past the slice"*) pins, and it was stated nowhere outside
  the test. A test pinning an undocumented ordering invites a future reader to "fix" the code and
  find only an opaque failure. One clause added to the `parseLeaveNotice` row of the wire-shape
  parser table in `docs/fret.md`.

### Major — none, with the reason

No major findings. The change adds no production code path, weakens no invariant, and every
assertion targets a rule that was already documented and already implemented — the diff is one
spec file plus its own ticket move. The two major-finding surfaces that actually apply to a
test-only change are (a) a test that passes for the wrong reason and (b) a test that pins
behavior the design forbids; both were checked directly above and neither is present.

### Conditional / speculative — parked as tripwires, not tickets

- **`pulls === 1` pins current `it-length-prefixed` chunk granularity.** It holds because
  `lp.decode` pulls whole chunks and the `onLength` hook throws before requesting another; an `lp`
  that pulled at byte granularity would fail this row against a still-correct implementation.
  Already parked at the site — the comment above the two-chunk split says exactly this — so
  nothing was added. Indexed here only.
- **The normalize rows do not assert `timestamp` passthrough.** `from` passthrough already proves
  the parser's `{...msg}` copy survives intact, and `timestamp` rides that same copy, so a
  dedicated row would buy a second observation of one fact. Deliberately not added.

### Considered and not re-filed

- **The frame-level arm is exercised on leave only**, and the maybeAct / neighbors caps plus the
  documented service-tier disagreement (the wire admits 512 KB while `handleMaybeAct` refuses an
  activity over 128 KB) have no frame-level row. That is `15.4-rpc-byte-cap-tightening`'s subject
  and it is already open in `tickets/implement/`; a second ticket for the same site would be the
  duplicate the site-claim check exists to prevent.
- **The announce-snapshot half of the matrix** is `15.32555-rpc-snapshot-field-matrix` and the
  service-tier cap counting is `15.3256-rpc-snapshot-cap-merge-tests`, both already in
  `tickets/implement/`. Both edit this same spec file, so expect merge conflicts if they land out
  of order — noted, not re-filed.
- **`v` is unchecked and deliberately has no row.** Nothing negotiates versions; a row asserting a
  reject would pin behavior `docs/fret.md` explicitly says must not exist.
