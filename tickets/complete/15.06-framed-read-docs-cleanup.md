## Review findings

**Checked:** the full implement-stage diff read before the handoff summary; `readFramed` and both
of its implementations in `packages/fret/src/rpc/protocols.ts` read line-by-line against every
behavioral claim the doc edits make; a repo-wide grep for `EOF_POLL`, `EOF poll`,
`end-of-stream poll`, `framed-read-false-truncation`, `remoteFinishedWriting`, `readAllBounded`
across `docs/`, `src/`, `test/` and `tickets/`; the surrounding comments in `ping.ts` and
`neighbors.ts` re-read for coherence after the note deletions.

**Fixed in this pass (minor):**

- `docs/fret.md` byte-cap bullet still said the cap is enforced "in the decoder's `onLength` hook".
  That is now true only on the iterable path — `readFramedFromStream` reads the prefix a byte at a
  time and checks the decoded length itself, and refuses at nine prefix bytes since that already
  declares ≥ 2^56. Rewritten to state both paths. This is exactly the kind of sentence the ticket
  existed to catch and it sits two lines below one of the edited bullets.
- `docs/fret.md` *Wire formats* trailing-bytes sentence — the one behavioral claim the implementer
  flagged for a second look — was half right. Trailing bytes *are* pulled on the stream path, but
  the sentence stopped there; `readFramedFromStream` calls `byteStream.unwrap()` in a `finally`,
  which pushes unread bytes back onto the stream for the next reader. Corrected.
- `tickets/backlog/debt-verify-fret-docs-stream-management.md` listed "the 20 ms end-of-stream
  poll" among constants "confirmed against the code and correct". That constant no longer exists;
  leaving it would have sent the next agent looking for it. Removed from the list.

**Verified correct, no change needed:**

- The `NOTE:` at `protocols.ts:510` that `docs/threat-analysis.md` §3.7 points at still exists and
  still says what the doc claims (inbound handler holds a stalled stream for the full budget;
  reintroducing an idle timer is ruled out).
- `test/rpc.protocols.spec.ts:570`, `test/rpc.stream-errors.spec.ts:858` and
  `test/rpc.protocols.spec.ts:712` still name the deleted poll, but each does so in the past tense
  as history ("the deleted 20ms EOF poll", "`readAllBounded` polled for EOF"). Same treatment the
  ticket already gave the `readAllBounded` comment at ~648. Left alone deliberately.
- `docs/threat-analysis.md` §8.4 and `docs/threat-rir-mitigated.md` §8.4 reference `readAllBounded`
  only as the superseded reader, explicitly marked obsolete. Correct as written.
- Stale `EOF_POLL_MS` hits in `packages/fret/dist/` are gitignored build output, not source.
- `ping.ts` / `neighbors.ts` read coherently after the note deletions — the remaining comments
  cover the body-less `registerJsonHandler` overload and the seam's ownership of encode/close, and
  neither depended on the deleted text.

**No new tickets filed.** Every finding resolved inline; none had a class behind it worth an
