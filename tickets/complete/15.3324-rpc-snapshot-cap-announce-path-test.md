## What shipped

One new test, `it('applies the cap through the handler the service actually registers')`, in
`test/rpc.handler-fuzz.spec.ts` inside `describe('announce snapshot merge caps')`, parameterized
over the `core` and `edge` profiles.

Every sibling test in that block builds `makeSnapshotParser(...)` in the test body, which *restates*
the 8th argument `registerRpcHandlers` passes to `registerNeighbors` rather than proving it — unwire
the parser at the registration site and all of them still pass. The new test closes that gap: it
swaps `handle` on a real started in-memory libp2p node for a recorder, calls the private
`registerRpcHandlers()` through a cast to capture the handler the service actually installs for the
announce protocol, feeds it a raw over-cap snapshot frame from a transport-authenticated `from`, and
counts store upserts. The truncation it observes can only have come from the parser the service
wired in.

Supporting mechanics, all load-bearing and all confirmed correct on review:
- `FROM` is seeded into the store *before* the upsert counter is installed, so the handler's
  detached `noteInboundRpc(from)` short-circuits on its `if (!getById(id))` guard and adds no noise.
- `mergeAnnounceSnapshot` is wrapped on the instance to capture and await the promise
  `handleAnnounce` detaches. `handleAnnounce` calls it through `this.`, so the instance property is
  genuinely consulted — the wrap is not bypassed by a bound reference.
- A real node is required (not the module's `fakeNode()`), because `applyTouch` / `enforceCapacity`
  reach `selfCoord()` -> `hashPeerId(this.node.peerId)` and the stub has no `peerId`.
- The connection's `remotePeer` matches the body's `from`; a mismatch is dropped silently and would
  read as a mystery zero count.

## Review findings

### Verified (what was checked)

- **Read the implement diff first**, via `git show 6a3f0fe -- packages/fret/test/rpc.handler-fuzz.spec.ts`
  (the two later commits in the chain are ticket-body edits only), before the handoff summary.
- **The wiring claim is real, not asserted.** Traced `registerRpcHandlers` at
  `src/service/fret-service.ts:1020` -> the `makeSnapshotParser(this.mergeSnapshotCaps())` argument
  at line 1033 -> `handleAnnounce` at 1772 -> `this.mergeAnnounceSnapshot` at 1777. Dynamic
  dispatch, real parser, real handler. The prior run's manual mutation check (uncapping the parser
  at the registration site turned exactly the 2 new parameterizations red, 173 others green) is
  consistent with what the code reads as; not re-run this pass.
- **Determinism of the upsert count.** `noteInboundRpc` (line 816) upserts only when `getById`
  misses; `applyMembershipSignal` and `noteProofOfLife` use `store.update`, never `upsert`. Seeding
  `FROM` first is sufficient, and there is no residual race.
- **Registration failure cannot pass silently.** `registerRpcHandlers` swallows and logs its errors,
  so the test's `expect(handler, ...).to.not.equal(undefined)` is the guard that catches it — present.
- **Rate limiting.** `handleAnnounce` takes `bucketAnnounceInbound` before merging; one message
  cannot exhaust it, and `expect(merges.length).to.equal(1)` fails loudly if it ever did.
- **Resource cleanup / leakage.** The monkeypatches (`node.handle`, `svc.mergeAnnounceSnapshot`,
  `store.upsert`) are all on per-test fresh objects; `afterEach` stops the node; the service is never
  started so there are no loops to stop. Nothing outlives the test, and the mocha exit watchdog
  would have failed the run on a leaked handle — it did not.
- **Typecheck**: `npx tsc --noEmit` from `packages/fret` — clean.
- **Spec run**: `node --import ./register.mjs node_modules/mocha/bin/mocha.js "test/rpc.handler-fuzz.spec.ts" --timeout 30000` — **175 passing**, run after this pass's edits.
- No pre-existing failures encountered; `tickets/.pre-existing-error.md` not written.
