Implement commit `51c3323` replaced per-spec casts into the service's probe-backoff internals with
one shared test helper (`test/helpers/backoff.ts`, exposing `backoffOf(svc)` over the public
`ProbeBackoff` surface), across five spec files, and refreshed the matching paragraph in
`docs/fret.md`.

Review ran in two passes: a first pass read the whole implement diff and both supporting source
files and exhausted its budget before validating; this pass ran the gates. No code changes were
needed in either pass.

## Review findings

### Checked — semantic equivalence of every converted site (first pass, read-only)

- `ProbeBackoff.factor(id)` returns `this.entries.get(id)?.factor ?? 0`, so `factor(id) === 0` is
  exactly the old `backoffMap.get(id) === undefined` and `factor(id) !== 0` exactly the old
  `!== undefined` — a retained entry always carries `factor >= 1`. Both directions of every
  converted assertion are faithful, including the inverted "backoff recorded" case in
  `dead-state.spec.ts`.
- `backoffOf(svc).clear(id)` reaches `ProbeBackoff.clear`, which is `entries.delete(id)` — the same
  effect the old `clearBackoff` cast had.
- `service-lifecycle.spec.ts`'s judgement call (the `stop()`-clears-state case) is sound: `factor()`
  returns 0 both for a never-recorded peer and after `clearAll()`, which is what the assertion means.
- The helper introduces no second cast — every converted site reaches `ProbeBackoff` through
  `backoffOf`'s public surface only.
- The `docs/fret.md` edit (*Security and abuse considerations → Current state*) renames the
  "backoff map" to `ProbeBackoff` and notes its own clock. No behavior claim changed; the
  surrounding capacity / sweep / retention text is untouched and still accurate against
  `src/service/probe-backoff.ts`.

### Checked — the two type-change spots the text substitution introduced

- `rpc.stream-caps-local-limit-scoring.spec.ts`: local `backoffFor` return type moved from
  `unknown` to `number`, and its two call sites from `.to.equal(undefined)` to `.to.equal(0)`.
  Type-checks clean and the spec passes.
- `stabilize-concurrency.spec.ts`: the diagnostic capture object's `backoff:` field is now `number`
  rather than `unknown`. Read every `backoff` reference and every `deep.equal` in the file — the
  capture is only ever compared *before-vs-after against itself* (`evidence(id)` vs
  `before.get(id)`, both built by the same helper), so the field's type change is symmetric and no
  assertion downstream compares it against `undefined`. Nothing to fix.

### Checked — stale-symbol grep

`grep -rn "backoffMap\|recordBackoff\|clearBackoff\|getBackoffPenalty\|BACKOFF_" src test --include=*.ts`
from `packages/fret/` returned no hits, confirming the implement handoff's claim.
