---
`FretService.enforceCapacity` now builds its eviction-protection set with the shared two-sided ring
walk (`ringNeighborsBothSides`) plus an explicit self id, instead of the store's own
`protectedIdsAround`. The protected set widens from `2m - 1` ids to `2m + 1`: self, plus
`max(2, m)` live members clockwise and the same counter-clockwise. The m-th successor and m-th
predecessor — genuine successor/predecessor members that the old walk left evictable because each
side spent a slot on self — are now protected.

`DigitreeStore.protectedIdsAround` was deleted rather than fixed: it had exactly one caller, and
keeping it would put the over-fetch rule in two modules.

### Protection arithmetic — re-derived by hand, all eight fixtures

Each fixture's survivor set was computed independently of the fixture comments (clockwise order
from self in `standardLayout` is `+1, +2, +1000 … +6000, -2, -1`), then compared with what the test
asserts. All eight agree; no transposed expectation hiding an off-by-one in the code.

- *protects the ring neighbors around self* — protected 7 (self, `near-cw-1/2`, `far-1`,
  `near-ccw-1/2`, `far-6`); 11 entries against a cap of 8 evicts `far-2` … `far-4`.
- *protects the m-th successor and m-th predecessor* — protected 7 (self + `succ-1..3` +
  `pred-1..3`); evicts `far-1` … `far-3`.
- *protects self when the ring walk returns nothing* — every other peer `foreign`, so the filtered
  walk is empty and protection is `{self}` alone.
- *picks victims by relevance* — far scores descend with ring order, so the evictions are
  `far-5`(2), `far-4`(3), `far-3`(4) and `far-2`(5) survives; a ring-ordered loop would have
  evicted `far-2` first.
- *drops a dead neighbor from protection* — the clockwise window skips dead `near-cw-2` and reaches
  `far-1`,`far-2`; evictions are `near-cw-2`, `far-3`, `far-4`.
- *does not protect an adjacent peer labelled foreign / unknown* (both arms) — window skips both
  `near-cw-*` and reaches `far-1..3`; evictions are `near-cw-1`, `near-cw-2`, `far-4`.
- *leaves the table over capacity* — m 8 gives 17 protected (self + ±1..±8); only ±9 and ±10 are
  evictable, so 21 entries settle at 17 against a cap of 4.
