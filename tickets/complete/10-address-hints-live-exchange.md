# Signed address hints in the neighbour exchange (live half) — complete

Fixes gotchoices/Optimystic#11. A NAT-only peer reachable only through a circuit relay used to become a ring member whose `/p2p-circuit` address nobody but its relay knew, so every sibling-initiated bare-id dial failed with `NoValidAddressesError`. Neighbour snapshots now carry libp2p signed peer records (`NeighborSnapshotV1.hints`) for the peers they name; a receiver checks the labelled id against both the envelope's signer and the payload's peer id, skips anything not newer than the record it already holds, and hands the rest to `peerStore.consumePeerRecord`, which verifies the signature and writes the addresses. Each node seals its own record with `FretConfig.privateKey` (the `privateKey` component when hosted by libp2p) and re-seals when its address list changes, so a reservation landing after start reaches the next snapshot. The full design lives in `docs/fret.md` under *Dialability → Address hints*; the implementation landed in `ticket(implement): address-hints-live-exchange`.

The persisted-table half (a restarted node reloading these records, gotchoices/sereus#18) is the follow-on ticket `address-hints-persisted-table`, which builds on the `PeerEntry.addressRecord` field this ticket added.

## Review findings

Read the implement diff in full before the handoff, then every file it touched plus the two it should have touched (`peer-discovery.ts`, `request.ts` — both were). Ran `npx tsc --noEmit`, the two new address specs, the profile spec, then the full `yarn check` from root (typecheck, build, script tests, mocha suite): **1300 passing, 0 failing, 0 pending** (5 min). Log at `tickets/.logs/address-hints-live-exchange.review.log`. There is no lint step in this repo (see AGENTS.md).

**Checked and found correct.** The identity pre-check is load-bearing, not belt-and-braces: libp2p's `consumePeerRecord` (read in `@libp2p/peer-store`) checks only the signer against `expectedPeer` and then patches the *payload's* peer id, so without FRET's payload check a peer could sign a record rewriting another peer's addresses. `store.update` on a missing id is a no-op, so an entry evicted during the `consumePeerRecord` await cannot resurrect. `exportEntries` picks fields explicitly, so the `Uint8Array` on the entry never reaches JSON. `decapsulateCode(CODE_P2P)` on an address with no `/p2p` component returns the whole address (slice to `undefined`), so the projection is safe on bare addresses. Hints are vetted against the post-truncation named set, so the merge caps bound verify work; a hint can never reach `peerIdFromString` with an unparseable id because no store entry exists for one. Ingestion runs after id merges on both inbound paths and after capacity enforcement on the announce path, before the announce to newcomers that needs them dialable. The wire-cap arithmetic (60,738 < 65,536) is pinned both concretely and as a bound. The rate-limiting arm the handoff says was parked is present in `tickets/backlog/20-debt-per-peer-rate-limiting.md`. Re-ran both mutations the relay spec's header records (ingestion disabled → the peerStore wait times out; control stays green) and confirmed they redden it.

**Minor, fixed in this pass.**
- `SelfAddressRecord`: two snapshot builds straddling an address-list change could let the *earlier* seal (lower sequence number) finish last and land in the cache, so the next snapshot carried a stale record until a later build noticed the mismatch and re-sealed. Added a seal generation counter: a seal overtaken while signing never commits and hands back the newer seal's result. Pinned in the new `test/address-records.spec.ts` with a gated `sign`; the test fails without the guard (checked by mutation).
- `adoptPeerRecord` peeked two envelopes (two protobuf parses each) on every `peer:update`, including the echo of FRET's own `consumePeerRecord` and unrelated peerStore changes for that peer (tags, protocols). Added a byte-equality fast path ahead of the decode; the sequence rule still catches the rest.
- `validate.ts` JSDoc linked `{@link MAX_SELF_RECORD_ADDRS}`, a symbol from another module it does not import; rewritten as prose.
- `docs/fret.md`: the two clauses above updated, and the new spec added to the *Pinned by* sentence.

**Tests.** The implementer's tests all pin real contract (the reproduction with its negative control; the forgery matrix beside its positive control; parser rows tied to the named set; the byte-cap invariant) and none restates the implementation or verifies a mock, so nothing was cut.
