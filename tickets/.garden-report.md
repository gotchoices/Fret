## Queue re-ranked (commit `7cb5f67`)

The previous ranking was built around what was safe to land in front of a downstream build. That
constraint is gone, so the queue reverts to ranking by value.

1. **`plan/15-rpc-shared-helper`** stays at the head. It was deferred *because* of the deadline; a
   freshly tagged beta is the right window for a refactor that deletes roughly half the rpc
   directory. Its handler-stream-leak arm is struck — the receive half already landed as
   `registerRpcHandler` under `rpc-handler-fault-isolation`. The ticket now says to adopt that seam
   rather than re-derive it, and records the subtlety a rewrite would otherwise lose: `status` alone
   cannot tell you whether a handler already released a half-closable stream, because it stays
   `open` until the *remote* closes its write end — the write-end status is the load-bearing one.
2. **`plan/15.5-sim-router-realism`** moved up from 24. It was ranked last while being load-bearing
   for three other items (`plan/2-ci-matrix`, the far-mode selector work, any routing tuning):
   nothing under `test/simulation/` imports the shipped selector, so the sim's routing-success
   threshold validates ring-maintenance math rather than the routing code it is meant to protect.
3. **`plan/17-store-perf-allocation`** annotated, not promoted. The `coordToHex` lookup table moved
   half its premise: the per-probe 64-char hex string still exists at `digitree-store.ts:153`, it is
   only cheaper per unit. Do not size this work on the old "38% of total CPU" number — re-measure.
   The wrap-walk early-exit half is untouched by that change and is where the structural win is.
4. **`plan/19-cleanup-rpc-layer`** annotated to stay sequenced *after* the consolidation. Its items
   tidy exactly the code that refactor rewrites, so landing it first is churn and landing it
   concurrently is a directory-wide merge conflict.
