**Saturday night into Sunday** — the far-mode selector floor, discovery-emission

plumbing through the RPC layer.

Three results worth reading before you release:

1. **A hot-path performance defect, found by profiling a timing-out test.** `coordToHex` in
   `src/ring/hash.ts` allocated two throwaway strings per byte — 64 per coordinate — and
   measured **38% of total CPU** in the N=100 simulation. `DigitreeStore` embeds the hex
   coordinate in every tree key, so it ran on every store write and every ring walk. Now a
   256-entry lookup table. **Check whether this retires `plan/16-store-perf-allocation`**
   before promoting that ticket.
2. **A real leaked async operation.** The suite hung after passing; the ticket was filed
   honestly as `severity: cosmetic` with `--exit` already masking it, but the follow-up found
   the cause: `mocha-exit-leak-proactive-announce`, a proactive announce holding the Node
   process open. Service-side, not test hygiene. A watchdog also landed so a future leak
   surfaces instead of hiding.
3. **A regression, caught and fixed the same morning.** `map-capacity-bounds` added a
   `maxTracked` bound to the discovery bookkeeping map in `d8449e7`; past that bound roughly
   half of known peers were never announced to libp2p — always the same half, permanently.
   `git log -S maxTracked` confirmed it was new. Filed as
   `bug-discovery-scan-starves-ring-tail` (`repro: verified`) and carried to `complete/` in
   `f4bcdec`. It is the newest code in the tree, so it is the least soaked.
