## Read this first — optimystic will not build clean against this tree

I checked `../optimystic` against the current FRET public surface. Three things:

1. **`xorDistance` is gone and optimystic imports it.**
   `packages/substrate-simulator/src/ring-model.ts:1` and
   `packages/substrate-simulator/test/fret-model.spec.ts:2` both import it by name. The
   ring-distance consolidation removed it in favour of `minDistance`, deliberately — XOR maximizes
   where arc length minimizes, so it was giving that simulator wrong answers near the wrap-around
   seam. **Fixing this is optimystic's edit, not FRET's**; re-adding the export would just keep the
   wrong metric in use. Note that it is a behavior change, not only a rename — the numbers move.
2. **Resolution is mixed today, which is why this has not bitten yet.** optimystic's root
   `package.json` uses `p2p-fret: portal:../Fret/packages/fret` (this working tree, live), while
   `packages/substrate-simulator/package.json` pins `^0.6.0` from npm. `^0.6.0` will not accept
   0.7.0, so the moment you bump that pin, the import breaks.
3. **optimystic is asking FRET for something specific.** Its
   `tickets/backlog/debt-shared-limited-connection-dial-options.md` says the cleanest fix for a live
   defect is for FRET to export `openRpcStream`, and that it is "gated on a dependency release".
   That defect: `libp2p-node-base.ts:1041` opens streams without `runOnLimitedConnection`, so a
   relay-only peer holding a block silently never answers during restoration. Three hand-written
   copies of that selection logic exist downstream, one of them wrong. This is now `plan/1` here.

Three results worth reading before you release:

1. **A hot-path performance defect, found by profiling a timing-out test.** `coordToHex` in
   `src/ring/hash.ts` allocated two throwaway strings per byte — 64 per coordinate — and measured
   **38% of total CPU** in the N=100 simulation. `DigitreeStore` embeds the hex coordinate in every
   tree key, so it ran on every store write and every ring walk. Now a 256-entry lookup table.
   **Check whether this retires `plan/17-store-perf-allocation`** before promoting that ticket.
2. **A real leaked async operation.** The suite hung after passing. Filed honestly as
   `severity: cosmetic` with `--exit` masking it; the follow-up found the cause — a proactive
   announce holding the Node process open. Service-side, not test hygiene. A watchdog landed so a
   future leak surfaces instead of hiding.
3. **A regression, caught and fixed the same morning.** `map-capacity-bounds` added a `maxTracked`
   bound to the discovery bookkeeping map; past that bound roughly half of known peers were never
   announced to libp2p — always the same half, permanently. `git log -S maxTracked` confirmed it was
   new. Fixed in `f4bcdec`. It is the newest code in the tree, so it is the least soaked.
