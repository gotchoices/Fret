# Garden report

Pass run: 2026-08-14 (late evening, local). Scope: whole board, not just `backlog/` —
the pending queues had grown to 22 `fix/` + 24 `plan/` tickets with no ordering, which is
what actually needed organizing before an overnight runner could be pointed at them.

**Context for this pass:** a release is wanted tomorrow morning. The board was ranked with
that as the objective — correctness bugs that a consumer of this package would actually hit
first, cleanup and test-infrastructure work last.

## What this pass changed

### Merged four instance tickets into two theme tickets

Both merges follow *Architecture first*: the deliverable is the invariant that retires the
class, with the original findings preserved as evidence arms.

| Survivor | Absorbed | Why one ticket |
|---|---|---|
| `fix/3-membership-classification-strength` | `negotiate-failure-marks-peer-foreign-permanently`, `stale-identify-demotes-member` | Both are the same mistake: a weaker or staler membership signal overwriting a stronger, more recent one. Two guards at two call sites would leave the third site to be written wrong later. Deliverable is a classification-strength ordering (completed RPC > identify list > one negotiate failure). The first ticket already named the second as the same class. |
| `fix/10-store-index-tree-invariant` | `insert-conflict-import-orphan`, `update-rekey-desync` | Both let `DigitreeStore`'s ordered tree and its `byId` index diverge, at two write paths in one file. Deliverable is a single mutation helper that owns both structures, plus a property test asserting "exactly one tree entry per id, and `byId` points at it" — which a future write path cannot silently bypass. They also *must* land together: fixing import to move an existing id turns the latent re-key path live. |

No reproduction, measurement, or code-site reference was dropped — every file/line citation
from the four absorbed tickets is carried into the survivors.

Nothing else was merged. The six `plan/cleanup-*` tickets and the nine test-coverage tickets
are each genuinely different work at different sites; batching them would have traded
reviewability for a queue that only *looks* shorter.

### Ranked both working queues

Every `fix/` and `plan/` ticket now carries a sequence prefix, so the runner drains them in
priority order instead of alphabetically. Full ordering below.

### Backfilled backlog triage metadata

All 20 backlog tickets that lacked a `tradeoffs:` line now carry one — the honest
one-sentence argument for declining or deferring. None needed `severity:`/`likelihood:`:
every backlog item is a hardening feature or a design exploration, not a filed defect.
Two also gained a real `prereq:` line (`3-constrained-join-neighbor-attestation` →
`size-consensus-bounded-gossip`; `3-size-consensus-bounded-gossip` → `message-signatures`),
because those were previously recorded only in a non-standard `dependencies:` header the
runner does not read.

Three of those `tradeoffs:` lines are worth the human's eye, because writing them turned up
something the ticket body overstates or that has since moved:

- **`plan/3-metadata-sanitization`** — the prototype-pollution claim is weaker than it
  reads. Object spread defines own properties rather than invoking a setter, so the merge
  site the ticket names does not actually pollute a prototype. What remains is storage
  bloat, already partly bounded by the table capacity limit.
- **`impl/4-per-peer-rate-limiting`** and **`impl/4-leave-authentication`** — both list
  dependencies that have already shipped (`transport-identity-verification`,
  `announce-inbound-rate-limiting` are in `complete/`). They are unblocked now.
- **`plan/2-ci-matrix`** and **`plan/3-docs-simulator-invariants`** both depend on the
  simulator being trustworthy, and `plan/24-sim-router-realism` says it currently is not
  (it routes with global knowledge no real node has). Neither should be promoted before it.

Backlog slugs were **not** renamed to carry `bug-`/`feat-`/`debt-` prefixes. The human's
`impl/` and `plan/` sub-folders already encode kind, and renaming 21 files for a convention
those folders satisfy is churn with no triage benefit. Say the word and they get prefixed.

## Ranked queue — `fix/` (bugs; highest priority stage after review/implement)

Release-critical block — everything from here up should land before a release:

| # | Ticket | Why now |
|---|---|---|
| 1 | `stopstart-lifecycle` | A stop→start cycle produces an unhandled promise rejection from duplicate handler registration — process-fatal by default. Any consumer restarting the service hits this. |
| 2 | `idle-read-timeout` | A 100 ms gap between chunks is treated as end-of-message, so large snapshots over relayed or congested links truncate, fail to parse, and the *healthy* sender gets failure-scored. Easy fix, and it matches field symptoms. |
| 3 | `membership-classification-strength` | Field-correlated (gotchoices/Optimystic#11): peers demonstrably serving the network were stuck labelled foreign, excluded from ring and discovery, and the mesh never closed. |
| 4 | `unguarded-bare-peerid-dials-fail-on-addressless-peers` | Field-correlated (same issue, 76 logged address-less dial failures against admitted cohort members). Several paths dial peers whose address cannot possibly be known. |
| 5 | `dedup-defeats-resend` | The headline find-then-act flow never acts: the duplicate-request cache returns the cached digest reply to the follow-up that carries the actual work. The lookup then spins until its attempt budget is exhausted. |
| 6 | `pickanchors-key-coord` | One-line bug — anchors are measured from the all-zero coordinate instead of the key, so the wire response promises the key's neighbors and returns the wrong ones. |
| 7 | `maybeact-ratelimit-ordering` | The rate-limit token is taken *after* the expensive per-message work, so a flood of trivially-invalid messages bypasses limiting entirely. Easy. |

## Ranked queue — `plan/` (design and enhancement; deliberately *not* in tonight's run)

Correctness and robustness first (1–8), then tests (9–14), then performance (15–16), then
mechanical cleanup (17–22), then the two large refactors (23–24).

1. `consolidate-discovery-emission` — one of three emission paths can leak peers belonging to another network
2. `dead-state-transition` — the design promises dead-peer marking; nothing ever marks a peer dead, so unreachable peers linger and keep getting selected
3. `in-cluster-membership-width` — the act-locally test is stricter than the design, adding hops the sender did not budget
4. `leave-amplification-cap` — one small inbound message triggers ~10–14 outbound requests plus an eviction (its `prereq:` is complete)
5. `waitfor-helper` — ~10 tests sleep a fixed several seconds then assert; replacing with condition-waits makes every later run faster and less flaky
6. `map-capacity-bounds` — several bookkeeping maps have no hard cap
7. `stabilization-concurrency` — one slow peer stalls the whole maintenance cycle for tens of seconds
8. `rpc-shared-helper` — the send/receive path is copy-pasted 4–5 times with three inconsistent failure conventions; leaks connections, hides unreachable peers behind fake successes. High value, `hard`, and a wide blast radius — deliberately not scheduled near a release

   be moved up or held depending on how much risk the release should carry.

   SiteCAD_branch were all running concurrently at the start of this pass). The five-hour
   usage window is the real constraint on how much of the ranked queue lands by morning, not
