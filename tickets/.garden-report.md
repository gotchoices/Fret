## New ticket from the review passes

Eighteen review stages ran and filed exactly one new ticket, which this pass **promoted from
`backlog/` into `fix/1-bug-far-mode-self-distance-floor`**:

> The next-hop selector's *far* mode has no floor on distance-to-key. The
> "already connected" bonus (0.3–0.5) swamps the distance term (~0.002 per binary order of
> magnitude), so when connectedness differs, far mode ignores distance and can hand a message
> to a peer *behind* the sender. `repro: verified` — measured against the shipped selector.

Promoted rather than left parked because it is the exact sibling of the near-mode fix that
just landed (that work fixed only one of the two modes), it is `severity: wrong-result` ×
`likelihood: normal-use`, and settling the far-mode tolerance is a judgment the fix stage can
make and document — not a human-only call. It carries its own honest caveat: the
connected-first bias exists on purpose for mobile/edge nodes, and nobody has measured the
right balance.

**It is dormant below ~60 peers** (the near radius saturates the whole ring under
`n_est ≈ 2·β·k`), and nothing in the test suite or simulation harness runs at that scale — so
it is not a release blocker, but it is real at the scale FRET is built for.
