- `test/rpc.handler-fuzz.spec.ts:323` — repeats it to justify the

**Recommended disposition: export both, which makes all three true at once**, rather than
correcting three sites to say the surface does not exist. The argument is already made in the

a consumer wrapping its own JSON protocol over the same libp2p node has exactly the drop/abort and
stream-release problem this seam solves, and a hand-rolled copy is what drifts. Also export the two
option interfaces (`JsonRequestHandlerOpts`, `JsonReplyOnlyHandlerOpts`), or a consumer cannot name
what it is passing. Then extend `test/package-exports.spec.ts` — it currently pins the outbound
seam and the parsers in two `it` blocks around lines 55–80; this wants a third in the same shape.

`test/rpc.handler-fuzz.spec.ts` at minimum.

**(C) Decide the shape of `registerNeighbors`' trailing `snapshotParser` parameter.** It defaults
to a parser built with `Infinity` caps — "validate the shape, truncate nothing" — so a caller that

(`src/rpc/neighbors.ts`), so this is a tripwire rather than a defect. **Recommended disposition:

`test/rpc.handler-fuzz.spec.ts:426`) for a case production cannot reach. Decide it explicitly
