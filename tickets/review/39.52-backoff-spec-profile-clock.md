Closes the `backoff-spec-clock-conversions` continuation. Both spec files now reach the probe
backoff through its public class (`ProbeBackoff`) and the two test-only accessors
(`backoffOf` / `setBackoffOf`) instead of poking at a raw `ExpiringMap` behind the service's back.

## What changed

### `failure-recovery.spec.ts` — landed in the prior run, validated in this one
Converted in full before this ticket started (commits `d47b2f7` / `c03528b`) but never
type-checked or run. It is now both. No edits were needed to it here.

Shape, for the reviewer: a module-scope `clockMs` is seeded in `beforeEach` from `Date.now()`
immediately after the service is constructed and before any tick, and a
`new ProbeBackoff({ capacity: 2048, now: () => clockMs })` is installed via `setBackoffOf`.
`expireBackoff()` advances that clock by `DEFAULT_BASE_MS * DEFAULT_MAX_FACTOR + 1` (32_001 ms) —
past the longest window, far inside the 300 s retention — rather than writing `until: Date.now() - 1`.
A `factor(id)` helper reads `backoffOf(svcA).factor(id)`.

### `profile.behavior.spec.ts` — converted in this run
Two sites, both of which the original ticket named without verifying against HEAD. Line numbers
had drifted; the located sites were:

- **The two capacity cases** now read `backoffOf(svc).capacity` instead of
  `(svc as any).backoffMap.capacity`. Values unchanged (Core 2048 / Edge 512) — the sizing
  expression in the constructor was not touched, and `ProbeBackoff.capacity` is the backing map's
  normalized capacity. The `describe` heading and both `it` titles say "probe-backoff" rather than
  "backoffMap", since the field no longer exists under that name.
- **The sweep case** (`stabilizeOnce sweeps expired entries …`) installs a fake-clock
  `ProbeBackoff` through `setBackoffOf` and writes its entry with `record(selfId)` instead of
  `set(selfId, { until, factor })`. `departureDebounce` is still a raw `ExpiringMap` and is
  untouched.

**One real bug fixed there, not merely a rename.** The retention TTL was read as
`(CoreFretService as any).BACKOFF_RETAIN_MS`, which evaluates to `undefined` at HEAD — the
constant moved onto `ProbeBackoff` when the class was extracted and the service no longer declares
it. `undefined` flowed into `ttlMs`, so the backoff half of that case was asserting against a map
with no working TTL, and `Math.max(undefined, 2000)` is `NaN`, so the clock step was
`clockNow += NaN` — the clock never advanced at all. It now reads
`ProbeBackoff.DEFAULT_RETAIN_MS` (300_000) and the step is a real 300_001 ms.

## What the reviewer should push on

**The `ProbeBackoff` public surface was sufficient — nothing needed a second cast.** Both files
reach it only through `backoffOf` / `setBackoffOf` plus `capacity`, `size`, `record`, `factor`.
No spec wanted anything the class does not expose, so there is nothing to raise back at the
class's API.

**The sweep case's live-entry half is weaker than it reads.** After the fix it does assert a real
TTL, but `record()` also restarts retention, so the "a live entry is kept" tail would pass under a
sweep implementation that simply never expires anything. The expired half above it is what
carries that; worth confirming the pair still discriminates.

**`factor(id) === 0` is not the same claim as the old `map.get(id) === undefined`.** In
`failure-recovery.spec.ts` the three assertions that used to probe the raw map now read
`factor() === 0`. A *retained but window-closed* entry reports `factor > 0`, so the two differ
exactly where the retention rule matters — which is the point, but it means those assertions now
say "no backoff was ever recorded", strictly stronger than "no open window". Check each of the
three still wants the stronger claim.

**Neither spec was re-read end to end for other stale private-field reaches.** Only the sites the
ticket named were audited.
