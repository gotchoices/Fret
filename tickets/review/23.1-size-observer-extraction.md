## What landed

`packages/fret/src/service/size-observer.ts` — a new `SizeObserver` class holding the observation
array and the four maths methods that were inline in `FretService`. It reads nothing but its own
array and an injected clock; the caller's *local* FRET estimate is passed **in** per call
(`LocalSizeEstimate`) rather than reached out for, which is what makes it store-free.

```ts
class SizeObserver {
	constructor(opts?: { windowMs?; maxObservations?; now? })
	report(estimate, confidence, source?): void
	blend(local: LocalSizeEstimate): BlendedSize          // { size_estimate, confidence, sources }
	churnPerMinute(): number
	detectPartition(local: LocalSizeEstimate): boolean
	observations(): SizeObservation[]                     // defensive copy
	clear(): void
}
```

`FretService` keeps `private readonly sizeObserver = new SizeObserver()` plus a new private
`localSizeEstimate()`; the four public methods (`reportNetworkSize`, `getNetworkSizeEstimate`,
`getNetworkChurn`, `detectPartition`) are one-line delegations. Public surface unchanged —
`src/index.ts` and the `Libp2pFretService` pass-throughs are untouched, and `SizeObserver` is
deliberately **not** exported from the package root (`test/package-exports.spec.ts` pins that set).

The maths was carried across verbatim. Two deliberate changes on top:

- **`stop()` now calls `sizeObserver.clear()`**, beside the existing `backoffMap` /
  `departureDebounce` clears. A start → stop → start cycle is a fresh run.
- **`report` refuses a non-finite estimate or confidence.** The class is the boundary now, and one
  `NaN` in the array makes every later blend `NaN` *while slipping past* the `totalWeight === 0`
  guard (`NaN === 0` is false). Negative values are still accepted — the `> 0` gate lives at the
  caller (`calibrateSizeFromSnapshot`) and was left there rather than duplicated.

## Things a reviewer should look at

- **The ticket's claimed `oldAvg` "quirk" does not exist.** It said `slice(-5)` and the
  `Math.min(5, oldObs.length)` divisor "can disagree when `oldObs.length` is between 3 and 5". They
  are equal for every input — `slice(-5).length === Math.min(5, length)` — so this is a plain mean
  of the newest ≤ 5 old observations, not a truncated-numerator bug. Code carried verbatim anyway;
  the comment at the site now says this rather than repeating the ticket's claim. Worth a second
  pair of eyes on that reasoning.
- **`detectPartition`'s drop arm is much less sensitive than it reads.** `current` is the *blend*,
  which includes the observation history, so a low `local` against a history of high observations
  does not produce a low `current` — the observations outvote it. The drop arm fires only when the
  recent *observations themselves* have collapsed. Found while writing the spec (my first three
  drop-arm cases failed because they shaped `local` instead of the observations); the tests now
  shape the observations, and the helper documents why. This is pre-existing behavior carried
  across unchanged, not something this ticket introduced — flagging it because it is the kind of
  thing a reader would assume works the other way. No ticket filed; the ticket explicitly scoped
  arithmetic changes out.
- **`clear()` on `stop()` is a real behavior change**, however small: a service that is stopped and
  restarted now reports a size blended from its local estimate alone until peers report again.
  Nothing in the suite depended on the old carry-over, but it is the one place parity was broken on
  purpose.
- **`blend` does not trim.** Only `report` applies the age/count bounds, so a long quiet period
  leaves stale observations in the array and `blend` still weights them (negligibly). Pinned as
  contract in the spec; carried from the original.

## Known gaps

- No property-based (`fast-check`) coverage — every case is example-based. A generator over
  (observation sequences, clock schedules) asserting `blend` never returns non-finite and
  `confidence ∈ [0,1]` would be stronger than the hand-picked degenerate cases.
- `observations()` is not consumed by anything in production — it exists for diagnostics and the
  spec. If the reviewer would rather not ship an unused public method on an internal class, it is
  removable at the cost of the defensive-copy test.
- The two constructor options (`windowMs`, `maxObservations`) are exercised only by tests; the
  service always takes the defaults. That is intended (they were `readonly` fields before), but it
  does mean no production path proves them.
- Non-finite rejection is silent (`return`, no counter, no log). A poisoned wire value now
  disappears without a diagnostic. Arguably it should bump something in `diag`.
