## What the change was

The per-message caps on a received neighbor snapshot (Core 16 successors / 16 predecessors /
8 sample; Edge 8/8/6) used to be enforced twice — by the snapshot parser *and* by a
`slice(0, caps.*)` inside each of the two merge loops in `FretService`. The merge-loop copies were
removed; `makeSnapshotParser` is the single enforcement point.

**Behavior change, upheld.** `parseSample` rejects an entry whose `relevance` is not a finite
number, where the old merge loops read only `id` and `coord` and would have merged it. The
implementer flagged this for a second opinion; it was upheld — `relevance` is a required wire
field, so an entry missing it is unusable, whereas `size_estimate` / `confidence` are optional
advisories and so are dropped field-wise. Recorded at the code site as an accepted-tradeoff
`NOTE:` naming the declined alternative (`finiteNumberOr`), its cost, and a revisit condition.
