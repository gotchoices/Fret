## Settled and verified — do not redo, do not re-file

- **Two clocks (fixed, run 3).** `recordContactSuccess` scored at an injected `now()` while
  `recordContactFailure` scored at its `time` argument; those disagree on the scheduler's
  `processEvent` and `advanceTo` paths. `recordContactSuccess` now takes `time`, both call sites
  pass it, and the `now` dep is gone from `LivenessDeps`, the private field and the deps literal.
  Verified: `npx tsc --noEmit` clean, and `simulation.partition.spec.ts` +
  `simulation.routing.spec.ts` green (13 passing, 46 s) including deterministic replay.
- **Non-null assertions (settled, run 5).** `modelFor(selfId)` and `coordOf(id)` bang on
  `this.models.get` / `this.peers.get`. Both unreachable as crashes: `handleLeave` only sets
  `alive = false`, nothing deletes from `peers` / `stores` / `models`, and both deps are only
  called with an id the harness is itself sweeping or routing from. Comment at the deps literal
  states that; `handleLeave`'s "reclaim here if memory runs out" NOTE warns that reclaiming would
  turn both into crashes. No ticket.
- **Docs corrected (run 5).** `docs/fret.md` *Testing strategy* routing bullet no longer claims
  the sim's eviction is degenerate because "every entry ties at relevance 0"; it now says eviction
  is still degenerate for the store *shape* (unbounded stores plus a per-tick full-window gossip
  merge). Rest of that section read and matches the code.
- **Per-tick whole-store scoring magnitude** — tripwire `NOTE:` at `recordContactSuccess` with a
  revisit condition. Adequate; do not re-file.
- **`reprobeDeadEntries` applies no success scoring (settled, run 6).** Production's dead arm
  scores an answered re-probe; the sim's does not. Judged **out of scope and recorded at the site**
  as an accepted-tradeoff `NOTE:` on `reprobeDeadEntries` (`liveness.ts`), because the earlier
  framing ("a recovered entry never earns relevance back") was wrong: `contactSweep` runs *before*
  the re-probe pass on every tick (`fret-sim.ts:502` then `:505`) and a restored entry is no longer
  `dead`, so the next tick's sweep contacts and scores it. The whole divergence is one tick of
  deferred success credit, against a change that would rewrite stored relevance and `lastAccess` —
  the key the re-probe rotation and any capacity-bounded eviction order by. Revisit condition is
  stated in the NOTE. **Do not re-open this; do not file it.**
- Omitting `avgLatencyMs` from the success patch is **correct** per `recordSuccess`'s own doc.
  `lastAccess: time` in the failure patch is redundant but deliberate.
- `src/store/relevance.ts` was consumed as-is; not in the changeset.
- `npx tsc --noEmit` clean at the current tree — checked after every edit above **except** the
  run-6 comment-only NOTE, which adds no code.
