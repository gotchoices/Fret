# Signed address hints in the neighbour exchange (live half) — implemented, for review

Fixes gotchoices/Optimystic#11: a NAT-only peer reachable only via a circuit relay becomes a ring member, but no third party learns its `/p2p-circuit` address, so every sibling-initiated dial fails with `NoValidAddressesError`. The persisted-table half (restart, gotchoices/sereus#18) is the follow-on ticket `address-hints-persisted-table`, which depends on the `PeerEntry.addressRecord` field this ticket adds.

The design landed as the implement ticket specified it; `docs/fret.md` now carries the full description under *Dialability → Address hints*, plus the updated *libp2p integration*, *Stream management*, *Wire formats* and *Security* passages. This handoff is what a reviewer needs to verify it, and where the seams are.

## What changed, by seam

- **Wire** (`src/index.ts`): `NeighborSnapshotV1.hints?: AddressHintV1[]`, `AddressHintV1 = { id; record }` (`record` is base64url of a marshaled libp2p `RecordEnvelope` over a `PeerRecord`). No version bump. `FretConfig.privateKey?: PrivateKey` — the same field the message-signatures backlog ticket plans.
- **Store** (`digitree-store.ts`): `PeerEntry.addressRecord?: { envelope: Uint8Array; confirmedAt: number }`, opaque bytes plus local clock. Preserved by `upsert` (spread), patched by `update`. Not serialized.
- **Constants** (`rpc/validate.ts`): `MAX_NEIGHBORS_BYTES` 16 KiB → **64 KiB**; new `MAX_ADDRESS_RECORD_CHARS` 2048, `MAX_SNAPSHOT_HINT_BYTES_CORE` 48 KiB / `_EDGE` 16 KiB. In `service/address-records.ts`: `MAX_SELF_RECORD_ADDRS` 8, `ADDRESS_HINT_FORWARD_MAX_AGE_MS` 1 h. Worst Core emission measured by the codec spec: 11,575 fixed + 49,152 hints + 11 framing = 60,738 < 65,536.
- **Parser** (`makeSnapshotParser`): `hints` vetted after truncation against the named set `{from} ∪ successors ∪ predecessors ∪ sample ids`; kept only for a named id, once per id, `record` a base64url string ≤ 2048 chars; field deleted when empty. Structural only, never throws.
- **New module** `service/address-records.ts`: `peekPeerRecord` (structural, no crypto, never throws), `selfRecordAddrs` (identify's projection, bare `/p2p-circuit` placeholder dropped, reserved circuit addresses first, capped at 8), `SelfAddressRecord` (lazy seal, re-seals on address-list change, seq `max(BigInt(Date.now()), last + 1n)`, in-flight seal shared between concurrent snapshot builds, no listener to detach; clock-went-backwards `NOTE:` at the seq), `encodeAddressRecord` / `decodeAddressRecord`.
- **Service** (`fret-service.ts`): constructor throws if `privateKey` does not derive `node.peerId`; `start()` logs once when no key. `snapshot()` → `buildAddressHints(successors, predecessors, sampleIds)`: self first, then successors/predecessors interleaved nearest-first, then sample; non-self only while connected or `confirmedAt` within 1 h; per-hint cost `JSON.stringify(hint).length + 1`, skip-and-continue under the profile budget. `ingestAddressHints(snap)` at the end of **both** `mergeAnnounceSnapshot` (after `enforceCapacity`, before `announceToNewPeers`) and `fetchAndMergeSnapshot`: skip self / no entry → peek (undecodable, signer ≠ id, payload ≠ id → `diag.rejected.addressHint++`) → held seq ≥ new → skip → `consumePeerRecord(bytes, { expectedPeer })` (throw → counted; `false` → nothing) → `store.update(addressRecord)` + `setAddressKnown(id, true)`. `adoptPeerRecord` mirrors identify-stored records on `peer:update` (always) and in `seedFromPeerStore` (only when the entry holds nothing).
- **Facade** (`libp2p-fret-service.ts`): `Components` gains `privateKey?`; the core gets `cfg.privateKey ?? components.privateKey`.
- **Comments** updated where they said FRET carries no addresses: `hasAddresses`, `addressKnown`, `announceNeighbors` (neighbors.ts), the "128 KB" remarks in `handleAnnounce` / `mergeAnnounceSnapshot`, `peer-discovery.ts`, `request.ts` (16 KiB → 64 KiB), `MAINTENANCE_SNAPSHOT_TIMEOUT_MS`.
- **Dependencies**: `@libp2p/peer-record ^9.0.5` (dependencies), `@libp2p/crypto ^5.1.13` (devDependencies). `yarn why @libp2p/interface` still shows one copy (3.1.0) everywhere; the lockfile gained only the two descriptors.

## Known gaps and things a reviewer should look at

- **Per-sender verify cost is unbounded** beyond the global announce bucket and the named-set cap (Core ≤ 41 records per message, crypto only for records newer than held). A sender with throwaway keys can mint a fresh record per throwaway id on every message. Parked as an arm on `tickets/backlog/20-debt-per-peer-rate-limiting.md` (already appended there by the plan ticket) and stated in `docs/fret.md` *Security*.
- **Tripwire, in code:** `ingestAddressHints` step 3 re-decodes the held envelope (two protobuf parses, no crypto) on every resend — `NOTE:` at the site; cache the peeked seq beside the bytes if ingestion ever shows up in profiles. The entry keeps only opaque bytes by the ticket's design and the follow-on ticket serializes exactly that shape.
- **Tripwire, in code:** clock-went-backwards across a restart → lower seq than peers hold → new addresses refused until the clock passes it. `NOTE:` at the seq computation in `SelfAddressRecord.seal`; same limitation as libp2p identify.
- **`seedFromPeerStore` mirrors only when the entry holds nothing.** A record that libp2p updates *without* a `peer:update` reaching us (none known — identify always fires one) would not be re-adopted. Deliberate: it keeps the per-tick walk free of a peek per peer.
- **The relay spec's convergence relies on the foreign re-probe arm.** identify ran on the hub's nodes before their FRET services started, so each labels the others `foreign` from the stale protocol list and the foreign arm (Core 2/tick) re-admits them on the first tick. Identify-push is deliberately absent on those nodes — its header says why (with it, the relay could forward a fresh identify record and the self-seal mutation would stay green). If someone adds `identifyPush` to the hub, re-run the self-record mutation before trusting the spec.
- **`consumePeerRecord` replaces addresses**, so a bootstrap-configured address for a peer gives way to that peer's own signed record — accepted and documented; same as identify.
- **`buildAddressHints` encodes base64url per record per snapshot** (`encodeAddressRecord`) rather than caching the string; cheap at ≤ 41 records of ≤ 2 KiB, not measured.
- **Dormant path worth a glance:** `ingestAddressHints` decodes `hint.record` inside a `try` even though both inbound paths run the parser first — it guards a caller (a test, or a future path) handing the merge an unparsed snapshot.
