# Addresses in the saved routing table (restart half) — review

Fixes gotchoices/sereus#18. Optimystic's db-p2p saves and restores the FRET table (`exportTable` / `importTable`), but the table held only peer ids. A restarted node's libp2p peerStore is empty, so a bare-id dial to a peer reachable only through a relay failed with `NoValidAddressesError`, and each ring came back holding only itself. The live half (`address-hints-live-exchange`, complete) added `PeerEntry.addressRecord` (verified signed peer record + local accept time); this ticket persists and restores it.

## What changed

- **Store** (`digitree-store.ts`): new `SerializedPeerEntry.addressRecord?: SerializedAddressRecord` (`{ envelope: string /* base64url */, confirmedAt: number }`), plus a named `PeerAddressRecord` type for the entry field. `serializeAddressRecord` / `deserializeAddressRecord` own the persisted format; the deserializer throws on a non-string or non-base64url envelope and on a non-finite `confirmedAt`. `exportEntries` writes the field; `importEntries` decodes it in its existing decode-everything-first pass, so a malformed record still refuses the snapshot before any write. `SerializedTable.v` stays 1; tables without the field import as before. Both types are exported from the package root.
- **`address-records.ts`**: `ADDRESS_RECORD_PERSIST_MAX_AGE_MS` = 14 days, with its reasoning at the constant. `freshenExportedAddressRecord` (export rule: connected at export → `confirmedAt = now`; older than 14 days → omitted) and `vetPersistedAddressRecord` (import pre-pass: corrupt → throw; stale → drop the field; future `confirmedAt` → clamp to now). Both are pure functions.
- **Service** (`fret-service.ts`): `exportTable` maps the store's export through the freshness rule. The connection check runs only for entries that hold a record. `importTable` vets every non-self entry before the store sees any of them, imports, enforces capacity, and then calls the new `consumeImportedAddressRecords`. That method passes each surviving entry's record to `peerStore.consumePeerRecord` with the entry id as `expectedPeer`. `true` → `setAddressKnown`. A throw is a bad signature: the record is stripped from the entry (only if the entry still holds that same record object) and counted in `diag.rejected.addressHint`. `false` → the entry keeps its copy. The `NOTE:` import-latency tripwire sits at the top of that loop. `rejectAddressHint` is now `rejectAddressRecord(source, …)` so the snapshot and import paths share one count + log seam. The log text changed from "rejecting address hint" to "rejecting address record".
- **Docs**: `docs/fret.md` covers the *Serialized routing table* interface (new field + `SerializedAddressRecord`), *Routing table persistence* (a new "Addresses are restored too" block with the export rule, the corrupt / stale / bad-signature import rules, the 14-day reasoning and what pins it), the *Address hints* intro and "Where a record lives" (no longer "not serialized yet"), and one sentence in the *Security* address-hint bullet. The AGENTS.md layout line for `address-records.ts` is also updated.

## Tests (each checked by mutation)

- `service.table-persistence.spec.ts` — **'a restarted node dials a peer it knew only from its saved table, with no exchange first'**: this reproduces #18. Node A (memory transport + identify) connects to B, and identify's record is mirrored onto B's entry. A exports through `JSON.stringify` / `JSON.parse` and stops. A fresh node with A's key and a new peerStore then imports the table into a FRET service that is never started. Negative control, same `it`: the same table with `addressRecord` stripped restores B's entry, but the dial fails with `NoValidAddressesError`. Then the full table is imported and `dial(B.peerId)` succeeds. Removing the `consumeImportedAddressRecords` call makes this test fail.
- Same file — **'refuses the table for a corrupt record, strips a forged signature, drops a stale record'**: table-driven, with a fresh node per row. A good entry G with a genuine record sits beside B, and B's row supplies the record:
  - Refused rows: an envelope that is not a peer record, a record about B signed by C, and a genuine C record labelled B. Each import rejects, nothing is written, and not even G's record reaches the peerStore.
  - Stripped row: the signature is tampered. The import stands, B has no record, nothing about B reaches the peerStore, G is consumed, and `addressHint` goes up by 1.
  - Dropped row: the record is older than 14 days. Same as the stripped row, but the count stays 0.
  - Removing the identity check, the strip, or the stale drop each makes this test fail.
- `digitree.persistence.spec.ts` — the existing malformed-coordinate case is now table-driven. It adds two store-level rows: an envelope that is not base64url, and a `NaN` `confirmedAt`.
- `rpc.codec-properties.spec.ts` — the `SerializedPeerEntry` generator carries the optional `addressRecord` (random bytes, canonical base64url, finite `confirmedAt`). This extends the JSON round trip and the store import→export fixpoint property, with a distribution assertion that the field was generated. No new test.
- `test/helpers/libp2p.ts` — `createIdentifyMemNode(privateKey?)`: a memory node with identify, and optionally a fixed identity.

`cd packages/fret && npx tsc --noEmit && yarn test`: **1302 passing, 0 failing**. `yarn build` is clean. Log: `tickets/.logs/address-hints-persisted-table.test.log`.

## Known gaps / things for the reviewer to weigh

- **Import after `start()` can leave an entry holding an older record than the peerStore.** Import replaces by id, which is the existing documented semantic. So a live entry with a fresh identify-mirrored record gets replaced by the table's older record, or by none. `consumePeerRecord` then returns `false` (the peerStore holds a newer one), and the entry keeps the older copy. It forwards that older copy until the next `peer:update` adopt, and receivers holding the newer one refuse it on sequence number. Harmless, but slightly stale. Not fixed. The fix would be a `peerStore.get` on `false` to adopt the stored envelope. The common path (import before `start()`) cannot hit this.
- **Inspection-only, not tested:** the future-`confirmedAt` clamp; a record whose entry was evicted by the post-import capacity pass is never consumed (the loop reads the store after `enforceCapacity`); the "strip only if still the same record" guard against a hint that lands during the verify await; `false` from `consumePeerRecord` leaving the entry's copy in place.
- **Base64url is decoded twice per record on import**: once in the service pre-pass (to peek) and once in the store's decode loop. Accepted as cheap; the store has to decode for direct store users anyway.
- **Ticket numbers corrected**: the plan said the table capacity is "Core 2048 / Edge 512 max". The routing table's default capacity is 2048 on both profiles; 512 is the Edge `ProbeBackoff` cap. The constant's comment says "the table's capacity" without a number.
- Pre-existing: some touched files were LF in the working copy and are now LF after editing (`git` warns LF→CRLF). `core.autocrlf=true` normalizes on commit, and the diff shows only real changes.
