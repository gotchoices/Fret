## Edit 2 — self-id DRY (decided: constructor-bound field, not per-method binds)

`this.node.peerId.toString()` is recomputed at **27 occurrences** in `fret-service.ts`

`private readonly node: Libp2p` (~line 171) is assigned first thing in the constructor (~line
401), so the id is knowable at construction. Add beside it:

```ts
	/** Own peer id as a string. Bound once: `node` is readonly, so this cannot go stale. */
	private readonly selfIdStr: string;
```

assign `this.selfIdStr = node.peerId.toString();` immediately after `this.node = node;`, and
replace every occurrence. This retires the whole recompute class rather than the four sites an
earlier pass listed; local `const selfId = this.selfIdStr` binds inside methods stay fine and
need not be unwound.

## Edit 3 — redundant self in `exclude`

`announceNeighborsBounded` (~1473) builds `exclude = new Set([<self>])` and `announceOnDeparture`
(~1814) builds `new Set([<self>, departedId])`, while `ringNeighborsBothSides` drops self
unconditionally — self is excluded twice and the over-fetch reach is inflated by one slot.
Harmless numerically, but it invites a reader to believe the helper does not drop self. Drop self
from both sets (departure keeps `new Set([departedId])`; the bounded announce passes no `exclude`
at all) and add one line at `announceTargetsAround`'s call of the helper saying self is dropped
by the helper, so `exclude` carries only the extra ids.
