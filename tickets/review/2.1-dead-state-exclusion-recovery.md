Second half of the dead-state work (Phases 4–6). The sibling `dead-state-liveness-seam` ticket
added the contact-failure counter, the `dead` transition, and the recovery helper; this one makes
the label *mean* something (exclusion from routing) and makes it *reversible without outside help*
(a dead re-probe arm).

Build and tests pass: `npx tsc --noEmit` clean, `yarn test` **522 passing, 0 failing** (~5 min).

### What changed

**Exclusion is one predicate, not a second guard.** `isMember` in `fret-service.ts` was renamed
`isLiveMember` and extended to `e.membership === 'member' && e.state !== 'dead'`. It was already
the predicate every ring-shaped read funnels through, so this single edit covers the
successor/predecessor windows, cohort assembly, the routing-candidate walk, the size estimate, and
the outgoing snapshot's neighbor lists and sparsity sample. Two things fall out with no code of
their own:

- FRET stores no separate successor/predecessor *set* — those windows **are** the filtered ring
  walk — so exclusion from the predicate is the "remove from S/P" the design asks for.
- `enforceCapacity` protects only the peers that predicate returns around self, so a dead peer
  loses protection and, with a decayed relevance, sorts to the front of the eviction victim list.

`isMember` was module-private, so the rename is file-local (10 call sites). One test comment in
`membership-identify.spec.ts` named the old pass and was updated.

**Maintenance fan-outs that walk the store unfiltered got their own dead skip.** These deliberately
do *not* use the member-scoped ring views (an unfiltered walk is what keeps a freshly-connected
`unknown` peer from stalling bootstrap), so they need the guard stated locally:
`sendAnnouncementsRateLimited` (next to the existing `foreign` skip, before the token is spent) and
`sendLeaveToNeighbors`'s dial guard (`ids` itself stays unfiltered — it defines the S/P set the
replacement list excludes). `classifyUnknownPeers` also skips dead candidates so the two probe
passes never target the same peer in one tick.

**Recovery pass.** `reprobeForeignPeers` was split into `reprobeExcludedPeers` (the two-arm driver)
plus `reprobeOffRing(isCandidate, budget)` (the shared mechanics: off-backoff + reachable candidates,
ascending-backoff-factor order, per-tick budget, `probeMembership`). Arms: `foreign` (Core 2 / Edge
1) and `dead` (Core 2 / Edge 1). Separate budgets, not one merged list, so a large foreign
population can't starve dead recovery. The arms are **disjoint** — the foreign arm excludes dead
peers, so a foreign+dead peer belongs to the dead arm alone and a successful ping there fixes both
labels at once (`applySuccess` applies the membership signal and clears the contact-failure run
together). `stabilizeOnce` now calls `reprobeExcludedPeers`.

**Docs.** `docs/fret.md` updated in three places: the *Stabilization and churn handling* section
(removal-from-S/P is ring-view exclusion; why proof of life needs a path to *arrive*), the re-probe
pass bullet under *Ring membership* (now two arms, why the budgets are separate), and
*Network-scoped admission* (the predicate is now member **and** not dead; the two exclusions are
independent and separately recoverable). `contactFailures` / `deadAfterFailures` were already
documented by the sibling ticket.

`test/dead-state.spec.ts` now has 30 tests. New in this ticket:

- **Exclusion** — a dead peer placed *nearer* the key than a live one is absent from
  `getNeighbors`, `assembleCohort`, and the routing-candidate walk, where the live one is present.
- **No cohort shrink** — four dead peers nearest the key, live members further out: the cohort
  still returns `wants` ids, none dead.
- **Snapshot** — with 24 live + 4 dead peers, none of the dead appear in successors, predecessors,
  or the sample (and the sample is asserted non-empty so the check isn't vacuous); the member-scoped
  size estimate falls when half the ring is killed.
- **Capacity** — one dead peer and one live member neighbor at equal (zero) relevance past
  capacity: the dead one is evicted, the live neighbor and self survive.
- **Resurrection** — `noteProofOfLife` puts a dead peer straight back into `getNeighbors` and the
  cohort.
- **Standalone regression** — the no-filter `assembleCohort` / `estimateSizeAndConfidence` /
  `selectDiverseSample` exports and a bare `neighborsRight` still see dead entries, so the design
  simulator is unaffected.
- **Two-node recovery** — B is marked dead *and* left `unknown` in A's store, then one
  `stabilizeOnce()`: the ordinary probe targets are asserted empty (B is out of the ring), the ping
  count rises, and B comes back `connected` + `member` with a cleared run.
- **Budget isolation** — 40 foreign peers plus one dead peer: the dead one is still probed, and the
  foreign arm consumes exactly its own 2 slots.
- **Arm disjointness** — a foreign+dead peer is probed exactly once per tick.
- **Announce skip** — with a bucket stubbed to always grant, only the live target is attempted.
- **Resurrection race** — an inbound RPC concurrent with a failing probe; asserts the coherence
  invariant (dead ⟺ counter at threshold), not a specific interleaving.

### Known gaps — treat these as the floor, not the ceiling

- **The race test asserts an invariant, not a schedule.** Under the current interleaving the
  inbound RPC lands first and the trailing strike counts as 1. The test deliberately does not pin
  that number, because it depends on where `applyFailure`'s `await selfCoord()` sits. If a reviewer
  wants the stronger claim (the *last* writer wins outright), that needs a deterministic scheduler,
  not a `Promise.all`.
- **The announce-skip test stubs the token bucket** to count attempts, because a dial to a synthetic
  peer id can never succeed and `announcementsSent` only advances past a successful send. It proves
  the guard ordering (dead skipped before the token) but touches a private field.
- **The leave-path dead skip has no test.** It is the same one-line guard as the announce path and
  the same reasoning (`stop()` must not stack doomed dials), but exercising it needs a real
  neighbor set inside `stop()`. Called out rather than papered over.
- **The size-estimate assertion is directional** (`after < before`), not a pinned value — it goes
  through `getNetworkSizeEstimate`'s whole-store fallback path, since the service is unstarted and
  has no cached self coordinate. It proves dead peers are excluded from the counted population; it
  does not pin the arithmetic.
- **`FretPeerDiscovery` was left alone** — it already filtered `state === 'dead'` independently
  (`peer-discovery.ts:118`) and `peer-discovery.spec.ts` already covers it ("does not emit dead
  peers", "never leaks a foreign or dead peer from a restored routing table"). Verified it still
  agrees with the service predicate now that dead peers actually occur; no new test added there.
- **Backoff is shared across both arms.** `reprobeOffRing` reads one `backoffMap`, so a peer that
  accumulated backoff while foreign carries it into the dead arm. Intended (it is the same
  "don't hammer this peer" budget), but worth a reviewer's eye.

### Tripwire recorded

- Each stabilization tick now walks the whole store three times — once in `classifyUnknownPeers`
  and once per `reprobeOffRing` arm. Fine at C=2048; the `NOTE:` at `classifyUnknownPeers` in
  `fret-service.ts` says to do one walk and partition it if capacity or tick rate grows a lot.
