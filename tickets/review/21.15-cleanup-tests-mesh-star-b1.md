## What changed

### `iterative-lookup.spec.ts`

- Local `makeMesh(n)` (hand-rolled node loop + service loop + star dial) → thin wrapper over
  `buildMesh(n)` with no factory (helper's default `createMemNode`, memory transport — same factory
  the file used before). Order preserved: `addServices(...)` then `connect('star')`, i.e.
  services-first, so each `peer:connect` handler still fires.
- `bootstraps` unchanged: `i === 0 ? [] : [m.ids[0]!]`.
- Deleted the local `type Mesh = Awaited<ReturnType<typeof makeMesh>>` alias (it collided by name
  with the helper's exported `Mesh`); the helper's type is imported instead.
- Deleted the local `teardown({nodes, services})`. All three cases still tear down from their
  existing `finally`, now calling `await mesh.stop()`. **The load-bearing comment was moved, not
  dropped** — its reasoning (tear down from a `finally` so a failed assertion reports itself rather
  than being buried under the exit watchdog's open-handle dump; service stops settled rather than
  `Promise.all`ed so one rejecting stop cannot strand the rest) now sits on `makeMesh`'s doc block,
  stated once for all three cases rather than copied into each `finally`. **Reviewer: this is the
  one judgement call in the ticket** — the instruction said "onto the call site" and there are three
  call sites; one shared home next to the rig every case uses was chosen over three duplicates. Move
  it if you disagree.
- Imports: `createMemNode`, `stopAll` and `FretService as CoreFretService` all became unused and
  were dropped; `./helpers/mesh.js` added. Typecheck confirms none were still needed.
- One incidental cleanup: `nodes.slice(1).map((n: any) => ...)` lost its `any`, since the helper's
  `Mesh` types `nodes` as `Libp2p[]`.
- The header comment (lines 9–16) about behaviours deliberately *not* tested in this file is
  untouched.

### `maybeact-dedup-phases.spec.ts`

- Only the inline rig inside `iterativeLookup does not re-probe a peer` migrated. 4 nodes,
  `{ factory: createMemoryNode }` — **TCP preserved**, this site does not use the default memory
  factory. Services-first then `connect('star')`, then the same 2000 ms settle.
- Teardown `await Promise.all(services.map(s => s.stop())); await stopAll(nodes)` →
  `await mesh.stop()` (which settles per-service stops, so this is a strict improvement over the
  `Promise.all`).
- `makePair()` at the top of the file is **out of scope and untouched**, so `createMemoryNode`,
  `stopAll` and `CoreFretService` all stay imported. The now-unused `import type { Libp2p }` was
  dropped.

## What a reviewer should check

- **Behaviour, not shape.** The claim is that only *how the nodes get spun up* changed. Diff each
  case body against `git show HEAD:packages/fret/test/iterative-lookup.spec.ts` and confirm no
  assertion, timeout, key, ttl, `wantK`/`minSigs`, settle duration or activity-handler wiring moved.
- **Factory per site.** `iterative-lookup.spec.ts` must stay on the memory-transport default
  (`buildMesh(n)`, no options) and the dedup site must stay on TCP
  (`{ factory: createMemoryNode }`). Swapping either is silent — both still pass — so it is worth
  eyeballing rather than trusting the green run.
- **Ordering.** Both rigs are services-then-dial. `buildMesh` deliberately leaves that order to the
  caller; an accidental `connect()` before `addServices()` changes what `start()`'s
  `seedFromPeerStore` sees and would likely still pass on a 3–4 node star.
- **The moved comment.** See the judgement call flagged above.

## Known gaps / honest notes

- **Green-run confidence is per-file, not per-case.** Pass counts were compared as totals (3 and 6),
  not case-by-case against a pre-edit run — the pre-edit baseline was not captured before editing,
  so "same count" is inferred from the unchanged `it` blocks rather than from a recorded before-run.
  The full-suite 1123 is a post-edit number only; there is no recorded HEAD total to diff it against
  in this ticket.
- **Both files are timing-sensitive.** Each case sleeps 2 s and asserts on emergent ring state
  (probe counts, anchor substance). They passed on this machine; they are not deterministic rigs.
  A flake here would be pre-existing behaviour, not introduced by the swap, but the swap is not
  proof against it either.
- **`mesh.stop()` is a behaviour change in one direction on the dedup site**: `Promise.all` →
  settled stops. That is strictly more robust, but it does mean a rejecting service stop that would
  previously have failed the test is now swallowed. Deliberate — it matches what the helper does
  everywhere and what `iterative-lookup.spec.ts` already did — but it is a real difference, not a
  pure refactor.
- No tripwires recorded; nothing conditional was noticed at either site.
