## What changed

`test/simulation/fret-sim.ts` (was ~1050 lines, now 779 — the plan's ~660-line snapshot was
mid-refactor, size settled higher because `FretSimulation`'s public API surface stayed in the
file) was decomposed into four modules, already committed at d48ce8a:

- `placement.ts` — `CoordPlacement` (peer coordinate assignment, clustered/uniform placement,
  cluster centers)
- `reachability.ts` — `PartitionModel` (partition state, `crossPartitionBlocked` bookkeeping)
- `liveness.ts` — `LivenessModel` (dead/alive tracking, `notDead`, contact-failure escalation,
  dead re-probe)
- `measurement.ts` — `SimMeasurement` (coverage snapshot, `deadNeighborRatio`)

`FretSimulation` now composes these four; public surface (`partition`, `heal`,
`crossPartitionBlocked`, `snapshotCoverage`, `deadNeighborRatio`) is one-line delegates.
`PlacementStrategy` / `ClusterConfig` re-exported from `./placement.js`, so every existing spec
import is untouched — no test file needed to change.

## Critical edge cases preserved

- **Same-seed determinism (RNG call order).** `CoordPlacement` is constructed immediately after
  the message bus (the bus consumes no RNG), so clustered-mode cluster-center draws land at the
  same RNG position as before the split. This is the constraint that would silently break replay
  determinism if a future refactor reorders construction.
- **Liveness doesn't duplicate partition state.** `LivenessModel` consumes reachability only
  through the injected `contactAllowed` predicate — no separate copy of which peers are
  partitioned. This is what `test/simulation.partition.spec.ts` exercises (leave-during-cut,
  in-flight-message-drop, mid-split joins, deterministic replay of a cut/escalate/heal schedule).
- **`bigintToCoord` / `24-sim-router-realism` stale-comment TODO** from the original ticket was
  already satisfied by prior work (`cleanup-tests-core`) — nothing left to do here, confirmed
  during this pass.
- **DRY**: `uniformCoord` uses `helpers/ring.js`'s `toCoord` (verified byte-identical to the old
  inline implementation in an earlier run's investigation) rather than reimplementing it.
