## What landed

Last slice of `debt-local-limit-arms-untested`. The counting half (8 rows that **do** increment
`diag.streamLimit`) shipped earlier; the two write-ups of the non-counting half (the accepted-tradeoff
`NOTE:` at `FretService.countStreamLimit`, the `local-limit` clause in *Stream management*) shipped in a
second slice. This slice added the missing test rows and the docs sentence that could only be written
once they existed.

### The two rows

Appended to `packages/fret/test/rpc.stream-caps-local-limit-arms.spec.ts` as a new `describe`
(`non-counting — an outcome that is not our own ceiling counts nothing`), placed **after** the capped
block so it cannot perturb that table's diagnostics deltas. Both rows drive a sender directly and hand
the returned `RpcOutcome` to `noteRpcFailure` — the same shape the existing "shared noteRpcFailure seam"
row uses — so no new private surface and no widening of the `priv()` cast.

- **`cancelled`** — abort an `AbortController`, then `sendPing(..., { signal: ac.signal })`, assert
  `out.kind === 'cancelled'`, hand it to `noteRpcFailure`. This is the arm a naive "count it wherever we
  see a stream error" implementation over-counts.
- **`skipped`** — a third `createMemNode()` that is never dialed, driven with `rpcRequest(..., { dial:
  'never' })`, assert `out.kind === 'skipped'`, hand it to `noteRpcFailure`. `sendPing` exposes no dial
  mode, hence `rpcRequest` directly (write-only overload; it returns before any write matters).

Each row drives `REFUSALS` (4) times with the contact-failure spacing rewound between drives — same
shape as the counting rows, so a booked strike would provably have reached `dead` — and asserts:
`contactFailures === 0`, `state !== 'dead'`, membership / relevance / `failureCount` / `successCount`
unchanged against a pre-loop copy, `negotiateFailures === 0`, `backoffOf(svc).factor(id) === 0`, and the
delta that makes the rows non-counting: `after.streamLimit - before.streamLimit === 0`, a **strict
equality**. The helper is local to the new block and deliberately not shared with the counting rows.

### Docs

The *Stream management* `local-limit` paragraph in `docs/fret.md` now says the table also pins the two

unpinned-arms list went from two arms to three (see residual below). The mirror-case sentence (a remote's

## What a reviewer should check

- **Are the rows vacuous?** Each asserts `out.kind` explicitly before scoring, so a drive that silently
  succeeded (or classified differently) fails the row rather than passing quietly. Worth re-checking that
  reasoning, since it is the whole load-bearing part.
- **Cap independence.** Both rows run after the capped block installs `maxOutboundStreams: 0` on
  PROTOCOL_PING. Neither is affected: `cancelled` returns at `rpcRequest`'s entry check before
  `openRpcStream` is reached, and `skipped` has no open connection to the third node. Stated in comments;
  confirm the reasoning holds if the block is ever reordered.
- **Third-node hygiene.** It is `stopAll`-ed in the block's own `after`; the exit watchdog would have
  failed the run otherwise, and did not.
- The `skipped` row rewinds `lastContactFailureAt` on the **third** peer's id, not the capped remote's.

## Known gaps (stated, not papered over)

- **The `cancelled` row pins the outcome, not which error was suppressed.** An already-aborted controller
  takes `rpcRequest`'s *entry* exit (`if (opts.signal?.aborted === true) return { kind: 'cancelled' }`),
  so no stream is opened. The `classify` exit — a real stream refusal reclassified `cancelled` because the
  caller's signal fired first — is driven by no row. Two prior runs burned their budget chasing that
  narrow window; it is now recorded as a residual in both the spec comment and the docs paragraph rather
  than chased again. If a reviewer sees a cheap way to drive it, that is a genuine improvement — but it is
  not a defect in what landed.
- The two arms the spec already declared unpinned are unchanged: the leave rows drive `sendLeave` rather
  than the `sendLeaveToNeighbors` loop, and no row drives two refusals concurrently.
