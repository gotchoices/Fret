Implement stage of `7.4-rpc-cancel-evidence-tests` (test half of the cancellation-evidence work for
`rpc-service-signals`, Phase 4 of `7-rpc-abort-deadlines`). The docs half is `rpc-cancel-docs`,
still in `implement/`.

## The rule under test

`FretService.wasCancelled(sig)` is `sig?.aborted === true`, checked against the run signal the
**caller** captured before its loop — not the sender's own deadline, which is a child of it and so
also fires on a genuine timeout. When it is true the call site records nothing: no `noteRpcFailure`
(hence no contact strike and no relevance decay), no `recordBackoff`, no `diag.pingsFail`. Without
it a `stop()` landing on a busy tick manufactures strikes against healthy neighbors and can mark
them `dead`.

## What changed

**Tests** — one new `describe` block, "cancellation is not evidence about a peer", appended to
`packages/fret/test/dead-state.spec.ts` (10 tests). It constructs the service without starting it
(a live stabilization loop would probe the synthetic peers and make every count non-deterministic)
and reproduces the state `stop()` leaves behind with a local `cancelRun()` helper: a fresh
`AbortController`, aborted, assigned to the private `runAbort`. `stopped` is deliberately left
`false`, so what stops each pass is the *signal* alone. `liveRun()` is the contrast.

**Source, two changes:**

- `sendAnnouncementsRateLimited` — widened the existing top-of-loop check from `if (this.stopped)`
  to `if (this.stopped || this.wasCancelled(sig))`. This is the ticket's recommended one-line fix
  and it was taken. The `catch`'s `wasCancelled` return was removed at the same time, because it
  was unreachable on the cancellation path: `announceNeighbors` swallows every error internally
  (the abort included), so the catch only ever runs for a malformed peer id. Both facts are now
  stated in comments at the site. Behaviour change: a cancelled run spends **zero** announce
  tokens instead of one per remaining target.
- `iterativeLookup` — added a `NOTE:` at the final `yield { type: 'exhausted', hop }` recording
  that `exhausted` conflates "the ring offered no further hop" with "our own run was cancelled",
  and why widening `RouteProgress` (a public interface type) was rejected. **`rpc-cancel-docs`
  should not add this NOTE again** — its TODO already says to check first. The matching prose in
  `docs/fret.md` still belongs to that ticket.

## The two sites where the guard cannot fire

Both senders swallow every error internally, so the `catch` holding `wasCancelled` is never entered
on the cancellation path. A reviewer should know these are understood, not missed:

- **`mergeNeighborSnapshots`** — `fetchNeighbors` (`src/rpc/neighbors.ts:86`) catches everything and
  returns a fabricated empty snapshot, so `diag.snapshotsFetched++` still runs for a fetch that
  never opened a stream. Documented accepted behaviour, written up at the call site
  (`fret-service.ts:1759–1772`). The test therefore pins `snapshotsFetched` at **+1** rather than
  "unchanged", with a comment saying the expectation flips if `fetchNeighbors` ever distinguishes
  "skipped" from "empty". What it asserts instead: nothing merged, nothing scored.
- **`sendAnnouncementsRateLimited`** — this was the undocumented gap; it is now fixed rather than
  documented (above).

## Use cases the new tests cover

Each cancelled-path test asserts the same shape via a local `expectUnscored(id)` — entry still
present, `contactFailures === 0`, `state !== 'dead'`, `backoffMap.get(id) === undefined` — plus the
diagnostics counter relevant to that call site.

| Call site driven | What is asserted | Contrast that keeps it honest |
|---|---|---|
| `probeNeighborsLatency([id])` | `pingsSent` / `pingsFail` unchanged, nothing scored | live run → exactly one strike, `pingsFail` 1 |
| `probeMembership(id)` | same, plus **no backoff entry** (the load-bearing one — a cancelled probe must leave the next run free to probe immediately) | live run → one strike *and* a backoff entry |
| `preconnectNeighbors()` | **zero `dialProtocol` calls** | same pass on a live run → exactly 1 dial |
| `mergeNeighborSnapshots([id])` | nothing merged (store entry count unchanged), nothing scored, `snapshotsFetched` +1 | — |
| `sendAnnouncementsRateLimited([a,b], snap)` | **zero** announce tokens taken, `announcementsSent` 0 | live run → one token per live target (2) |
| `routeAct(msg)` forward path | reply is a `NearAnchorV1`, `diag.maybeActForwarded` +1, neither candidate struck or backed off | the counter increment *is* the proof the forward path ran rather than the message being answered in-cluster |
| `iterativeLookup(key, {})` hop arm | progress is exactly `['probing','exhausted']`, hop unscored | asserts `progress[0].peerId` is the seeded hop, so the walk really picked it |
| `iterativeLookup` activity-resend arm | progress is exactly `['probing','near_anchor','activity_sent','exhausted']`, anchor unscored | `activity_sent` in the sequence is what proves the resend arm was reached |

Recipes worth knowing before editing these tests:

- **Real Ed25519 peer ids, never synthetic strings.** `sendPing` / `sendMaybeAct` call
  `peerIdFromString` on their first line, *outside* the try — a synthetic id like `'peer-a'` throws
  a *parse* error, so the cancelled-path test would pass for the wrong reason and the contrast
  would record a strike unrelated to reachability. `unreachablePeer(coord?)` spins a mem node,
  stops it, and seeds its id (optionally at a chosen coordinate).
- **`preconnectNeighbors` needs a dial counter, not `pingsSent`.** That site increments `pingsSent`
  only *after* a successful ping, so an unreachable peer leaves it at 0 whether or not the run was
  cancelled — the counter cannot distinguish "cancelled" from "empty target list". Counting
  `node.dialProtocol` calls can; `openRpcStream` throws on an already-aborted signal before dialing.
- **`routeAct` forward path** is forced by hashing the key locally and seeding two member+dialable
  peers at `±1` from the key coordinate (`offsetCoord`), with `want_k: 2`, so the cluster window of
  `max(2, min(2,2)) = 2` is filled by them and self (not even in the store) is never in-cluster.
- **The activity-resend arm** needs a second node running a *started* `CoreFretService` on the same
  `networkName` so its maybeAct handler answers. The generator is driven with explicit `.next()`
  calls and the controller aborted the moment `near_anchor` arrives, so the abort lands on the
  resend rather than the probe. On a ring this small `shouldIncludePayload` is false regardless of
  distance (`probability * confidence >= 0.5` needs confidence ≥ 0.5, and confidence is
  `0.5*sizeFactor + 0.5*dispersion` with `sizeFactor = count / 2m`), which is what makes the probe
  digest-only and the resend arm the one taken.

## Known gaps — treat the tests as a floor

- **The two `preconnectNeighbors`-family sites are covered asymmetrically.** The one-shot
  `preconnectNeighbors()` is tested; the *active-preconnect loop tick* (same guard, `break` instead
  of `return`) is not — driving it means arming a timer loop, which is what every block in this
  file avoids. The guard is character-for-character the same, but that is an argument by
  inspection, not a test.
- **No test drives a real `stop()`.** Every test here injects the aborted controller directly.
  That `stop()` genuinely produces this state is pinned separately in
  `test/service-lifecycle.spec.ts:452` ("mints a fresh run signal per start and leaves the stopped
  run aborted") and exercised end-to-end at `service-lifecycle.spec.ts:380–450`; the seam between
  the two is convention, not assertion.
- **The `routeAct` and hop-arm lookup tests never open a stream.** With an already-aborted signal
  `openRpcStream` throws before dialing, so they prove "nothing was scored" but not "the abort
  propagated correctly through a partially-completed RPC". Only the activity-resend test aborts
  mid-walk against a live remote.
- **`expectUnscored` does not assert `negotiateFailures`.** A cancelled RPC should not be
  membership evidence either; the paths involved route through `noteRpcFailure`, which is skipped
  wholesale, so nothing can reach the membership seam — but the assertion is absent rather than
  redundant-and-present.
- **The announce fix widens a guard that no other test covers from the `stop()` side.** The new
  test injects a cancelled signal with `stopped === false` — precisely the `stop()` + `start()`
  mid-loop case the widened check exists for — but nothing exercises that interleaving for real.
