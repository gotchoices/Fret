## What shipped (already committed, in `fd81cf4` "ticket(implement):
cleanup-tests-mesh-migrate-line-full-verify")

`packages/fret/test/proactive-announce.spec.ts`, in the `peer disconnect triggers proactive
announcement to remaining neighbors` test's teardown:

```ts
// Node 2's libp2p node is already down, but its FretService is not — mesh.stop's `skip`
// leaves both alone, so the service must be stopped explicitly or its internal timers
// (stabilization interval, etc.) leak past the test.
await mesh.services[2]!.stop()
await mesh.stop({ skip: [2] })
```

**Root cause** (confirmed by diffing against the pre-migration version of the file,
`git show 7074998:packages/fret/test/proactive-announce.spec.ts`): that test simulates an
ungraceful disconnect by abruptly stopping `nodes[2]` mid-test, then only means to skip the
already-dead node 2 in teardown. The old hand-rolled teardown stopped every *service*
unconditionally (`await Promise.all(services.map(s => s.stop()))`, no filtering) while skipping
only the dead node. The migrated helper's `mesh.stop({ skip: [2] })` skips **both** the service
and the node at that index — that's `Mesh.stop`'s documented, intentional contract (see
`helpers/mesh.ts`'s jsdoc: "Both the service and the node at each index are skipped"), which other
specs may rely on as-is. So the migration mapping dropped a call it shouldn't have: service 2's
`FretService` was left running forever with its stabilization timers armed, which is what the exit
watchdog (`test/mocha-exit-watchdog.ts`) was catching.

The fix restores the original semantics (every service always gets `.stop()` called exactly once;
only the already-dead *node* is excluded from the node-stop pass) at the one call site that needed
it, without changing `Mesh.stop`'s general `skip` contract — `helpers/mesh.ts` itself was **not**
touched, so no other spec using `mesh.stop({ skip })` is affected.

**Flag for reviewer:** this fix was found via a hanging process (the exit watchdog), not a failing
assertion — worth a second look for that reason alone, even though it's narrowly scoped to one
call site.
