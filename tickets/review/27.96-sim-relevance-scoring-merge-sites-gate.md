## Open findings to decide — none resolved yet, all still open

- **Undocumented wall-clock/sim-clock mix (suggest a one-line `NOTE:` at `scoreMerge`).**
  `DigitreeStore.upsert` stamps `lastAccess` with `Date.now()`; every new scoring site then
  patches it to sim time. So on the *first* scoring of an entry `recencyScore` computes
  `max(0, simNow - wallClock)`, which is always 0, giving recency exactly 1.0; on later
  re-scores `lastAccess` is already sim time and the decay is real. Benign, but subtle and
  currently unwritten — the kind of thing the next reader re-derives from scratch.
- **DRY, minor.** `handleConnect`'s `touch` block is inline while the three merge sites share
  `scoreMerge`. Both are "score one entry in one store", differing only in hearsay vs proven
  contact. A sibling helper (`scoreContact`) beside `scoreMerge` would make the pair read as one
  rule with two arms; as written, a future edit must notice the inline copy.
- **Expressiveness, cosmetic.** `addPeer` computes `normalizedLogDistance(peer.coord, peer.coord)`,
  a constant 0. Reads as intent rather than as a magic 0, so it may be right as-is — recorded so
  the next reviewer does not re-decide it.
- **Source hygiene.** `fret-sim.ts` measured at **899 lines**
  (`wc -l test/simulation/fret-sim.ts`), up from ~830 before this diff, against six focused
  sibling modules of 51-220 lines. It is the harness's dispatch core by design, so this is an
  observation to weigh, not an automatic split.
