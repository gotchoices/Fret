  asked for `m + 1`: if self is in the store the walk returns `[self, s1..sm]` and the drop

## Edit 1 — pair the estimator's anchor fields (the one confirmed defect)

`SizeEstimateOptions.selfCoord` and `selfId` are independent optionals that are only meaningful
together. `collectGaps` passes `selfId ?? ''`; an empty string matches no peer id, so the helper's
`drop` predicate never fires, each side spends a slot on the anchor entry, and the window loses one
gap per side — G = 2m − 2 = 14 instead of 16 (confidence 0.8664 rather than 0.875). Quiet numeric
degradation, and `SizeEstimateOptions` is exported from the package root (`src/index.ts:142`), so an
external caller can reach the half-specified state. Ladder rung 1 (types/representation): pair them
so the half-specified anchor is unrepresentable and the `?? ''` fallback retires with it.

In `src/estimate/size-estimator.ts`, replace the `selfCoord` / `selfId` members of
`SizeEstimateOptions` with one field, keeping the existing prose about what supplying it selects:

```ts
export interface SizeEstimateOptions {
	/** Restrict the estimate to a subset of the store (e.g. same-network members only). */
	filter?: (e: PeerEntry) => boolean;
	/**
	 * Ring position *and* id of the local node. Supplying it selects the S/P-window method;
	 * omitting it selects the degraded whole-store fallback. The two travel as one field because
	 * the window walk drops the anchor entry by *id* — a coordinate without its id silently
	 * costs the window one gap per side.
	 */
	self?: { coord: Uint8Array; id: string };
}
```

Thread it through: `collectGaps` takes `self?: { coord, id }` in place of the two trailing
parameters and branches on `if (self)`, calling `windowGaps(store, m, self.coord, self.id, filter)`
— the `?? ''` disappears. `windowGaps` itself is unchanged. `estimateSizeAndConfidence` passes
`options?.self`.

## Edit 3 — redundant self in `exclude`

`announceNeighborsBounded` (1473) builds `exclude = new Set([<self>])` and `announceOnDeparture`
(1814) builds `new Set([<self>, departedId])`, while `ringNeighborsBothSides` drops self
unconditionally — self is excluded twice and the over-fetch reach is inflated by one slot.
Harmless numerically, but it invites a reader to believe the helper does not drop self. Drop self
from both sets (departure keeps `new Set([departedId])`; the bounded announce passes no `exclude`
at all) and add one line at `announceTargetsAround`'s call of the helper saying self is dropped by
the helper, so `exclude` carries only the extra ids.
