**Item 1 — `encodeJson` / `decodeJson` dropped `async`, call sites dropped `await`. Clean.**

`await`s left on the now-synchronous functions are legal and harmless.

**Item 2 — `PROTOCOL_*` constants derive from `makeProtocols('default')`. Clean.** Same review.

**Item 3 — success replies changed from `{ ok: true }` to `undefined`. Was a regression; reverted
in commit `9e1d510`.** At `547d506`, `yarn test` gave 1040 passing / 76 failing, all in
`test/rpc.handler-fuzz.spec.ts` and `test/rpc.codec-properties.spec.ts`, all on the leave / announce
reply path (`expected a reply frame, got eof`, plus ~60 cases of `Could not append value, must be
an Uint8Array or a Uint8ArrayList` from `it-length-prefixed` being fed the absent reply). Both
handlers return `{ ok: true }` again, each carrying a `NOTE:` recording the accepted tradeoff and
its revisit condition. Reasoning, recorded so it is not re-litigated: it is a wire-format change
rather than the low-risk tidy-up the ticket was scoped as; it collapses the seam's `undefined`,
which until then meant only "identity mismatch, drop", into meaning both "drop" and "success"; the
acknowledgement is observable by a non-FRET consumer, since the protocols and the
`registerRpcHandler` / `registerJsonHandler` seam are exported from the package root; and
`docs/fret.md` *Leave* parks planned work where `sendLeave` **does** read a reply so a rate-limited
leave can answer `busy`. The counter-argument (neither `sendLeave` nor `announceNeighbors` reads a
reply, so the bytes are provably unread by any FRET sender) is real but does not outweigh those,
and is recorded at both code sites as the revisit condition.

**Item 4 — `decodeJson` counts stripped NUL bytes and emits one `log.error`. Not a defect; parked
as a tripwire, and that is done.** The concern was log amplification: `decodeJson` runs *before*
the maybeAct token bucket (`registerMaybeAct` decodes in its own handler body, then `handle()`
takes the bucket), so a peer can drive one line per NUL-padded message with nothing metering it.
Checked and settled: `@libp2p/logger`'s `logger(name).error` is `debug(`${name}:error`)` from
`weald`, and a weald debug instance's body opens with `if (!debug.enabled) return`, where `enabled`
derives from the `DEBUG` namespaces. With `DEBUG` unset it writes nothing. So it is namespace-gated,
not unconditional — no ticket. A `NOTE:` tripwire is already at the `decodeJson` site naming the
revisit condition (FRET gaining a sink that records unconditionally: a metrics counter, a structured
logger, a file appender). This also confirms rather than inherits the debug-gated claim the existing
`NOTE:` in `src/rpc/leave.ts` makes about its own mismatch log.

**Docs — done.** The *Wire formats* `decodeJson` paragraph in `docs/fret.md` described the trim as
silent; it now states the NUL count line and its namespace gating. The *Leave* passages describing
`registerLeave` as committing to `{ok: true}` are correct again after the item-3 revert and were
