Semantic equivalence of every converted site holds on inspection:

- `ProbeBackoff.factor(id)` returns `this.entries.get(id)?.factor ?? 0`, so `factor(id) === 0` is
  exactly the old `backoffMap.get(id) === undefined`, and `factor(id) !== 0` is exactly the old
  `!== undefined` — a retained entry always carries `factor >= 1`. Both directions of every
  converted assertion are therefore faithful, including the inverted "backoff recorded" case in
  `dead-state.spec.ts`.
- `backoffOf(svc).clear(id)` reaches `ProbeBackoff.clear`, which is `entries.delete(id)` — the same
  effect the old `clearBackoff` cast had.
- `service-lifecycle.spec.ts`'s judgement call (the `stop()`-clears-state case) is sound:
  `factor()` returns 0 both for a never-recorded peer and after `clearAll()`, which is what that
  assertion means.
- The helper introduces no second cast: every converted site reaches `ProbeBackoff` through
  `backoffOf`'s public surface only.
- Docs edit in `docs/fret.md` (*Security and abuse considerations → Current state*) renames the
  "backoff map" to `ProbeBackoff` and notes its own clock. No behavior claim changed; the
