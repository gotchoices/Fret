## What landed

Test-only change to `packages/fret/test/rpc.handler-fuzz.spec.ts`. No production code
touched (`src/rpc/validate.ts` and `src/rpc/neighbors.ts` are read-only context for the new
tests, listed in `files:` above because the new rows assert against their behavior).

1. `interface Hooks` (~line 502) gained `lastAnnounce?: NeighborSnapshotV1` beside the
   existing `lastLeave?: LeaveNoticeV1`.
2. `registerAnnounceWithHooks`'s `onAnnounce` callback (~line 525, 3rd arg to
   `registerNeighbors`) now does `(_from, snap) => { h.served++; h.lastAnnounce = snap }`,
   so a test can inspect the normalized snapshot the handler actually served.
3. New `describe('announce snapshot field matrix', ...)` block (~line 767–965), inserted
   between the existing `leave notice field matrix` and `registerNeighbors' defaulted
   snapshotParser` describes. 26 rows:
   - **Reject rows** (`from` and `timestamp`, 12 rows total): unparseable string, empty
     string, wrong type (number/array/object), null, missing — for both fields. Each
     asserts `expectDropped` with `reasons: ['parse']` (the announce handler's cheap-guard
     rejection path, mirroring the existing leave-notice matrix pattern).
   - **Normalize rows** (`successors` / `predecessors`, 14 rows total, via a shared
     `succPredRows` factory): non-array variants (number/string/object/null), missing,
     array of non-strings, over the 16-entry cap, mixed valid/invalid entries, and a
     truncate-then-filter ordering check (a valid id placed past the cap slice must be
     dropped, not kept) — pinning `makeSnapshotParser`'s documented "truncate, then drop
     non-strings" order from `docs/fret.md`'s wire-shape-parsers table. Each asserts the
     message is served (not dropped) and the normalized `NeighborSnapshotV1` field via
     `expectSnapshot`.
