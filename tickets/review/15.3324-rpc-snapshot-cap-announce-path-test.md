## What the test does (unchanged from how the third run described it, still accurate)

- Replaces `handle` on an already-started real in-memory libp2p node with a recorder, then calls
  the private `registerRpcHandlers()` through a cast, to capture the actual handler function the
  service installs for `PROTOCOL_NEIGHBORS_ANNOUNCE` — as opposed to calling the merge/cap logic
  directly, which is what the *other* tests in `describe('announce snapshot merge caps')` do and
  is exactly the gap this ticket closes. A real node (not the module's `fakeNode()`) is required
  because `enforceCapacity` / `applyTouch` reach `selfCoord()` → `hashPeerId(this.node.peerId)`,
  and the stub has no `peerId`. `start()` is deliberately not called, so stabilization and the
  peerStore seed can't add their own upserts to the counter.
- Seeds the `FROM` peer into the store before installing the upsert counter, so the announce
  handler's detached `onInbound` → `noteInboundRpc(from)` short-circuits on its `if
  (!getById(id))` guard and doesn't add noise to the count.
- Wraps `mergeAnnounceSnapshot` on the instance to capture and await the promise
  `handleAnnounce` detaches, so the assertions run after the merge has actually finished. The
  snapshot itself still goes through the real wire parser.
- Invokes the captured `PROTOCOL_NEIGHBORS_ANNOUNCE` handler with a stub inbound stream carrying
  an over-cap snapshot body, and a connection whose `remotePeer` is `FROM` (must match the body's
  `from` field or the handler silently drops the message with no reply and the count would read
  as 0 with no indication why).
- Asserts the counted upserts equal `1 + successors + predecessors + sample` (matching the
  existing merge-cap arithmetic) and that the merged ids match expectation in order, and that
  nothing past each cap reached the store.

Reuses the block's existing fixtures unchanged (`FROM`, `OVER_SUCC`, `OVER_PRED`, `OVER_SAMPLE`,
`overCapBody()`, `countUpserts()`, `DrivableMerge`, the `profiles` table) plus the module-scope
`InboundHandler`, `inboundStub`, `json`, `P`. Nothing was hoisted to a wider scope in this run.
