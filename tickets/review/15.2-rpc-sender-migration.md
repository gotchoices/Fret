## What changed

- **Senders.** `sendPing`, `fetchNeighbors`, `sendMaybeAct`, and the write-only
  `announceNeighbors` / `sendLeave` are thin wrappers over `rpcRequest`, the one owner of
  open/write/read/close. Each returns `RpcOutcome<T>` — `ok {value, rttMs}` | `skipped` |
  `cancelled` | `timeout` | `unreachable {error}` | `foreign-protocol {error}` |
  `decode-error {error}` | `busy {retryAfterMs?}` — and never throws for a network outcome.
  Only caller bugs throw (malformed peer id; `if-addressed` without dialability), before any
  timer is armed.
- **Single clock.** All reads go through `readFramed` in `Infinity` mode, bounded by the RPC
  deadline alone. Stall → deterministic `timeout`; the deadline signal fires before the
  `finally` releases the stream, so the release arm is deterministically `abort()` on
  timeout/cancel and bounded `close()` otherwise. Classify order: cancelled → foreign-protocol →
  truncation/too-large → decode-error → deadline → timeout → unreachable. Zero bytes + clean
  EOF → `FrameTruncationError` → `decode-error`. Busy is tested on the parsed reply before
  `decode`.
- **Uniform scoring.** `noteRpcFailure` (`fret-service.ts:666`): `decode-error` →
  `applyFailure` (relevance decay only, no contact strike); `unreachable` / `timeout` →
  `applyContactFailure`. `probeNeighborLatency` (`fret-service.ts:1980–2020`) maps every
  variant explicitly; `cancelled` / `skipped` record nothing anywhere.
- **No fabricated snapshots.** `fetchNeighbors` no longer swallows errors into an empty
  snapshot; `fetchAndMergeSnapshot` returns early on `cancelled` / `skipped` and increments
  `snapshotsFetched` only on `ok`.
- **Tests.** `test/rpc.stream-errors.spec.ts` rewritten to drive reset-mid-stream,
  tidy-close-mid-JSON, and bytes-then-stall through every sender that can meet them, pinning
  release arm + count. New `describe('dead state: a run of answered-but-undecodable replies')`
  in `test/dead-state.spec.ts` pins that decodes failing repeatedly decay relevance but never
  mark the peer dead.
- **Docs.** `docs/fret.md` stabilization / stream-management / sender-agreement sections
  rewritten to match (busy-backoff behavior, deterministic release arm, `RpcOutcome` seam,
  write-only gap).

## Reviewer focus — known gaps and deliberate choices

- **`fetchNeighbors` decode is still shape-unvalidated** beyond `decodeJson`'s object check —
  parity with pre-migration behavior, kept deliberately; snapshot shape vetting lives in
  `makeSnapshotParser` at the merge site. Confirm nothing downstream assumes the decode
  validated more.
- **Write-only `ok` ≠ receipt.** `announceNeighbors` / `sendLeave` return `ok` right after the
  write with real `rttMs`; a write throw → `unreachable`. `openRpcStream` pins
  `negotiateFully: false` and this path never reads, so write-only can never observe
  `foreign-protocol`. Stated gap, parked with leave-authentication work.
- **Busy-backoff on the near pass is deliberate NEW behavior**: `probeNeighborLatency` on a
  `busy` reply records `recordBackoff` + `pingsSent` + `pingsFail`, no relevance decay, no
  contact strike. Previously busy was indistinguishable from other failures there. Docs state
  it as deliberate; verify the backoff map interaction (routing cost penalty, off-ring passes)
  reads sensibly.
- **`probeMembership` negative-pong parity choice**: an `ok` outcome whose parsed reply says
  `ok: false` is still treated as proof of life / membership evidence (peer answered our
  protocol), matching pre-migration semantics. Confirm that matches the evidence-strength table
  in docs.
- **`routeAct` / `iterativeLookup` group `skipped` with `cancelled`** in their outcome
  switches. `skipped` is unreachable today on those paths — `sendMaybeAct` dials
  (`dial: true`), so `openRpcStream` never yields no-stream — grouping keeps the switches
  exhaustive without inventing scoring for an unreachable case. If a future dial-mode change
  makes it reachable, the grouping silently treats "never contacted" as "cancelled" (records
  nothing), which is the safe default.
- **`sendLeave` in shutdown fan-out**: verify the `budget.signal.aborted` break conditions in
  the leave fan-out (preserved run 7) still short-circuit correctly now that `sendLeave`
  returns an outcome instead of throwing — `SHUTDOWN_BUDGET_MS` / `LEAVE_NOTICE_TIMEOUT_MS`
  unchanged.
- **`sendMaybeAct` uses `halfCloseBeforeRead: true`** — flush close precedes release, so
  non-abort read paths see `closes: 2`. Pinned in tests; confirm no consumer counts closes.
- Edge cases pinned by tests, worth spot-checking in review: `stop()` mid-flight records
  nothing at every call site; pooled-task `skipped` (pool status) is distinct from `RpcOutcome`
  `skipped`; tick-budget expiry behaves like `stop()`; caller signal checked before dial
  (`cancelled`, no dial); decode-callback throw → `decode-error` (or `cancelled` if caller
  signal fired); no read-modify-write over `PeerEntry` counters.
