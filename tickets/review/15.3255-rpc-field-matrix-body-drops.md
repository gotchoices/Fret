## What landed

### 1. A pull counter on the inbound stub

`inboundStub` (~line 122) gained `pulls: number`, incremented at the top of its async iterator's
`next()`. It exists so "the body was never pulled" is a *measurement* rather than an inference from
the absence of a crash — the same measure-do-not-infer rule `test/rpc.codec-properties.spec.ts`
applies to the codec's own byte cap.

### 2. Two helpers promoted one scope level (no behavior change)

Inside `describe('body-level drop hooks: onMalformed reason vs identity mismatch')`, the per-subject
`drive(chunks)` and `expectDropped(h, s, label)` moved out of the `for (const subject of subjects)`
loop and up to the parent describe. `drive` became a generic `driveWith(protocol, register, chunks)`;
the per-subject `drive` is now a one-line closure over it. The existing leave/announce subject rows
call exactly the same code they did before.

The `Hooks` record gained `lastLeave?: LeaveNoticeV1`, written by `registerLeaveWithHooks`'s
`onLeave`. `served` was only a counter, and the normalizing rows need to assert *what reached the
body*, not merely that it ran.

### 3. Leave notice field matrix — 24 rows, one `it` each

`describe('leave notice field matrix')`, a sibling of the existing subject describes. Table-driven;
each row states its own expectation because the three fields are not treated alike:

| Field | Wrong how | Expectation |
|---|---|---|
| `from` | unparseable string, empty string, number, array, object, `null`, missing | **reject** (7 rows) |
| `timestamp` | `'5'`, `'now'`, `true`, `null`, missing | **reject** (5 rows) |
| `replacements` | number, string, object, `null`, missing, `[]`, all-unparseable, non-string entries | **normalize** → key absent (8 rows) |
| `replacements` | 15 valid ids | **normalize** → first 12, in order |
| `replacements` | valid/invalid interleaved | **normalize** → only the parseable ids |
| `replacements` | 12 unparseable then 3 valid | **normalize** → key absent |

A *reject* row asserts: `{closes: 1, aborts: 0}` (the **arm**, not just the count), no reply written,
`onLeave` never ran, `onMalformed` reason is exactly `['parse']`, and zero identity mismatches.

A *normalize* row asserts: `{closes: 1, aborts: 0}`, no `onMalformed` reason, `onLeave` ran once, the
reply decodes to `{ok: true}`, `from` came through untouched, and either the `replacements` **key is
absent from the notice object** (`'replacements' in notice === false` — not present-and-empty; the
parser deletes it) or it equals the exact normalized list.

**The last row is the load-bearing one.** `sanitizeReplacements` slices to 12 and *then* filters, so
three parseable ids sitting past the cap are gone before the filter sees them and the result is
empty. Filter-then-slice would keep all three. Swap the two operations and only that row fails.

### 4. Frame-level abort arm — 2 rows

`describe('frame-level failures abort')`, a new top-level describe inside
`describe('RPC handler fault isolation')`. Body-level drops **close**; frame-level failures
**abort** — `registerJsonHandler` reads through `readFramed` and lets a framing throw propagate into
`registerRpcHandler`'s error arm.

- **Truncated frame** — a well-formed frame with the last 5 bytes cut off. The stub's source runs
  out mid-frame, `readFramed` sees `done` and raises `FrameTruncationError`. Asserts
  `{closes: 0, aborts: 1}`, no reply, `onLeave` never ran.
- **Over-cap frame** against `registerLeave`'s fixed 4096 — an 8192-byte body, handed to the stub
  as **two chunks split at the varint boundary** (`frame.subarray(0, prefixLen)` /
  `frame.subarray(prefixLen)`). In one chunk a single pull delivers both and the counter proves
  nothing. Asserts `{closes: 0, aborts: 1}` **and `pulls === 1`** — refused in `readFramed`'s
  `onLength` hook the moment the prefix decodes, body never pulled.

## Use cases a reviewer should exercise

- **Break the parser and watch the right row fail.** In `src/rpc/validate.ts`:
  - Swap `sanitizeReplacements`' slice and filter → only *"replacements: valid entries sitting past
    the slice"* fails. That is the row's whole job.
  - Make `parseLeaveNotice` return `out` with `replacements: []` instead of deleting the key → all
    eight absent-key rows fail on `'replacements' in notice`.
  - Coerce `timestamp` with `Number(...)` → *"timestamp: numeric string"* fails alone.
- **Break the seam and watch the arm flip.** Make `registerRpcHandler`'s error arm `close()` instead
  of `abort()` → both frame-level rows fail on the arm, and nothing else in the file does. Make a
  body-level drop abort → all 12 reject rows fail. This is why the rows assert
  `{closes, aborts}` as a pair rather than a release count.
- **Check `pulls === 1` is not accidental.** Merge the two chunks in the over-cap row into one and
  the assertion should read 1 for the wrong reason (one pull delivered everything). That is the
  trap the split exists to avoid — confirm the split is still there.

## Known gaps — treat this as a floor

- **The frame-level arm is exercised on leave only.** Leave was chosen because its 4096 cap is fixed
  inside `registerLeave` and needs no plumbing. The maybeAct (512 KB Core / 256 KB Edge) and
  neighbors (128 KB Core / 64 KB Edge) caps have no frame-level row here, and neither does the
  service-tier disagreement documented in `docs/fret.md` (wire admits 512 KB, `handleMaybeAct`
  refuses activity over a fixed 128 KB) — that one is `15.4-rpc-byte-cap-tightening`'s subject.
- **`pulls === 1` pins current `it-length-prefixed` behavior.** It holds because `lp.decode` pulls
  whole chunks and the `onLength` hook throws before requesting another. If a future `lp` version
  pulls at byte granularity the row would fail on a still-correct implementation. That is the price
  of measuring instead of inferring, and the comment at the site says so.
- **No wire-tier row was added,** so the `MatrixRow.counts` constraint from the earlier ticket never
  came into play. Everything new here is unit tier (stub streams, `fakeNode`). The wire tier still
  covers leave's drops through `malformedMatrix()` — the two tiers overlap on `from`-absent and
  `from`-unparseable and that duplication is deliberate (different seam, different assertion).
- **`v` is unchecked and deliberately has no row.** Nothing negotiates versions; a row asserting it
  rejects would pin behavior the design says must not exist.
- **The announce snapshot half is not here** — sibling ticket `rpc-snapshot-field-matrix`. Service-
  tier cap counting is `rpc-snapshot-cap-merge-tests`. Both edit this same spec file, so expect
  merge conflicts if they land out of order.
- **Rig promotion is untested in isolation.** `driveWith` / `expectDropped` moving up a scope is
  covered only by the existing subject rows continuing to pass. That is adequate evidence, but it is
  regression coverage, not a test of the refactor.
