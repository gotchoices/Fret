## Open question for the finishing run

None of the three rigs tear down if an assertion or a `waitFor` gate throws part-way: each calls
`mesh.stop()` as its last statement, and the describe block has no `afterEach`. A rig that times
out therefore leaves its libp2p nodes running, and the mocha exit watchdog fires a second,
unrelated-looking failure on top of the real one.

This is **pre-existing** — the hand-rolled rigs had the identical shape, and the migration neither
caused nor worsened it. It is called out here only because this file already carries a comment
worrying about exactly this scenario ("once reported failing at the 20s budget inside a full-suite
run"), so a leaked-handle dump masking the real stall would be costly here specifically.

The finishing run should pick one and say which in its findings:

- **Fix inline** — hoist a `let mesh: Mesh | undefined` per test plus one `afterEach`. Needs care:
  the two `skip`-using rigs would have to record which index was already stopped, and the existing
  explicit `mesh.stop()` calls must not double-stop (clear the variable after them, or drop them
  and let `afterEach` own teardown).
- **Leave it and record it as a tripwire** — a `NOTE:` at the describe block saying teardown is
  end-of-test only, so a rig that throws leaks its nodes and the watchdog dump is a consequence of
  the first failure rather than a second bug.

Either is defensible; the second is honest and cheap, the first is a real diagnosability gain on a
file that has already been flaky once. Do not file it as a separate ticket — it resolves at one
site and belongs in this pass.
