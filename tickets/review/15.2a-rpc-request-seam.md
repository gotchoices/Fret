## What landed

**`src/rpc/outcome.ts`** — `RpcOutcome<T>`, a discriminated union with one variant per outbound
failure mode: `ok` / `skipped` / `cancelled` / `timeout` / `unreachable` / `foreign-protocol` /
`decode-error` / `busy`. Each variant's doc comment states *what it proves about the peer*,
because that is what the service branches on: a contact strike belongs only to variants proving
the peer unreachable, never to ones proving it alive. This is the type that ends the divergence
documented in `docs/fret.md` (today ping returns `ok: false`, `fetchNeighbors` fabricates an
empty snapshot and `sendMaybeAct` throws — for identical evidence).

**`src/rpc/request.ts`** — `rpcRequest(node, peer, protocol, opts)`, the single owner of the
open / write / read / release sequence, composing the four pinned primitives (`openRpcStream`,
`sendFramed`, `readFramed`, `releaseRpcStream`). Contract:

- **Never throws for a network outcome.** It throws only for a caller bug — a malformed peer id,
  or `dial: 'if-addressed'` with no `isDialable` — and both checks sit *before* `deadline()`, so
  a throw leaves no timer to cancel.
- **One clock.** The helper's deadline is a child of the caller's signal, and `readFramed` runs
  in its `Infinity` mode with that deadline as the sole signal. This is what makes the release
  arm deterministic (see the release table below).
- **Classification order** on any transport failure (open / write / read), all through one shared
  `classify`: caller's signal aborted → `cancelled`; `isUnsupportedProtocolError` →
  `foreign-protocol`; `isFrameTruncationError` or a message starting `payload too large` →
  `decode-error`; deadline signal aborted or `DeadlineExpiredError` → `timeout`; else
  `unreachable`. The decode phase has its own classifier (`decodeFailure`) so a validator's throw
  can never be dressed as a timeout, with the caller-signal check still first.
- **Deferred negotiate failures.** `openRpcStream` pins `negotiateFully: false`, so an
  `UnsupportedProtocolError` surfaces at the *first read*, not at the open. `classify` is shared
  across phases specifically so that case still yields `foreign-protocol` — a per-phase mapping
  would have booked a contact strike for membership evidence.
- **Backpressure is honored.** `sendFramed`'s boolean is no longer ignored: a `false` is followed
  by a drain wait bounded by the deadline signal, which re-checks `writableNeedsDrain` after each
  `'drain'` event. A stream with no backpressure surface skips the wait entirely.
- **Busy short-circuits the validator.** `decodeReply` parses with `decodeJson`, tests the busy
  shape on the parsed value, and only then calls `opts.decode(bytes)` — so `decode` never sees a
  busy reply. `decode` still receives the raw bytes, so a validator that parses again is an
  accepted double parse of a small framed message.

**Exports** — `rpcRequest`, `RpcRequestOptions`, `RpcOutcome` re-exported from `src/index.ts`
under the extended seam comment; `test/package-exports.spec.ts` pins all three at runtime and

**Docs** — `sendFramed`'s doc comment in `src/rpc/protocols.ts` now says the boolean is honored

## Test inventory (all 31 passing)

**Failure shapes → variants.** reset mid-stream → `unreachable` (error surfaced); tidy close
mid-JSON → `decode-error`; EOF before any bytes → `decode-error` (proof of life — generalizes
`sendPing`'s no-strike behavior); empty frame (prefix `0x00`) → `decode-error` / `empty
response`; framed `[1,2,3]` → `decode-error` / `non-object JSON payload`; declared length over
`maxBytes` → `decode-error` / `payload too large…`; bytes then silence → `timeout`, elapsed
asserted in `[80, 1000]` ms against a 100 ms budget; `UnsupportedProtocolError` at the open →
`foreign-protocol`; the same error **surfacing at the read** → `foreign-protocol`, not
`unreachable`; framed `{busy: true, retry_after_ms: 500}` → `busy` with `retryAfterMs === 500`
and a decode callback that counts its own invocations proving it never ran; a decode callback
that throws on a good frame → `decode-error`, stream released; a whole framed reply → `ok` with
the decoded value and `rttMs >= 0`; `halfCloseBeforeRead: true` on the ok path → `closes: 2`.

**Cancellation vs timeout.** Signal aborted before the call → `cancelled` with the counting
node's `getConnections`/`newStream`/`dialProtocol` all still at 0; abort during the open (against
a signal-honoring never-resolving `newStream`) → `cancelled`; abort during the read (via the
stub's `onNext` hook, call 2) → `cancelled`; budget expiry with a live caller signal → `timeout`,
and the caller's signal asserted still un-aborted; an open that expires on the budget → `timeout`.

**Release exactly once, arm pinned.** `expectRelease` deep-equals `{closes, aborts}` rather than
summing them — deterministic here because the single clock removes the two-timer race that forces
`rpc.stream-errors.spec.ts` to assert only the count. Observed table:
`ok`/`busy`/`decode-error`/`unreachable`/`foreign-protocol`-at-read → `{closes: 1, aborts: 0}`;
`timeout`/abort-during-read → `{closes: 0, aborts: 1}`; `halfCloseBeforeRead` adds one flush close
on both the read and the write-only paths.

**Dial modes.** `'never'` + no connection → `skipped`, `dialProtocol` and `newStream` both 0;
`'if-addressed'` + `isDialable` false + no connection → `skipped`, and `isDialable` asserted to
have been asked about exactly the peer under call; `'if-addressed'` + `isDialable` false + an
**existing connection** → proceeds to `ok` via `newStream`, `dialProtocol` 0; `'always'` + no
connection → `dialProtocol` called once; `'if-addressed'` without `isDialable` → throws, with
`getConnections` still 0 (the throw precedes any contact); malformed peer string → rejects.

**Backpressure.** Never drains → `timeout` inside the budget (not a hang), released via `abort`;
a drain that clears the flag → `ok`; a drain that does *not* clear it followed by one that does →
still `ok` (pins the re-check loop); a stub with `send() → false` but no `writableNeedsDrain` /
event surface → the wait is skipped entirely, asserted by elapsed `< 80 ms`. Every drain case also
asserts the stub has **zero** live `'drain'` listeners afterwards, including the abort arm — that
was listed as a reviewer probe and is now pinned instead.

**Write-only** (`decode` absent). `ok` with `value === undefined`, `sends === 1`, `delivered === 0`;
`halfCloseBeforeRead` still flushes (`closes: 2`); a `send()` that throws → `unreachable`, released
once.

**Hygiene.** A describe-scoped `unhandledRejection` hook (registered on the describe, not at file
top level, so it is not a root hook) fails any case that leaks a rejection; scheduled drain timers
are tracked and cleared in `afterEach` so nothing can trip the exit watchdog.

## Deviations from the ticket, stated

- **The ticket's release table was wrong about `cancelled`, in two directions.** It said
  `cancelled → {closes: 0, aborts: 1}`, and the core ticket's follow-up note corrected only the
  pre-call case. Actual behavior, now asserted per case: a signal aborted *before* the call returns
  `cancelled` having opened nothing → `{0, 0}`; an abort *during the open* leaves `openRpcStream`
  throwing, so **no stream exists to release at all** — that case asserts `newStream === 1` instead
  of release counters; only an abort *during the read* gives `{0, 1}`.
- **Two cases added** beyond the ticket's list, both implied by the landed code: an open that
  expires on the deadline → `timeout`, and `halfCloseBeforeRead` on the write-only path → `closes: 2`.

## Known gaps — please probe these

- **No real-transport case.** Everything is a stub. In particular the stub's `close()` ignores the
  `{signal}` it is handed, so `releaseRpcStream`'s "bounded close rejected → fall through to
  `abort()`" arm is never taken here. That arm is covered directly in `rpc.protocols.spec.ts`, but
  not *through* `rpcRequest`.
- **`skipped` release counters are not asserted.** No stream exists on that path so there is nothing
  to count, but the ticket listed `skipped → {0, 0}` as a row and it is only true vacuously.
- **`classify`'s `payload too large` check is a message-prefix match**, so an error whose message a
  remote can influence could in principle be misfiled as `decode-error`. Worth a look at whether any
  reachable error identity collides — `isFrameTruncationError` and `isUnsupportedProtocolError` match
  on `name` and are safe, this one does not.
- **The 64 KiB `maxBytes` default is untested.** Every case passes an explicit cap or relies on the
  default without exercising its boundary.
- **`busy` with a missing or non-numeric `retry_after_ms`** (→ `retryAfterMs: undefined`) is untested;
  only the well-formed 500 ms case is.
- **No concurrency case.** Two `rpcRequest` calls in flight over one node are never driven.
- **Case-by-case, not property-based.** Unlike `rpc.codec-properties.spec.ts` / `nexthop-cost.spec.ts`,
  there is no generator here. If the review wants the classification table proved over arbitrary error
  identities rather than the eight hand-picked ones, that is a `debt-` ticket, not an inline fix.
