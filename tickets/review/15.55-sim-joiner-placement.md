## Root cause (fixed)

`uniformCoord` divided by `this.nextPeerIndex`, which `handleJoin()` incremented *before*
placing (`const index = this.nextPeerIndex++`) — so each joiner's coordinate divided by its own
post-increment index instead of the population it should spread across, landing at fraction
`index / (index + 1)` of the ring and packing tighter as the run went on. `initialize()` was
unaffected since `nextPeerIndex` was fixed at `config.n` there.

Fix (already committed in an earlier commit on this ticket's chain, `packages/fret/test/simulation/fret-sim.ts`):
- `addPeer(index, isJoin = false)` — new `isJoin` param branches placement.
- `generateCoord` — initial population still uses `uniformCoord(index, population)`; a mid-run
  joiner now gets `randomCoord()`, a seeded random ring coordinate (`deterministic-rng.ts`)
  instead of index arithmetic.

## What this run added

**Calibration test**, `packages/fret/test/churn-scenarios.spec.ts` — new `it('uniform placement
keeps joiners spread across the ring', ...)`, last test in the `describe` block:
- Deterministic sim (seed 8008, n=40, k=15, m=8, batch-joins 10 peers at t=3000ms, 10s run).
- Measures largest gap between adjacent alive-peer coordinates on the ring vs. the uniform
  (population-even) spacing; fails if the ratio exceeds a threshold.
- Threshold calibrated from 3 seeds: 8008 → 5.00x, 8009 → 2.81x, 8010 → 3.65x. Final threshold
  is **10x** (2x headroom over the worst observed), seed fixed at 8008 for determinism.
- Helper `coordToBigInt` (inverse of `bigintToCoord`) added at module scope after the `describe`
  block.
