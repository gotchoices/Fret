## Confirmed finding — fix it in this pass

**`SizeEstimateOptions.selfCoord` and `selfId` are two independent optional fields that are only
meaningful as a pair.** `collectGaps` passes `selfId ?? ''`; an empty string matches no peer id, so
the helper's `drop` predicate never fires, each side returns `[self, s1..s(m−1)]`, and the window
silently loses one gap per side — G = 2m − 2 = 14 at the default m instead of 16, with confidence
0.8664 instead of 0.875. It is a quiet numeric degradation, not an error, and
`SizeEstimateOptions` is exported from the package root (`src/index.ts:142`), so an external caller
can reach the half-specified state.

Architecture ladder, rung 1 (types/representation): pair them into one optional field so the
half-specified anchor is unrepresentable and the `?? ''` fallback retires with it. Sketch:

```ts
export interface SizeEstimateOptions {
	filter?: (e: PeerEntry) => boolean;
	/** Local node's ring position *and* id. Supplying it selects the S/P-window method. */
	self?: { coord: Uint8Array; id: string };
}
```

## Remaining minor findings — fix inline

- **DRY, four sites.** `this.node.peerId.toString()` is recomputed inside the estimator options bag

- **Redundant self in `exclude`.** `announceNeighborsBounded` builds `exclude = new Set([selfId])`

  inflated by one slot. Same double-count on the departure path, where the set is
  `{self, departedId}`. Harmless numerically, but it invites a reader to believe the helper does not
  drop self. Drop self from those sets and say so in a comment at the helper call.
