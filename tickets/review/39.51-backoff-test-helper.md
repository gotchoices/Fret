## What landed

1. **New file `packages/fret/test/helpers/backoff.ts`**: two small accessors,
   `backoffOf(svc)` / `setBackoffOf(svc, pb)`, that reach a `FretService`'s private `backoff`
   field (`ProbeBackoff`) via a test-only cast — `setBackoffOf` exists because the field is
   `readonly` in production, letting a spec install a fake-clock instance. `ProbeBackoff` is
   imported with `import type` (repo uses `verbatimModuleSyntax`).

2. **`ring-membership.spec.ts`**: deleted the whole `describe('Foreign re-probe backoff growth', ...)`
   block (5 `it`s: window-grows-on-repeat, caps-at-32-and-prunes, survives-expired-window,
   resets-after-retention, `BACKOFF_RETAIN_MS > base*maxFactor` invariant). That block exercised
   an older `backoffMap`/`recordBackoff`/`getBackoffPenalty`/`pruneBackoffMap` surface on
   `CoreFretService` directly; `probe-backoff.spec.ts` already covers the same behaviours through
   the current `ProbeBackoff` class (escalation doubling, cap-at-maxFactor, closed-window-vs-
   forgotten-entry, retention expiry, and a `BACKOFF_RETAIN_MS` invariant case of its own —
   "shipped defaults"). Removing this also dropped the file's only use of `ExpiringMap`, so that
   import was deleted too (verified via grep — no other reference in the file).

3. **`probe-backoff.spec.ts`**: two new cases —
   - `'two failures inside one still-open window both escalate'` (in the `escalation` describe,
     after the doubling test): two `record('a')` calls with no `clock.advance` between them —
     pins that a second failure landing inside the first window's still escalates the factor
     (1 → 2) and pushes `until` out further, not just that factor climbs on separate windows.
   - Follow-up assertion appended inside `'clear forgets one peer and leaves the others'`
     (`forgetting` describe): after `clear('a')`, a fresh `record('a')` restarts at factor 1 —
     pins that `clear()` truly forgets the peer rather than leaving it retained at 0 (mirrors the
     retention-expiry shape already covered elsewhere in the file).
