## Findings recorded so far — disposition still open

None of these were acted on; the finishing run should decide and act.

**1. Cache-warming is an unstated side effect of change (b).** Two sites read
`this.cachedSelfCoord` *nullably* and degrade when it is unset: `isNearNeighbor` (~1732) returns
`false` outright, and `getNetworkSizeEstimate` (~2821) falls through to the estimator's
whole-store path, which `docs/fret.md` documents as a one-to-two-order-of-magnitude degradation.
Routing five former `hashPeerId(this.node.peerId)` call sites through `selfCoord()` populates that
cache strictly *earlier* in a service's life, so both sites now degrade in strictly fewer
situations. That is an improvement, not a defect — but it is a behaviour change the ticket does
not mention and no test covers. Suggested disposition: a tripwire `NOTE:` at `selfCoord()` saying
the cache is load-bearing for those two nullable readers, rather than a ticket.

**2. A `stabilizeOnce` throw before its `enforceCapacity()` leaves that tick's seeds untrimmed.**
The loop tick body is `seedFromPeerStore()` → `seedFromBootstraps()` → `stabilizeOnce()`, and the
seeds no longer trim for themselves. Anything that throws inside `stabilizeOnce` ahead of the
enforcement — realistically only `sweepBoundedMaps()` or `nearProbeTargets()` — is caught by the
tick's own `try/catch`, so the table keeps one tick's worth of overshoot. Self-heals on the next
tick unless the throw is deterministic. Judged narrow; suggested disposition is a tripwire, but
the finishing run should confirm neither of those two calls can throw on a reachable input before
settling on that.

**3. `coordOf` (`fret-service.ts` ~565) is open-coded twice.** The new reuse line at ~1897 is
`this.store.getById(pidStr)?.coord ?? (await hashPeerId(p.id))` — same shape as `coordOf`, but
deliberately hashing the `PeerId` object it already holds rather than re-parsing the id string,
which matters on the hot path this ticket exists to trim. A pre-existing second copy sits at
~3169 and *is* byte-identical to `coordOf`. Minor. Suggested disposition: leave ~1897 alone but
say why in one clause at the site; the ~3169 duplicate is outside this diff and is at most a
one-line inline fix.
