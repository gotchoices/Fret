### `parseLeaveNotice` per field — reject vs normalize (verified against the current file)

A reject drops the whole message: seam closes, no reply written, `onLeave` never runs.

- `from` — must satisfy `isPeerIdString` (a `peerIdFromString` try/catch). Wrong type, missing, or
  unparseable → **reject**.
- `timestamp` — must be a finite `number`; no coercion, so `'5'`, `null` and missing all
  **reject**.
- `replacements` — `sanitizeReplacements`: any non-array (including missing) or an empty array →
  `undefined`, i.e. the key is *deleted* from the notice rather than present-and-empty. Otherwise
  `slice(0, 12)` **then** a per-entry `isPeerIdString` filter; an all-invalid result is also
  `undefined`. **Normalizes — the message still answers `{ok: true}`.**
- `v` is deliberately unchecked. Do not add a case asserting it rejects.

So the matrix's columns are not uniform: "over cap" is meaningful only for `replacements`, and
"missing" collapses into "wrong type" for both rejecting fields. Write the table so each row states
its own expectation (`reject`, or `normalize-to <value>`) rather than assuming one shape per column.

### Frame-level arm (the aborts) — two facts that decide how the cases are written

Body-level drops **close**; frame-level failures **abort**. `registerJsonHandler` calls
`readFramed(stream, opts.maxBytes)` with the *default* 5s timeout and no signal, and lets the
throw propagate into `registerRpcHandler`'s error arm.

1. **Truncated frame** — a length prefix promising more bytes than follow. The stub's iterator
   simply runs out, `readFramed` sees `result.done === true` and raises `FrameTruncationError`
   (already imported by the spec). `remoteFinishedWriting(stream)` reads `readBufferLength` /
   `remoteWriteStatus` / `readStatus`, none of which `inboundStub` defines, so it returns false and
   the EOF poll never fires — nothing extra is needed on the stub for this case.
2. **Over-cap frame against the fixed 4096** — refused in `readFramed`'s `onLength` hook the moment
   the varint prefix decodes, so it must abort **and the body must never be pulled**.
   **`lp.decode` pulls whole chunks, so the prefix and the body must be handed to `inboundStub` as
   two separate chunks** — encode the frame, split it at the varint boundary, and pass
   `[prefix, body]`. In one chunk a single pull delivers both and the counter proves nothing.
   With the split, the assertion is `pulls === 1`.
   `inboundStub` has no pull counter today: add one (increment inside the async iterator's
   `next()`, expose as `pulls`) so "never pulled" is *measured*, the same measure-do-not-infer rule
   `test/rpc.codec-properties.spec.ts` applies to the codec.

## Tests to add

- **Leave notice, per field, per way of being wrong** (`from`, `timestamp`, `replacements`): wrong
  type, missing, and — for `replacements` — over cap. Each message must be dropped without throwing
  out of the handler and without leaking the stream, and the release-exactly-once invariant must
  hold. **Assert the arm, not merely the release count** — `close` on a body-level drop. The count
  alone passes for both arms and so proves nothing about the rule.
  - A *rejecting* field (`from`, `timestamp`) drops the whole message with no reply and never runs
    `onLeave`. A *normalizing* field (`replacements`) still answers `{ok: true}` with the field
    neutralized — assert **what reached `onLeave`** (key absent for the empty / all-invalid /
    non-array cases; exactly 12 entries for an over-cap list; only the parseable ids for a mixed
    list), not just the release arm.
- **Frame-level abort arm:** a truncated frame, and an over-cap frame against the fixed 4096-byte
  cap. Both abort. The over-cap case additionally asserts `pulls === 1` per the split-chunk rule
  above.
