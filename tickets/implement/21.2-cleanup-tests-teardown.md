Split off `plan/21-cleanup-tests.md` — arm 2 of 4.

Today most multi-node specs call `stopAll(nodes)` (or `Promise.all(services.map(s => s.stop()))`)
on the last line of the test body, outside any `try`/`finally` and outside an `afterEach`. A
failing assertion earlier in the body therefore skips teardown entirely: the libp2p nodes and
their stabilization timers stay live, and the mocha exit watchdog
(`test/mocha-exit-watchdog.ts`, wired via `packages/fret/.mocharc.json`) then fails the run a
*second* time with an open-handle dump — burying the original assertion failure the developer
actually needs to see.

Measured by grepping for spec files calling `stopAll` (or manual multi-`.stop()` teardown) with no
`afterEach` anywhere in the file: `maybeact-dedup-phases.spec.ts` (7 teardown call sites),
`proactive-announce.spec.ts` (5), `network.isolation.spec.ts` (3),
`route.maybeact.integration.spec.ts` (2), `profile.behavior.spec.ts` (at least 1). Re-grep at
implementation time — this ticket was scoped from the plan-stage review's count and line numbers
may have drifted since.

Also note: several of these teardown a service list via
`await Promise.all(services.map(s => s.stop()))`. If one `stop()` call rejects, `Promise.all`
short-circuits and every other service (and the libp2p nodes underneath them) is stranded
un-stopped. Prefer `Promise.allSettled` (or the shared helper below) so one failing stop doesn't
strand its siblings.

## Design (resolved)
Build a shared `withMesh(n, fn)`-shaped helper — depends on the consolidated mesh-setup factory
landing in `21.1-cleanup-tests-core` first, hence the prereq — that owns both setup *and*
teardown: it builds the mesh, runs the test body, and guarantees teardown via `finally` (or by
being invoked from within a helper that itself wraps the call in `try/finally`) regardless of
whether the body throws. This is preferred over asking each spec to remember its own
`try/finally`, because a shared helper makes the leak structurally unwritable — a spec author
can't forget it if the helper owns it.

Reference: `test/iterative-lookup.spec.ts` and `test/fret.mesh.spec.ts` already do this by hand
(fixed during the `lookup-profile-test-assertions` review) — read those two for the pattern this
ticket generalizes into a reusable helper.

## Edge cases & interactions
- A test that intentionally stops a node mid-test (e.g. churn/leave specs simulating a peer
  departure) must still work under the new helper — the helper's teardown must be idempotent
  against nodes already stopped, not double-stop and throw.
- `Promise.allSettled` migration: if any settled result is a rejection, still surface it somehow
  (log it) rather than silently swallowing — the point is "don't strand siblings," not "hide
  failures."
- Confirm the mocha exit watchdog (`FRET_TEST_EXIT_GRACE_MS`, 10s default) no longer fires on any
  of the five touched files when a test is made to fail deliberately (temporarily break an
  assertion, run the file, confirm only the real assertion error appears — no open-handle dump —
  then revert the deliberate break).
- `profile.behavior.spec.ts` has only ~1 site per the count above — verify it actually needs the
  shared helper or whether it's simple enough to fix with a plain `afterEach`; don't force every
  file onto the heavier helper if a lighter fix is equally correct there.
