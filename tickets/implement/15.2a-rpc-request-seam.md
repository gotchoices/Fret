## Why (condensed from the plan ticket — do not re-derive)

Five outbound senders hand-roll the same open / write / read / close sequence with four
disagreeing failure contracts:

| sender | reply undecodable / empty | unreachable | busy | site |
|---|---|---|---|---|
| `sendPing` | `{ ok: false }`, no strike | throws | `{ ok: false }` | `ping.ts:88-129` |
| `fetchNeighbors` | fabricated empty snapshot | fabricated empty snapshot | fabricated empty snapshot | `neighbors.ts:81-112` |
| `sendMaybeAct` | throws — service books a contact strike | throws | returns the busy object | `maybe-act.ts:91-110` |
| `announceNeighbors` | n/a (write-only) | logs and swallows | n/a | `neighbors.ts:120-149` |
| `sendLeave` | n/a (write-only) | throws | n/a | `leave.ts:75-92` |

The consequence that matters most: `noteRpcFailure` (`fret-service.ts:669-680`) splits membership
evidence from unreachability by sniffing the error with `isUnsupportedProtocolError`, and every
other throw becomes a contact strike. `sendMaybeAct` lets `decodeJson`'s plain `Error`s propagate,
so a peer that opened a stream and merely *replied badly* is counted unreachable — three such
replies mark it `dead`. The ping path classifies identical evidence the other way.

## What lands here

### `RpcOutcome<T>` — one discriminated union (`src/rpc/outcome.ts`)

```ts
/** Why an outbound RPC ended. Exactly one variant per FRET failure mode; the service branches
 *  on `kind` rather than sniffing an error. */
export type RpcOutcome<T> =
	| { kind: 'ok'; value: T; rttMs: number }
	| { kind: 'skipped' }
	| { kind: 'cancelled' }
	| { kind: 'timeout' }
	| { kind: 'unreachable'; error: Error }
	| { kind: 'foreign-protocol'; error: Error }
	| { kind: 'decode-error'; error: Error }
	| { kind: 'busy'; retryAfterMs?: number };
```

Meaning of each, stated once so the migration ticket has nothing to invent:

- **`ok`** — a whole framed reply arrived, decoded and (where a validator was supplied) validated.
  `rttMs` is measured from *after* the stream open, never including the dial, matching today's
  `sendPing`. For a **write-only** RPC (`announceNeighbors`, `sendLeave`) `value` is `undefined`
  and `ok` means *the body reached the transport*, explicitly **not** proof the peer received or
  accepted it. Say that in the doc comment — it is the whole reason a rate-limited leave is
  invisible today.
- **`skipped`** — nothing was attempted: the dial mode forbade dialing and no connection existed.
  Distinct from `ok` with an empty payload; separating them is what ends the `snapshotsFetched`
  overcount `NOTE:`d at `fetchAndMergeSnapshot`.
- **`cancelled`** — the **caller's** signal aborted. See the discriminator rule below.
- **`timeout`** — our own budget expired and the caller's signal did *not*. Evidence about the
  peer (a contact strike), unlike `cancelled`.
- **`unreachable`** — dial, stream-open, reset or transport failure. Contact strike.
- **`foreign-protocol`** — `isUnsupportedProtocolError(err)`. Membership evidence, never a strike.
- **`decode-error`** — the peer opened a stream and answered, but the answer was truncated, empty,
  non-JSON, a non-object top level, over the byte cap, or rejected by the validator. **Proof of
  life; never a contact strike.** This is the variant that retires the `sendMaybeAct` misclass.
- **`busy`** — the reply was a `BusyResponseV1`. `retryAfterMs` carries `retry_after_ms` when present.

**`cancelled` is a variant, and the helper owns the call.** `rpcRequest` holds both signals — it
builds its deadline as a child of the caller's — so it is the one site with the discriminating
fact, exactly the reasoning `wasCancelled` already documents at `fret-service.ts:704`. Rule: on any
failure the helper checks the *caller's* signal first; aborted → `cancelled`, else classify. The
service's `wasCancelled` stays for paths that do not go through the helper, and callers must
**not** re-derive cancellation from a helper result — the variant wins.
*Rejected:* leaving cancellation a caller-side check only. The write-only senders swallow their
errors today, so the caller has nothing to check (`sendAnnouncementsRateLimited`'s comment at
`fret-service.ts:1300-1320` says exactly this); and two places agreeing on one fact is how the
divergence in the table above happened.

### `rpcRequest` — the single owner of open / write / read / close (`src/rpc/request.ts`)

```ts
export interface RpcRequestOptions<T> {
	/** Whole-RPC budget: dial + open + write + read + close. Defaults to RPC_TIMEOUT_MS. */
	timeoutMs?: number;
	/** Caller's cancellation. The helper's deadline is a child of it. */
	signal?: AbortSignal;
	/** When may we dial? Replaces the `requireExisting` boolean at the call site. */
	dial?: 'never' | 'if-addressed' | 'always';
	/** Required for `dial: 'if-addressed'`; false → `{ kind: 'skipped' }` with no dial. */
	isDialable?: (peerIdStr: string) => boolean;
	/** Declared-length cap for the reply, per protocol. */
	maxBytes?: number;
	/** Body to write. Omit for a read-only request (the neighbors fetch). */
	body?: unknown;
	/** Absent → write-only: no reply is read and `ok.value` is `undefined`. */
	decode?: (bytes: Uint8Array) => T | Promise<T>;
	/** Half-close our write end before reading (the maybeAct flush). Default false. */
	halfCloseBeforeRead?: boolean;
}

export async function rpcRequest<T = undefined>(
	node: Libp2p, peer: string, protocol: string, opts?: RpcRequestOptions<T>
): Promise<RpcOutcome<T>>;
```

`rpcRequest` **never throws** for a network outcome — every failure becomes a variant. It may
still throw for a caller bug (a malformed peer id from `peerIdFromString`, `dial: 'if-addressed'`
with no `isDialable`); those are programming errors, not peer evidence, and must not be dressed
as `unreachable`.

**Generic with a `decode` callback, not raw bytes.** `15.3-rpc-message-validators` plugs its
per-message validator in as this callback; a validator rejection maps to `decode-error` in one
place.
*Rejected:* returning raw bytes for the caller to decode — every caller then re-implements the
same try/catch → `decode-error` mapping, which is the duplication this ticket exists to remove.

**Dial mode is explicit, replacing the `requireExisting` boolean at the call site.**
`'never'` = today's `requireExisting: true`; `'always'` = today's default; `'if-addressed'` is
new and is what stops the `NoValidAddressesError` class returning after
`4-dialability-guard-on-outbound-rpc` fixed today's instances. `openRpcStream`'s own signature is
**unchanged** — `rpcRequest` maps mode → boolean and applies `isDialable` itself.
*Rejected:* moving the mode into `openRpcStream`. That is a public pinned export
(`test/package-exports.spec.ts`), and the dialability fact lives on the service, not in `src/rpc/`.

### Backpressure (the one `protocols.ts` touch left in this ticket)

`sendFramed` returns `stream.send`'s boolean (`protocols.ts:151-160`, whose comment defers
backpressure to this ticket) and no sender reads it. `rpcRequest` reads it: on `false`, await the
stream's `drain` event, **bounded by the deadline signal** — expiry → `timeout`, caller's signal →
`cancelled`. Recovery surface is `writableNeedsDrain` plus `drain` (`@libp2p/interface`
`message-stream.d.ts:116,127,134`). Re-check `writableNeedsDrain` after the await rather than
assuming one `drain` clears it. Update `sendFramed`'s comment (it names this ticket's plan
ancestor as the owner of the deferral).

### Deliberately NOT in this ticket

- **The three primitive changes** — landed by `15.1-rpc-request-primitives` (prereq). `rpcRequest`
  passes `Infinity` to `readFramed` with its deadline signal so exactly one clock governs the read.
- **Iterator priming.** `readFramed`'s `EOF_POLL_MS` `NOTE:` (`protocols.ts:196-204`) says priming
  the reply iterator before the write is the durable fix for the lost-close-event case, and that
  the 20 ms poll is a floor under measured ping RTT. Priming requires splitting `readFramed` into
  "start reading" + "await frame" and threading a live iterator through a pinned public export —
  an API change for a 20 ms floor that only bites the lost-event case. **Keep the poll; do not
  prime.** The existing `NOTE:` at the constant already records the condition, so this is a
  tripwire already parked at its code site — do not file a ticket for it, and do not delete or
  weaken that NOTE.
- **Leave reporting busy.** `handleLeave` takes the rate-limit token but `registerLeave` has
  already committed to `{ok: true}` (docs/fret.md, *Leave*), so a dropped leave is invisible on the
  wire. Making `sendLeave` report `busy` means making it *read* a reply — a round trip added inside
  `SHUTDOWN_BUDGET_MS`, plus a wire-behavior change on the receive side. That belongs with the
  leave authentication / dedup work, not here. `RpcOutcome` makes it expressible; nothing in this
  ticket or `15.2b` makes it happen. **Update docs/fret.md's *Leave* paragraph** so it stops
  promising `15-rpc-shared-helper` will retire it and states the parking instead.

## Edge cases & interactions

- **An already-aborted caller signal must yield `cancelled` with no dial issued.** `deadline()`
  returns a synchronously-aborted signal for an aborted parent and `openRpcStream` throws before
  dialing — assert no dial happened, not merely that the outcome is `cancelled`.
- **The caller's signal firing *during* the read** must still be `cancelled`, not `timeout`: check
  the caller's signal before classifying, always.
- **A `stop()` landing mid-flight records nothing** — no strike, no backoff, no relevance decay, no
  `pingsFail` — for every sender. That is `15.2b`'s assertion, but the variant that makes it
  possible is minted here.
- **Tick-budget expiry** (`STABILIZE_TICK_BUDGET_MS`) is a child of the run signal and must behave
  identically to `stop()` at the seam: whichever signal the caller passed is *the* caller signal.
- **`dial: 'never'` with no connection → `skipped`, never `unreachable`.** No strike, no backoff.
- **`dial: 'if-addressed'` with `isDialable(id) === false` → `skipped` and no dial attempt.**
- **Release exactly once, on every path**, including `skipped` (nothing opened → nothing to
  release) and the backpressure-timeout path (opened, never fully written).
- **No unhandled rejection escapes** on any path — the abandoned `pending` read, the `drain` wait
  that loses its race, the release of an already-reset stream.
- **`decode` throwing must not leak the stream**, and must map to `decode-error`, not `unreachable`.
- **An over-cap reply** (`payload too large`) is `decode-error`: the peer answered, badly.
- **`FrameTruncationError` / `UnexpectedEOFError`** → `decode-error` (today `sendPing` already
  special-cases these at `ping.ts:106-108`; that behavior is preserved, generalised).
- **`d.cancel()` in a `finally` is mandatory** — an uncleared timer fails the repo's mocha exit
  watchdog. Every path through `rpcRequest`, including the early `skipped` return.

## Key tests to expect (`test/rpc.request.spec.ts`, new)

Drive `rpcRequest` against stub streams (reuse the shapes above):

- Each failure shape maps to its stated variant: reset mid-stream → `unreachable`; tidy close
  mid-JSON → `decode-error`; bytes then silence until the budget → `timeout`;
  `UnsupportedProtocolError` from the open → `foreign-protocol`; `{busy:true,retry_after_ms:500}`

- `sendFramed` returning `false` is followed by a bounded `drain` wait, not a hang: a stub that
  never drains ends as `timeout` within the budget; one that drains proceeds to `ok`.
