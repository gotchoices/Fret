## Src facts you inherit (verified against `src/rpc/protocols.ts` post-landing)

- `sendFramed(stream, body)` = `stream.send(lp.encode.single(body))`.
- `readFramed(stream, maxBytes, timeoutMs = RPC_TIMEOUT_MS, opts?: {signal})` reads exactly ONE
  frame. Over-cap prefix throws `payload too large: ${declared} exceeds ${maxBytes} byte limit`
  from the decoder's `onLength` hook — after the prefix, before any body byte. Defensive arm: an
  8-byte varint past 2^53 trips lp's `InvalidDataLengthError`, re-thrown as `payload too large:
  declared length exceeds ${maxBytes} byte limit` (no declared number) — `.include('payload too
  large')` covers both.
- Stream ending before a whole frame → `FrameTruncationError` (stable `.name`); lp's own
  partial-varint/partial-body EOF → `UnexpectedEOFError`. `isFrameTruncationError` matches
  exactly those two names.
- Zero-length frame (prefix `0x00`) is NOT an error — returns empty `Uint8Array`; `decodeJson`
  then throws `empty response`.
- Timeout throws `read timed out after ${timeoutMs}ms` — no byte-count suffix anymore.
- Trailing bytes after the first frame are never pulled. No EOF poll, no
  `readBufferLength`/`remoteWriteStatus` consultation; the 20 ms poll floor is gone.
- `sendPing` maps `isFrameTruncationError` and decode failures to `{ok: false, rttMs}`;
  everything else (reset, deadline, abort, payload-too-large) propagates. sendPing writes NO
  request — the handler replies on stream open.
- Caps: maybeAct sender 512 KB, neighbors 128 KB, ping 1024, leave handler 4096.
- `src/index.ts` exports `sendFramed, readFramed` (alongside `openRpcStream`/`releaseRpcStream`);
  `readAllBounded` is deleted from the surface.
- Frame test bytes with `lp.encode.single(bytes)` (`import * as lp from 'it-length-prefixed'`;
  `.subarray()` for a `Uint8Array`); truncate the FRAMED bytes for partial-message cases.

Design decisions are settled; do not re-open.
