Companion to the `framed-read-false-truncation` fix (prereq): `readFramed` now reads frames at
the same layer as the stream's own EOF state (`byteStream` from `@libp2p/utils` on real streams;
poll-less iterator loop on plain async iterables; the 20 ms `EOF_POLL_MS` poll is deleted). All
investigation was settled in that ticket; this one is tests + docs only.

## Tests

- **Forced-race seam test** — the load-bearing regression guard; site it beside `readFramed`'s
  other tests (`rpc.protocols.spec.ts`). Stub stream presenting the full message-stream surface
  (`closeRead`, `addEventListener`, `removeEventListener`, `send`, `push`, `log` — all six
  functions, so it takes the stream path) whose `readBufferLength` reads 0 and
  `remoteWriteStatus` reads `'closed'` while a complete length-prefixed frame is delivered via a
  `message` event AFTER `readFramed` is entered. Assert the frame is returned rather than
  `FrameTruncationError`. This shape failed under the old poll implementation by construction
  (stream-level state said "finished" while the frame was still in flight below it).
- **Two-node smoke matrix** — smoke only; the failing cell was never stable across runs, so do
  NOT build a depth-indexed assertion. Two `createMemNode`s, reply-only protocols registered via
  `registerJsonHandler` whose `serve` callbacks await 0/1/2/4 extra microtasks before returning,
  crossed with a with-body / without-body axis, driven by `rpcRequest`; assert every cell `ok`.
- **Restore the close-then-read shape in `sendRaw`** — `test/rpc.handler-fuzz.spec.ts:1034`
  (helper block starts ~1028; `RawResult` type at 1032). Move the half-close BEFORE the read
  starts and delete the stale comment at lines 1038–1040+ ("Start the read *before* the
  half-close... closing first can lose a reply..."), which documents the fixed defect as a
  test-shape constraint. Keep the `RawResult` mapping (`isFrameTruncationError` → `'eof'`)
  unchanged — the drop-shape assertions at ~1162–1166 depend on it. Callers (~1149, 1214, 1223,
  1237, 1251–1266, 1297, 1308) consume `RawResult` only and need no changes.

## Docs

- `src/rpc/ping.ts` and `src/rpc/neighbors.ts`: retire the two reply-only `NOTE:` blocks that
  point at the framed-read false-truncation defect (now fixed).
- `docs/fret.md`, *Stream management* bullet: remove the 20 ms poll (`EOF_POLL_MS`) description
  and its rationale; state the new guarantee (frames read at the same layer as the stream's EOF
  state). Caveat the "any bytes after the frame ignored (never pulled)" wording: on the
  real-stream path trailing bytes ARE pulled into `byteStream`'s buffer (message events deliver
  whatever arrives); the wording stays true on the iterable path.
- `test/rpc.codec-properties.spec.ts` pull-count measurement ("an over-cap message costs only
  the prefix") drives an async-iterable source, so it stays on the iterable path and should be
  unaffected — re-check it passes rather than assuming, and keep its wording accurate.
