## Tests to add — extend `test/rpc.handler-fuzz.spec.ts`

That spec already pins the `registerRpcHandler` seam (release-exactly-once, the write-end-status
branch in the error arm). The additions ride on its existing rig rather than a new one.

- For **every** inbound wire message and every field: wrong type, missing, and over cap. The
  message must be dropped without throwing out of the handler, without leaking the stream, and the
  existing release-exactly-once invariants must hold — **close** on a body-level drop, **abort** on
  a frame-level failure. Assert the *arm*, not merely the release count; the count alone passes for
  both arms and so proves nothing about the rule.
- A snapshot carrying more ids than the profile cap: assert the parse+hash+upsert loop runs exactly
  `caps.*` times, **by counting the loop's work** — a spy on the store's `upsert` or on the hash —
  rather than by inferring it from the absence of a crash.
- `from` that is not a parseable peer id: dropped, `diag.rejected.malformed` incremented,
  `identityMismatch` **not** incremented.
- `from` that is a parseable peer id but not the authenticated sender: dropped,
  `identityMismatch` incremented, `malformed` **not** incremented.
- A `sample` entry with a short `coord`: that entry dropped, the rest of the snapshot merged.
- **`onMalformed`'s `reason` argument is asserted, not just its call count.** The hook is called
  with `'decode'` for a body that is not JSON (or decodes to a non-object) and `'parse'` for a body
  that decodes but the parser rejects. Nothing currently pins which value each path passes, so the
  two could be swapped without a test noticing — and the service wires the hook to a counter it
  intends to split by reason later. One case per value, over the existing rig.
- **`registerNeighbors`' defaulted `snapshotParser` is exercised at least once.** Omitting the
  trailing parameter builds a parser with `Infinity` caps — "validate the shape, truncate nothing".
  Every current caller supplies one, so the default is untested: assert that a call omitting it
  still rejects a malformed snapshot (shape checking is live) and merges an over-cap id list whole
  (no truncation). See the `NOTE:` at that parameter in `src/rpc/neighbors.ts` for why it stays
  defaulted.

The last three are the pair of counters `15.32` has to keep distinct, so they are the tests most
worth writing first.
