## Verified facts about the code under test

`packages/fret/src/service/fret-service.ts`:

- `runAbort: AbortController | null` (line ~181), `private get runSignal()` (line ~648) returns
  `this.runAbort?.signal` — so `undefined` before the first `start()`.
- `start()` (line ~764): `this.runGen++; this.runAbort = new AbortController();` — a fresh
  controller per run.
- `stop()` (line ~860): order is `started=false` → `runGen++` → `stopped=true` →
  `clearLoopTimers()` → `this.runAbort?.abort()` → `removeNodeListeners()` →
  `unregisterRpcHandlers()` → `sendLeaveToNeighbors()` → `backoffMap.clear()` /
  `departureDebounce.clear()`. The aborted controller is **kept**, not nulled.
- `SHUTDOWN_BUDGET_MS = 3000`, `LEAVE_NOTICE_TIMEOUT_MS = 1500` (lines ~301/303, `private static`).
- `sendLeaveToNeighbors()` (line ~1383) builds `deadline(SHUTDOWN_BUDGET_MS)` and passes
  `{ signal: budget.signal, timeoutMs: LEAVE_NOTICE_TIMEOUT_MS }` to each `sendLeave`. Targets:
  unfiltered `neighborsRight/Left(selfCoord, cfg.m)` minus self, `.slice(0, 8)`, each skipped if
  `isDoomedDial(id)`.
- **The stabilization tick body is in `startStabilizationLoop()` at line ~1699, not in
  `stabilizeOnce`**:
  ```
  await this.seedFromPeerStore();
  await this.seedFromBootstraps();
  await this.stabilizeOnce();
  ```
  `stabilizeOnce()` (line ~1752) is: `sweepBoundedMaps()` → `probeNeighborsLatency(near.slice(0,4))`
  → `mergeNeighborSnapshots(near.slice(0,4))` → `classifyUnknownPeers()` → `reprobeExcludedPeers()`.
  It has **no `stopped` re-check between the passes**, and each pass captures `this.runSignal`
  itself — so the park point for the mid-tick test must be `seedFromPeerStore`, which is the only
  awaited seam ahead of every capture.
- `openRpcStream` (`src/rpc/protocols.ts` line ~277) throws immediately when
  `opts.signal?.aborted`, and only calls `node.dialProtocol` when no open connection exists —
  a connected peer goes through `connection.newStream` instead. That is what makes a
  `dialProtocol` override target exactly the non-connected (ghost) peer.
- `sendLeave` / `sendPing` build `deadline(opts.timeoutMs ?? RPC_TIMEOUT_MS, opts.signal)` — the
  sender's deadline is a **child** of the caller's signal.

## Tests to add (`packages/fret/test/service-lifecycle.spec.ts`)

The file already has the start/stop harness (`beforeEach` creates a `createMemNode()` + an
unstarted `FretService`), the `(svc as any)` override pattern, and a park/unpark example
("does not re-arm the stabilization timer when stop() lands mid-tick", ~line 170).

### `stop()` stays inside its shutdown budget when a dial hangs, and reachable neighbors still get the notice

Two real in-memory nodes (`createMemNode` from `test/helpers/libp2p.ts`), the stopping one holding
`svc`, the other running its own started `FretService` on the same `networkName`. Dial them
together so the receiver is `connected` (hence dialable and not `isDoomedDial`). Then seed one
**ghost** id (a real Ed25519 peer id from a node that was created and immediately stopped — see
`unreachablePeer()` in `test/dead-state.spec.ts` ~line 675, or `ghostPeerId()` in
`test/churn.leave.spec.ts` ~line 20) into the stopping node's store, and make it pass the guard
with `(svc as any).setAddressKnown(ghostId, true)`.

Make the ghost's dial hang: override `dialProtocol` on the stopping node, delegating for every
other peer. The hang must settle **only** on signal abort — that is libp2p's `AbortOptions`
contract, and the pattern is `hangsUntilAbort(opts)` in `test/rpc.protocols.spec.ts` ~line 260:

```ts
const original = node.dialProtocol.bind(node)
;(node as any).dialProtocol = (pid: PeerId, protocols: string[], opts: any) =>
    pid.toString() === ghostId
        ? new Promise((_res, reject) => {
            if (opts?.signal == null) return                       // hangs forever without a signal
            if (opts.signal.aborted) { reject(abortReasonError(opts.signal)); return }
            opts.signal.addEventListener('abort', () => reject(abortReasonError(opts.signal)), { once: true })
        })
        : original(pid, protocols, opts)
```

Count leave delivery on the receiver by wrapping its handler — `registerLeave` was bound at
`start()` as the closure `async (notice) => this.handleLeave(notice)` (line ~960), so a later
override of `handleLeave` **is** picked up:

```ts
const orig = (peerSvc as any).handleLeave.bind(peerSvc)
let leaves = 0
;(peerSvc as any).handleLeave = async (n: any) => { leaves++; await orig(n) }
```

Assert: elapsed `Date.now()` across `await svc.stop()` is `at.most(SHUTDOWN_BUDGET_MS + 1500)`
(4500 — generous on purpose; the property is "bounded at all", not scheduler precision), and
`leaves === 1`. Prefer the handler counter over "departing id removed from the receiver's store":
the receiver's own stabilization tick re-seeds from its peerStore every ~1500 ms and would put the
id back. Restore `node.dialProtocol` in a `finally`.

### A `stop()` landing mid-tick issues no dials and strikes nobody for the rest of the tick

Park `seedFromPeerStore` (**not** `stabilizeOnce` — parking that one exercises nothing, since the
passes that capture the signal never run at all; and **not** `probeNeighborsLatency`, which is
already past the capture). Seed a dialable member peer into the store *before* `start()` so the
tick has a real probe target: `store.upsert(id, coord)`, `store.setMembership(id, 'member')`,
`(svc as any).setAddressKnown(id, true)`.

```ts
let unpark: (() => void) | undefined
const parked = new Promise<void>((entered) => {
    ;(svc as any).seedFromPeerStore = async () => { entered(); await new Promise<void>((r) => { unpark = r }) }
})
await svc.start(); await parked; await svc.stop()
const before = { ...svc.getDiagnostics() }
unpark!(); await delay(100)
```

Assert after unparking: `diag.pingsSent` unchanged, `diag.snapshotsFetched` unchanged, the seeded
peer's `contactFailures === 0`, its `state !== 'dead'`, and `(svc as any).backoffMap.get(id)` is
`undefined`. (`stop()` clears `backoffMap` *before* the tick resumes, so a non-empty map after
unparking is genuinely the tick's doing.) This is the hole the review of `rpc-service-signals`
closed by **not** nulling `runAbort`; without this test it can silently regress to a null.

### A start→stop→start cycle mints a fresh controller

`(svc as any).runSignal` is `undefined` before the first `start()`; `.aborted === false` after
`start()`; `.aborted === true` after `stop()` (the aborted controller is deliberately kept);
`.aborted === false` again after the second `start()`.
