### Verified library facts

Source: `packages/fret/node_modules/@libp2p/utils/dist/src/stream-utils.js`. `byteStream(stream)`
is what the stream path reads through.

- **Admission** (its `isValid` check): throws `InvalidParametersError` unless `addEventListener`,
  `removeEventListener`, `send`, `push`, `log` are all non-null. (`closeRead` is *not* checked
  there — it is checked by `isEOF` below, and by FRET's own `isMessageStream`.)
- **Subscriptions, registered synchronously inside `byteStream(...)`**: `message` (appends
  `evt.data` to byteStream's own private read buffer), `close` (an `evt.error` rejects the pending
  read), `remoteCloseWrite` (wakes the pending read). The event name is **`message`** and the
  payload field is **`data`**.
- **`isEOF(stream)`** is `typeof stream.closeRead === 'function'` and then
  `stream.remoteWriteStatus !== 'writable' && stream.readBufferLength === 0`.
- **The gate that shapes the whole test** — the first lines of `bs.read(options)`:

```js
if (isEOF(stream)) {
    if (options?.bytes == null) return null;
    if (readBuffer.byteLength < options.bytes) throw new UnexpectedEOFError(...);
}
```

  `readBuffer` there is **byteStream's own buffer**, not the stream's. So with EOF true, a read
  succeeds exactly when the bytes it wants are *already in byteStream's buffer*. That is precisely
  the invariant the fix bought: **buffered-but-unread bytes beat "the stream says finished"**.
- `unwrap()` removes the three listeners and, only if bytes remain unread, calls `stream.log(...)`
  and `stream.push(...)`. A test consuming exactly one whole frame hits neither.

**Consequence for the stub — the non-obvious part.** There is **no `await` between the listener
registration and that `isEOF` gate**: `readFramedFromStream` calls `byteStream(stream)`
(synchronous), then `bs.read({bytes:1, signal})`, whose body runs synchronously down to its first
`await`, which is *after* the gate. So a `message` event dispatched on a later turn of the event
loop arrives too late — the read has already thrown `UnexpectedEOFError`. With
`readBufferLength: 0` and `remoteWriteStatus: 'closed'` held constant, the frame **must** be handed
over at the moment the `message` listener is registered. That models the real transport faithfully:
bytes that already arrived are dispatched to a reader the instant it subscribes, and
`readBufferLength: 0` is the correct post-dispatch state (the bytes left the stream's buffer and
now sit in the reader's).

### Why the stub fails under the pre-fix implementation

Source: `git show 377c8fe:packages/fret/src/rpc/protocols.ts`. The old `readFramed` ran
`lp.decode(stream)` over the stream **as an async iterable** and raced it against a 20 ms poll;
each poll tick called `remoteFinishedWriting(stream)`, which returned true for
`readBufferLength === 0 && (remoteWriteStatus === 'closed' || readStatus === 'closed')` and threw
`FrameTruncationError`. It never registered a `message` listener. So give the stub an
`[Symbol.asyncIterator]` that yields the frame after ~50 ms: under the old code the 20 ms poll
fires first and truncates, while under the new code the iterator is never touched and the frame
returns. That is what makes this a genuine regression guard rather than a shape assertion.
