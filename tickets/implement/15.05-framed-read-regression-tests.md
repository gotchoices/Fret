## State of the world (verified this run — do not re-derive)

The prereq fix **has landed**. `readFramed` (`packages/fret/src/rpc/protocols.ts`, ~line 535) now
dispatches on what the source is, and the 20 ms `EOF_POLL_MS` poll is deleted:

- `isMessageStream(stream)` (~line 350) is the discriminator. It requires **six** functions to be
  present: `closeRead`, `addEventListener`, `removeEventListener`, `send`, `push`, `log`. A stub
  missing any one of them falls through to the iterable path — exactly the trap the forced-race
  test below must avoid.
- True -> `readFramedFromStream` (~line 374): `byteStream(stream)` from `@libp2p/utils`, reads the
  varint prefix one byte at a time, enforces the cap at the prefix, then reads the declared body.
  Frames are read at the same layer as the stream's own EOF state.
- False -> `readFramedFromIterable` (~line 425): the old `lp.decode` path, ending on iterator EOF
  alone. Plain async generators (every existing stub in these specs) take this path.

### Forced-race seam test — the load-bearing regression guard

Site it in `test/rpc.protocols.spec.ts`, beside `readFramed`'s other tests (the `RPC deadlines`
describe block, ~lines 374-560, holds them today).

Build a stub stream presenting the full message-stream surface — **all six functions named above**,
so `isMessageStream` returns true and the test takes the stream path — whose `readBufferLength`
reads 0 and `remoteWriteStatus` reads `'closed'`, while a complete length-prefixed frame is
delivered via a `message` event **after** `readFramed` has been entered. Assert the frame is
returned rather than a `FrameTruncationError`.

This shape failed by construction under the old poll implementation: stream-level state said
"finished" while the frame was still in flight below it. Check what `byteStream` from
`@libp2p/utils` actually subscribes to before writing the stub — the event name and the buffer
fields it consults are what the stub has to satisfy.
