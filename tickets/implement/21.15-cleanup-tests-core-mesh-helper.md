### Explicitly NOT in scope

Two-node one-off pair setups (`await b.dial(a.getMultiaddrs()[0]!)` in `dead-state`,
`failure-recovery`, `identity-verification`, `network.isolation`, `membership-identify`,
`rpc.*`). They call the same factory but build no topology; folding them into a mesh helper
makes them harder to read, not easier. Leave them as they are.

## Design decision (made — implement this, don't re-litigate)

**New file `test/helpers/mesh.ts`.** A new file rather than growing `libp2p.ts`, because
`libp2p.ts` is the *node factory* (no knowledge of `FretService`) and a mesh helper must import
`FretService` — pushing that import into the factory would make every spec that only wants a bare
node pull the service in.

**Two-phase, not one call.** The ordering difference between specs is behaviourally real and must
not be flattened: `churn.leave` constructs and starts services *then* dials the star, while
`profile.behavior` dials the star *then* constructs the service (so `start()`'s
`seedFromPeerStore` sees the connections). A single `buildMesh({count, topology, service})` would
bake one order in and silently change what several specs assert. So:

```ts
// test/helpers/mesh.ts
export type Topology = 'star' | 'line' | 'full'

export interface Mesh {
	readonly nodes: Libp2p[]
	readonly ids: string[]            // nodes[i].peerId.toString()
	readonly services: FretService[]  // empty until addServices()
	connect(topology: Topology): Promise<void>
	addServices(cfg: Partial<FretConfig> | ((i: number, mesh: Mesh) => Partial<FretConfig>)): Promise<void>
	stop(opts?: { skip?: number[] }): Promise<void>
}

/** N started in-memory libp2p nodes. No services, no connections yet. */
export async function buildMesh(count: number): Promise<Mesh>
```

- `addServices` takes a **callback form** so a spec can write `bootstraps: [mesh.ids[0]!]` — the
  config depends on nodes that only exist after `buildMesh`. It constructs and `start()`s each
  service in index order and pushes onto `services`.
- `stop({ skip })` stops services first (in reverse), then nodes via the existing `stopAll`,
  skipping the given indices — that is the "one node was stopped mid-test" case in `churn.leave`
  and `profile.behavior`, and it is the only reason those teardowns are hand-written today.
  Every stop swallows its own throw, matching `stopAll`.
- `connect('line')` delegates to the existing `connectLine` rather than re-implementing it.
