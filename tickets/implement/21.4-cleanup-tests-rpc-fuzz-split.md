Recommendation: `test/rpc.handler-fuzz.wire.spec.ts`, which keeps the fault-isolation identity and
states which tier moved. Either name is acceptable; state the choice in the review handoff.

## Edge cases & interactions
- Pure file-split: every test case in both extracted blocks must still exist, still pass, and still
  assert the same things — count `it(` blocks before and after per section to confirm nothing was
  dropped in the move.
- **The `unhandledRejection` guard must be copied, not shared.** It is registered on the top-level
  `describe` (lines 249–259) precisely because a file-top-level hook would be a mocha *root* hook
  and run against the whole suite. Each extracted file needs its own `describe`-scoped copy, or it
  silently loses the "no case may leak a rejection" guarantee.
- The file's three-tier header comment (lines 22–37) describes a file that will no longer hold
  three tiers. Update it in `rpc.handler-fuzz.spec.ts` and give each extracted file a header saying
  what it owns and pointing back — the comments are load-bearing documentation here, not decoration.
- `seq` is shared mutable module state behind `baseMsg()`. If `baseMsg` moves to a shared helper,
  `seq` moves with it and correlation ids stay unique across both importing specs (fine — they run
  in separate mocha files but the same process). If it is duplicated instead, each copy gets its own
  counter, which is also fine. Just don't split `seq` from `baseMsg`.
- Confirm `packages/fret/.mocharc.json` picks up new spec files by glob rather than an explicit file
  list — **not yet checked.** One `cat` answers it.
