## Scope bound

Announce (`PROTOCOL_NEIGHBORS_ANNOUNCE`) is the only inbound message in scope. The neighbors
*request* and ping read no body, so they have no body-level drop path. Service-tier cap **counting**
(how many merge operations a crafted snapshot can force) is `rpc-snapshot-cap-merge-tests`, not
this ticket — here the assertion is what the parser hands `onAnnounce`, not what the service does
with it.

### `makeSnapshotParser(caps)` per field — reject vs normalize (verified)

A reject drops the whole message: seam closes, no reply, `onAnnounce` never runs.

- `from` — must satisfy `isPeerIdString`. Wrong type, missing, unparseable → **reject**.
- `timestamp` — must be a finite `number` (no coercion, so `'5'` and `null` both reject). Wrong
  type or missing → **reject**.
- `successors` / `predecessors` — `boundedStringArray(value, cap)`: non-array (including missing)
  → `[]`; otherwise **truncate to `cap` first, then drop non-strings**. That order is deliberate
  and is itself worth a case: a crafted list of 100k non-strings must cost `cap` comparisons, not
  100k. **Normalizes.**
- `sample` — `parseSample`: non-array → `[]`; else `slice(0, cap)`, then each entry must be a plain
  object with `id: string`, `coord: string`, a finite `relevance`, and a `coord` that survives
  `base64urlToCoord` (exactly 32 decoded bytes). A failing entry is **skipped and logged**; it is
  never a message-level reject. **Normalizes.**
- `size_estimate` / `confidence` — `finiteNumberOr(..., undefined)`; when not finite the key is
  **deleted** from the outgoing object.
- `metadata` — kept only when it is a non-null, non-array object; otherwise **deleted**.
- `sig` and `v` — deliberately unchecked. Do not add cases asserting they reject.

So the matrix's columns are not uniform: "over cap" is meaningful only for the four list fields
(`successors`, `predecessors`, `sample`), and "missing" collapses into "wrong type" for both
rejecting fields. Write the table so each row states its own expectation (`reject`, or
`normalize-to <value>`) rather than assuming one shape per column.

## Tests to add

- **Announce snapshot, per field, per way of being wrong** (`from`, `timestamp`, `successors`,
  `predecessors`, `sample`, `size_estimate`, `confidence`, `metadata`): wrong type, missing, and —
  for the list fields — over cap. Each message must be handled without throwing out of the handler
  and without leaking the stream, and the release-exactly-once invariant must hold. **Assert the
  arm, not merely the release count** — every case here is a `close`; the count alone passes for
  both arms and so proves nothing about the rule.
  - A *rejecting* field (`from`, `timestamp`) drops the whole message with no reply and never runs
    `onAnnounce`. A *normalizing* field (the id lists, `sample`, the advisory numerics, `metadata`)
    still answers `{ok: true}` with that field neutralized — assert **what reached `onAnnounce`**
    (`[]` for a non-array list; exactly `cap` entries for an over-cap one; the bad `sample` entry
    absent while its siblings survive; the key *absent* for a non-finite `size_estimate` /
    `confidence` and for a non-object `metadata`), not just the release arm.
  - One row for the truncate-then-filter **order**: a list of `cap + N` non-strings must normalize
    to `[]` having compared only `cap` entries — assert the observable half (the `[]`, and that a
    trailing valid string past `cap` did *not* survive).
