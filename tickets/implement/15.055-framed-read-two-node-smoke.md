## Why

The regression guard that landed covers `readFramed` against a stub stream at the seam. Nothing
yet exercises the same invariant — *a reply that was really written is never reported as cut off*
— over a real libp2p transport with two nodes. This adds that, as a **smoke test only**.

## Scope discipline — read this before designing

**Smoke only. Do NOT build a depth-indexed assertion.** The original failing cell was never
stable across runs, so an assertion keyed on "how many microtasks the handler awaited" will
flake. Assert only that every cell comes back `ok`.

## Shape

New spec file (or a new describe block in an existing rpc spec — implementer's call).

- Two nodes from `createMemNode` (`test/helpers/libp2p.ts:21`); tear down with `stopAll` (`:63`).
- On the responder, register **reply-only** JSON protocols via `registerJsonHandler`. The
  reply-only overload takes `{ serve: (connection) => Res }` and has **no `parse` key** — that
  absence is the discriminator TypeScript narrows on. See `src/rpc/protocols.ts:163-167` for the
  options interface and `:194-196` for the overload signature.
- Each protocol's `serve` awaits a different number of extra microtasks before returning: 0, 1,
  2, 4. That is the timing axis.
- Cross it with a second axis: a reply **with a body** and a reply **without one**.
- Drive each cell from the other node with `rpcRequest` (`src/rpc/request.ts:199-215` for the two
  overloads). **Pass `decode`** to get a typed reply — the no-`decode` overload is the write-only
  one and pins the reply type to `undefined`.
- Assert every cell's outcome `kind` is `ok`.

Keep the whole thing well inside a normal mocha timeout; these are in-memory nodes and the
handlers do no real work.
