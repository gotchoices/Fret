## Src facts you inherit (verified against `src/rpc/protocols.ts` post-landing)

- `sendFramed(stream, body)` = `stream.send(lp.encode.single(body))`.
- `readFramed(stream, maxBytes, timeoutMs = RPC_TIMEOUT_MS, opts?: {signal})` reads exactly ONE
  frame. Over-cap prefix throws `payload too large: ${declared} exceeds ${maxBytes} byte limit`
  before any body byte; the 2^53 defensive arm throws `payload too large: declared length
  exceeds ${maxBytes} byte limit` — `.include('payload too large')` covers both.
- Stream ending before a whole frame → `FrameTruncationError` (stable `.name`); lp's own
  partial-varint/partial-body EOF → `UnexpectedEOFError`. `isFrameTruncationError` matches
  exactly those two names.
- Zero-length frame (prefix `0x00`) returns empty `Uint8Array`; `decodeJson` then throws
  `empty response`.
- Timeout throws `read timed out after ${timeoutMs}ms` — no byte-count suffix.
- Trailing bytes after the first frame are never pulled; no EOF poll; 20 ms poll floor gone.
- `sendPing` maps `isFrameTruncationError` + decode failures to `{ok: false, rttMs}`; everything
  else propagates. sendPing writes NO request — the handler replies on stream open. The ping and
  neighbors-request inbound handlers never read the request body; maybeAct, leave, and announce
  read one frame.
- Caps: maybeAct sender 512 KB, neighbors 128 KB, ping 1024, leave handler 4096.
- `src/index.ts` exports `sendFramed, readFramed`; `readAllBounded` deleted from the surface.
- Frame test bytes with `lp.encode.single(bytes)` (`import * as lp from 'it-length-prefixed'`;
  `.subarray()` for a `Uint8Array`).

Design decisions are settled; do not re-open.
