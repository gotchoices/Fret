## Run-6 findings (investigation only, no edits yet)

### Failure group A — `test/stabilize-concurrency.spec.ts` (3 failures): root cause CONFIRMED

`PeerRig.reply` in `test/helpers/maintenance-rig.ts` (lines ~114–121) returns raw
`encodeJson(...)` bytes — UNFRAMED. Under `readFramed`, the first byte of raw JSON (`{` = 0x7b)
parses as a varint declaring a 123-byte body; the stub stream yields once then EOF, so every
ping/fetch ends in `FrameTruncationError` → `sendPing` returns `{ok:false}` → `pingsOk` 0,
`pingsFail` counted, snapshots empty. Exactly matches the three observed failures.

FIX (not yet applied): in `maintenance-rig.ts`, wrap both replies:
`lp.encode.single(await encodeJson(...)).subarray()` (import `* as lp from 'it-length-prefixed'`;
pattern identical to `framed()` at `rpc.handler-fuzz.spec.ts:166`). `stubStream` yields the
bytes it is given, so no other rig change needed. `preconnect-concurrency.spec.ts` shares this
rig and currently passes (its assertions tolerate `ok:false` pings); framing the replies makes
them valid, which can only strengthen it — but re-run it anyway.

### Failure group B — `test/rpc.stream-errors.spec.ts` "over a real transport" (2 failures): prior hypothesis REFUTED, cause still open

The prior note guessed the half-reply writers "still write UNFRAMED partial JSON". WRONG:
`HALF_PING` / `HALF_SNAPSHOT` are already framed partials — `framedPartial()` at lines 78–86
takes a strict prefix of `lp.encode.single(full)`. The writers (`halfThenClose`,
`halfThenReset`, lines ~906–915) send a partial FRAME then close/reset. Test-side framing
migration of this file is COMPLETE.

What run 6 established instead:

- Test 5's error `DeadlineExpiredError: deadline expired after 5000ms` is the `deadline`
  util's signal (`d.signal`) surfacing through `readFramed`'s ABORTED race arm — meaning the
  read sat the FULL 5 s with neither a frame nor an EOF/`UnexpectedEOFError` arriving. Test 4's
  5014 ms empty-snapshot return is the same stall with `fetchNeighbors` swallowing the error.
  So over the real transport (memory transport + noise + yamux between two nodes), the remote's
  partial-frame-then-`close()` never surfaces EOF to `readFramed` within the budget.
- NOT a "sender never negotiates" regression from the framing commit: `git show f5f2eb6 --
  src/rpc/ping.ts src/rpc/neighbors.ts` shows pre-framing `sendPing`/`fetchNeighbors` also
  wrote nothing (bare `readAllBounded`), same no-request shape. The real-transport describe
  pre-dates framing (added in `rpc-stream-error-tests`, commit 14c2444; framing migration of
  the file landed in d940580).
- readFramed implementation reviewed (`protocols.ts:222–287`): single `iter.next()` on
  `lp.decode(stream)` raced against its own timer + caller signal. A delivered partial body +
  source end SHOULD reject that pending next() with `UnexpectedEOFError` → `sendPing` maps to
  `ok:false` promptly. The stub `halfThenEof` unit tests (same bytes, same readFramed) PASS —
  so the gap is specifically in what the live stream's async iterator does on remote close.
