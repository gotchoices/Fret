## Why (condensed — do not re-derive)

Five outbound senders hand-roll the same open / write / read / close sequence with four
disagreeing failure contracts:

| sender | reply undecodable / empty | unreachable | busy | site |
|---|---|---|---|---|
| `sendPing` | `{ ok: false }`, no strike | throws | `{ ok: false }` | `ping.ts:88-131` |
| `fetchNeighbors` | fabricated empty snapshot | fabricated empty snapshot | fabricated empty snapshot | `neighbors.ts:81-112` |
| `sendMaybeAct` | throws — service books a contact strike | throws | returns the busy object | `maybe-act.ts:87-113` |
| `announceNeighbors` | n/a (write-only) | logs and swallows | n/a | `neighbors.ts:120-149` |
| `sendLeave` | n/a (write-only) | throws | n/a | `leave.ts:75-92` |

The consequence that matters most: `noteRpcFailure` (`fret-service.ts:669-680`) sniffs errors
with `isUnsupportedProtocolError` and books every other throw as a contact strike, so
`sendMaybeAct` letting `decodeJson`'s plain `Error`s propagate means a peer that opened a stream
and merely *replied badly* is counted unreachable — three such replies mark it `dead`. The ping
path classifies identical evidence the other way.

## What lands here

### `RpcOutcome<T>` — one discriminated union (`src/rpc/outcome.ts`)

```ts
/** Why an outbound RPC ended. Exactly one variant per FRET failure mode; the service branches
 *  on `kind` rather than sniffing an error. */
export type RpcOutcome<T> =
	| { kind: 'ok'; value: T; rttMs: number }
	| { kind: 'skipped' }
	| { kind: 'cancelled' }
	| { kind: 'timeout' }
	| { kind: 'unreachable'; error: Error }
	| { kind: 'foreign-protocol'; error: Error }
	| { kind: 'decode-error'; error: Error }
	| { kind: 'busy'; retryAfterMs?: number };
```

Doc-comment each variant with what it *proves about the peer* (that is what the service
branches on):

- **`ok`** — a whole framed reply arrived, decoded and (where a validator was supplied)
  validated. `rttMs` measured from *after* the stream open, never including the dial (matches
  `sendPing`). For a **write-only** RPC `value` is `undefined` and `ok` means *the body reached
  the transport*, explicitly **not** proof the peer received or accepted it — say that in the
  doc comment; it is the whole reason a rate-limited leave is invisible today.
- **`skipped`** — nothing was attempted: dial mode forbade dialing and no connection existed.
  Distinct from `ok` with an empty payload; the separation ends the `snapshotsFetched`
  overcount `NOTE:`d at `fetchAndMergeSnapshot`.
- **`cancelled`** — the **caller's** signal aborted. Not evidence about the peer.
- **`timeout`** — our own budget expired and the caller's signal did *not*. Contact strike.
- **`unreachable`** — dial, stream-open, reset or transport failure. Contact strike.
- **`foreign-protocol`** — `isUnsupportedProtocolError(err)`. Membership evidence, never a strike.
- **`decode-error`** — the peer opened a stream and answered, but the answer was truncated,
  empty, non-JSON, a non-object top level, over the byte cap, or rejected by the validator.
  **Proof of life; never a contact strike.** Retires the `sendMaybeAct` misclass.
- **`busy`** — the reply was a `BusyResponseV1`. `retryAfterMs` carries `retry_after_ms` when
  present.

**`cancelled` is a variant, and the helper owns the call.** The helper holds both signals — its
deadline is a child of the caller's — so on any failure it checks the *caller's* signal first;
aborted → `cancelled`, else classify. Callers must **not** re-derive cancellation from a helper
result — the variant wins. (The service's `wasCancelled` at `fret-service.ts:704` stays for
paths not on the helper.)

### `rpcRequest` — the single owner of open / write / read / close (`src/rpc/request.ts`)

```ts
export interface RpcRequestOptions<T> {
	/** Whole-RPC budget: dial + open + write + read + close. Defaults to RPC_TIMEOUT_MS. */
	timeoutMs?: number;
	/** Caller's cancellation. The helper's deadline is a child of it. */
	signal?: AbortSignal;
	/** When may we dial? Replaces the `requireExisting` boolean at the call site. */
	dial?: 'never' | 'if-addressed' | 'always';
	/** Required for `dial: 'if-addressed'`; false → `{ kind: 'skipped' }` with no dial. */
	isDialable?: (peerIdStr: string) => boolean;
	/** Declared-length cap for the reply, per protocol. */
	maxBytes?: number;
	/** Body to write. Omit for a read-only request (the neighbors fetch). */
	body?: unknown;
	/** Absent → write-only: no reply is read and `ok.value` is `undefined`. */
	decode?: (bytes: Uint8Array) => T | Promise<T>;
	/** Half-close our write end before reading (the maybeAct flush). Default false. */
	halfCloseBeforeRead?: boolean;
}

export async function rpcRequest<T = undefined>(
	node: Libp2p, peer: string, protocol: string, opts?: RpcRequestOptions<T>
): Promise<RpcOutcome<T>>;
```

`rpcRequest` **never throws** for a network outcome. It may still throw for a caller bug (a
malformed peer id from `peerIdFromString`, `dial: 'if-addressed'` with no `isDialable`) — those
are programming errors, never dressed as `unreachable`.

Generic with a `decode` callback (not raw bytes): `15.3-rpc-message-validators` plugs its
per-message validator in here; a validator rejection maps to `decode-error` in one place.

Dial-mode mapping (`openRpcStream`'s own signature **unchanged** — it is a pinned public
export): `'never'` → `requireExisting: true`; `'always'` → default; `'if-addressed'` →
`isDialable(peer)` ? default : `requireExisting: true` — an existing connection is still used
(no dialability needed to reuse a live connection); no connection → `undefined` → `skipped`.
"No dial attempt" is the invariant. `isDialable` missing with this mode → throw (caller bug).
Document the mapping decision at the site.

### Backpressure (the one `protocols.ts` touch here)

`sendFramed` (`protocols.ts:194-196`) returns `stream.send`'s boolean and no sender reads it.
`rpcRequest` reads it: on `false`, await the stream's `drain` event, **bounded by the deadline
signal** — expiry → `timeout`, caller's signal → `cancelled`. Re-check `writableNeedsDrain`
after each drain event rather than assuming one clears it. Rewrite the deferral clause in
`sendFramed`'s comment (`protocols.ts:190-193`, currently ends "…write backpressure is
deliberately out of scope here (owned by the follow-up write-backpressure ticket); the boolean
is `stream.send`'s own \"queue has room\" result, passed through."): the boolean is now honored
by `rpcRequest` (bounded drain wait); the legacy senders still ignore it until
`15.2b-rpc-sender-migration` moves them onto the helper.

## Implementation plan (decided across three runs — do not re-derive)

Structure `request.ts` as small functions: open, write(+drain), read, decode, one shared
classify, release.

```ts
export async function rpcRequest<T = undefined>(node, peer, protocol, opts = {}) {
	// Caller bugs throw — both BEFORE deadline() so a throw leaves no timer to cancel.
	const pid = peerIdFromString(peer);
	const dialMode = opts.dial ?? 'always';
	if (dialMode === 'if-addressed' && opts.isDialable == null) throw new Error(...);
	const timeoutMs = opts.timeoutMs ?? RPC_TIMEOUT_MS;
	const maxBytes = opts.maxBytes ?? DEFAULT_MAX_BYTES;   // 64 KiB, see decisions below
	const d = deadline(timeoutMs, opts.signal);
	let stream: Stream | undefined;
	try {
		if (opts.signal?.aborted === true) return { kind: 'cancelled' };   // no dial issued
		const requireExisting = dialMode === 'never'
			|| (dialMode === 'if-addressed' && opts.isDialable!(peer) === false);
		try {
			stream = await openRpcStream(node, pid, [protocol], { requireExisting, signal: d.signal });
		} catch (err) { return classify(err, opts.signal, d.signal); }
		if (stream == null) return { kind: 'skipped' };
		const start = Date.now();                          // RTT clock: after open, before write
		if (opts.body !== undefined) {
			const failed = await writeBody(stream, opts.body, opts.signal, d.signal);
			if (failed) return failed;
		}
		if (opts.halfCloseBeforeRead === true) {
			try { await stream.close({ signal: d.signal }); }
			catch (err) { return classify(err, opts.signal, d.signal); }
		}
		if (opts.decode == null) return { kind: 'ok', value: undefined as T, rttMs: Math.max(0, Date.now() - start) };
		let bytes: Uint8Array;
		try { bytes = await readFramed(stream, maxBytes, Infinity, { signal: d.signal }); }
		catch (err) { return classify(err, opts.signal, d.signal); }
		return await decodeReply(bytes, opts.decode, Math.max(0, Date.now() - start), opts.signal);
	} finally {
		await releaseRpcStream(stream, d.signal);          // accepts undefined (skipped path)
		d.cancel();                                        // AFTER release — ordering load-bearing
	}
}
```

- **One shared `classify` for open/write/read catches** (correction to the earlier per-phase
  mapping — see third-run findings), order:
  1. `callerSignal?.aborted === true` → `cancelled`
  2. `isUnsupportedProtocolError(err)` → `foreign-protocol`
  3. `isFrameTruncationError(err)` → `decode-error`
  4. `err.message` starts `'payload too large'` → `decode-error`
  5. `deadlineSignal.aborted` or `err.name === 'DeadlineExpiredError'` → `timeout`
  6. else → `unreachable` (normalize non-Error to Error)
- **Decode phase is separate, never fed through `classify`**: caller-signal aborted →
  `cancelled`, else `decode-error` — a decode callback's own throw must not classify as
  timeout/foreign. `decodeReply` = `decodeJson(bytes)` in try/catch (its `empty response` /
  `whitespace response` / `non-object JSON payload` throws land as `decode-error`); busy shape
  test on the parsed value (`typeof res === 'object' && res !== null && 'busy' in res &&
  res.busy === true`, per `ping.ts:31-33`) → `{ kind: 'busy', retryAfterMs }` **before**
  `opts.decode` runs; then `opts.decode(bytes)` in try/catch → `decode-error`. Double parse of
  small messages accepted — note in a comment, do not redesign.
- **`writeBody`**: `sendFramed(stream, await encodeJson(body))`; on `false` → `awaitDrain`,
  all in one try/catch → `classify`. Returns an outcome on failure, `undefined` on success.
- **`awaitDrain(stream, signal)`**: guard — skip entirely unless
  `typeof (stream as …).writableNeedsDrain === 'boolean'` and `addEventListener` is a function
  (keeps plain test stubs working). Loop `while (writableNeedsDrain === true)`: if
  `signal.aborted` throw `abortReasonError(signal)`; else await `onceDrain(stream, signal)` — a
  promise with a `'drain'` listener and a signal `'abort'` listener, **both removed in both
  arms**, rejecting with `abortReasonError(signal)`. Rejection is created inside the awaited
  promise, so it cannot escape as an unhandled rejection.

## Findings from third run (new facts; everything below verified by read — re-read nothing)

- **Classification correction (the one design change vs the earlier mapping):**
  `openRpcStream` pins `negotiateFully: false` (`protocols.ts:488`), so an
  `UnsupportedProtocolError` is *deferred from open to the first read* (docs *Dialability*
  states this; every FRET sender reads). The earlier phase-mapping checked
  `isUnsupportedProtocolError` only in the open phase — a deferred negotiate failure would then
  classify `unreachable` and book a contact strike for what is membership evidence. Hence the
  ONE shared classifier above: error identities are disjoint per phase (truncation cannot
  happen at open), so folding the checks is safe and simpler.
- `BusyResponseV1` = `{ v: 1; busy: true; retry_after_ms: number }` (`src/index.ts:60-64`).
  Import **type-only** from `../index.js` — `ping.ts:17` already does; no runtime cycle.
- `deadline(ms, parent?)` (`src/utils/deadline.ts`): already-aborted parent → synchronously
  aborted signal; own expiry aborts with `DeadlineExpiredError` (name
  `'DeadlineExpiredError'`); parent abort surfaces via `abortReasonError(parent)`. Import
  `deadline`, `abortReasonError` (and optionally `DeadlineExpiredError`) from
  `../utils/deadline.js`.
- `releaseRpcStream(stream | undefined, signal)` (`protocols.ts:527`): `undefined` is a no-op —
  one unconditional `finally` covers the skipped path. Arm rule is *inside* it: `abort()` if
  `signal.aborted`, else bounded `close({signal})`, abort again on close rejection. The
  release-before-`d.cancel()` ordering NOTE sits at `protocols.ts:522-526`.
- `readFramed(stream, maxBytes, Infinity, { signal })` — `Infinity` mode landed by 15.1; signal
  mandatory (throws at entry otherwise); over-cap throws start `'payload too large'`
  (`protocols.ts:350,393`); truncation matched by exported `isFrameTruncationError`
  (`protocols.ts:216`, matches `FrameTruncationError` + `UnexpectedEOFError` by name).
- Half-close precedent: `maybe-act.ts:100-107` — `await stream.close({ signal: d.signal })`
  inside the try, comment explains it is the write-side flush the responder waits on.
- Sender pattern mirrored: `ping.ts:88-131` — `peerIdFromString` outside try; RTT
  `Math.max(0, Date.now() - start)` with `start` after open; `finally { await
  releaseRpcStream(stream, d.signal); d.cancel(); }`.
- **Decisions made — do not re-litigate:**
  - `maxBytes` default **64 KiB** (the smallest production per-protocol cap, neighbors-Edge).
    Doc-comment that real callers pass their protocol's cap; the default only protects a direct
    consumer who forgot.
  - Body presence test is `opts.body !== undefined` (`undefined` = absent, matching the wire
    contract where `undefined` cannot travel).
  - Write-only `ok.rttMs` is still measured (open → write/flush done); its doc comment already
    says what `ok` does and does not prove.
  - Deterministic release arms per outcome (single clock now): `timeout`/`cancelled` → released
    by `abort()` (the deadline signal has fired by the `finally`); `ok`/`busy`/`decode-error`/
    `unreachable` → by `close()`; `skipped` → neither. `halfCloseBeforeRead` adds one extra
    `close()` (the flush) before the release. The tests ticket pins these.
- `Stream` is a `TypedEventTarget` with `drain: Event` in its events map;
  `writableNeedsDrain: boolean` (`@libp2p/interface` `message-stream.d.ts:42,116,126-128`).
