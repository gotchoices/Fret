## Naming (raised by the source ticket, implementer's call — state the choice in the handoff)

The original plan suggested `test/rpc.two-transport-integration.spec.ts`. The block being extracted
is *itself* fault-isolation content: the file's header comment names three tiers — unit, service,
**wire** — and the two transport `describe`s are that wire tier (the malformed-shape matrix plus
stream-release accounting, driven over real nodes instead of stubs). "Two-transport integration"
names the mechanism and drops the subject.

`test/rpc.two-node-framed.spec.ts` was checked and is **not** the natural home: its subject is that
a reply actually written is never reported as cut off, driven across a spread of reply timings — a
different claim from stream release under malformed input.

Recommendation: `test/rpc.handler-fuzz.wire.spec.ts`, which keeps the fault-isolation identity and
says which tier moved. For the other file, `test/rpc.snapshot-merge-cap.spec.ts`.

## Edge cases & interactions

- **Pure move.** Every `it` in both extracted blocks must still exist, still pass, and still assert
  the same things. Count `it(` per section before and after.
- **The `unhandledRejection` guard must be copied, not shared.** It is registered on the top-level
  `describe` (lines 249–259) precisely because a file-top-level hook would be a mocha *root* hook
  and would run against the whole suite. Each new file needs its own `describe`-scoped copy, or it
  silently loses the "no case may leak a rejection" guarantee.
- The three-tier header comment (lines 22–37) describes a file that will no longer hold three
  tiers. Update it in `rpc.handler-fuzz.spec.ts`, and give each new file a header saying what it
  owns and pointing back. These comments are load-bearing documentation here, not decoration.
- The extraction strands imports in the source file — at minimum `createIdentifyNode`,
  `makeSnapshotParser`, `isFrameTruncationError`, and some of the wire types. `npx tsc --noEmit` is
  the cheapest way to find them **only if `noUnusedLocals` is on** in `packages/fret/tsconfig.json`
  — check; if it is off, sweep the removed symbols by grep instead.
- `packages/fret/.mocharc.json` is `{"require": ["test/mocha-exit-watchdog.ts"]}` — **no spec list**.
  Discovery is the test script's glob, `test/**/*.spec.ts`. New `*.spec.ts` files are picked up with
  no config change. (Checked; do not re-check.)
- The two transport `describe`s start real libp2p nodes per test. Splitting them into their own
  file does not change how many nodes run at once, but it does mean the exit watchdog now judges
  that file on its own — a handle leak there fails that file's run rather than hiding in the larger
  one.
