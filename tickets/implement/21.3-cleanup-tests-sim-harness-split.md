## Resolved module design (from investigation; seams match the code as of 89ce4c5)

Four new modules under `test/simulation/`, each standalone (no imports back into
`fret-sim.ts` — use small structural types / injected predicates instead, so there are no
import cycles):

- **`placement.ts`** — `PlacementStrategy`, `ClusterConfig` types move here;
  `CoordPlacement` class owning `generateCoord`/`uniformCoord`/`randomCoord`/
  `clusteredCoord`/`skewedCoord` and the `clusterCenters` state. Constructor takes
  `(rng: DeterministicRNG, opts: { placement?, clusterConfig?, n })` and generates cluster
  centers itself when strategy is `clustered`.
  **Determinism constraint (critical):** RNG call order must be byte-identical. Today the
  centers are drawn (`rng.nextBigInt(256)` × numClusters) in `FretSimulation`'s constructor
  *after* the bus is created (bus constructor consumes no RNG). Construct `CoordPlacement` at
  exactly that point so same-seed runs replay identically.
  `uniformCoord`'s hand-rolled big-endian byte loop is byte-identical to `helpers/ring.js
  toCoord(val)` (verified: toCoord writes 32-byte big-endian, mod 2^256; uniformCoord's val is
  always < 2^256) — may DRY it to `toCoord`, optional.
- **`reachability.ts`** — `PartitionModel` class: the `partitionOf` map,
  `crossPartitionBlockedCount`, `partition(groups)` (validation via a
  `hasPeer: (id) => boolean` predicate injected at construction), `heal()`, `blocked()`,
  `reachable(a,b)`, `contactAllowed(a,b)`, plus two small accessors measurement needs:
  `isActive(): boolean` and `groupOf(id): number` (today `snapshotCoverage` reads
  `partitionOf` directly). Move the full doc comments (partition semantics, refusal-counting
  distinction) onto the model; `FretSimulation.partition/heal/crossPartitionBlocked` stay as
  public delegates with one-line docs.
- **`liveness.ts`** — export the `notDead` predicate (used by core, snapshots, routing pool,
  and measurement) and a `LivenessModel` class owning `contactSweep`, `reprobeDeadEntries`,
  `recordContactFailure`, `recordContactSuccess`. Constructor:
  `(cfg: { deadAfterFailures, deadReprobePerTick }, deps: { contactAllowed(a,b),
  isAlive(id) })`. `contactSweep`/`reprobeDeadEntries` only ever use `peer.id` from the
  SimPeer they receive — take `selfId: string` instead, killing the SimPeer coupling.
  `isAlive` covers the prune arm (`!p || !p.alive` → remove). This is the ticket's
  "reachability and liveness interact" edge case: liveness consumes the reachability model
  only through the injected `contactAllowed` predicate — no hidden copy of partition state.
  `recordContactFailure`/`recordContactSuccess` stay public on the model because
  `handleRoute` (staying in fret-sim) calls them — the shared-escalation invariant the doc
  comments describe.
  Update `contactSweep`'s doc comment's "handleRoute strikes through the same
  recordContactFailure" wording to name fret-sim.ts now that it's cross-module.
- **`measurement.ts`** — `SimMeasurement` class with `snapshotCoverage()` and
  `deadNeighborRatio()`. Constructor deps: `{ peers: ReadonlyMap<string, MeasurablePeer>,
  stores: ReadonlyMap<string, DigitreeStore>, m: number, partition: PartitionModel }` where
  `MeasurablePeer = { id, coord, alive }` is a local structural type (SimPeer is assignable;
  avoids importing fret-sim). The maps are stable references mutated in place, so
  construct-once injection is safe. `FretSimulation.snapshotCoverage/deadNeighborRatio`
  remain public delegates.
- **`fret-sim.ts` keeps**: `SimPeerConfig`, `EDGE_PROFILE`, `CORE_PROFILE`, `ProfileMix`,
  `SimPeer`, `SimConfig`, and `FretSimulation` composing the four modules — event
  dispatch/scheduling, stabilize tick, snapshot exchange (bus + direct), churn/join/leave,
  `enforceCapacity`, routing (`handleRoute`, `nearRadiusFor`), `aliveCount`, getters.
  Re-export `PlacementStrategy` / `ClusterConfig` from `./placement.js` so spec imports are
  untouched.
