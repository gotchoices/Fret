## Why these three tests and not others

The tests that landed apply the parser **by hand inside the test body**. That is enough to keep the
suite honest about the caps' *values*, but it restates the wiring rather than proving it: unwire
the parser at `fret-service.ts:1033` and every existing test still passes. And the fetch path has
no cap test at all — the claim that its removed slice was redundant currently rests on reading the
code.

Assert on **counted loop work** (a spy wrapping `store.upsert`, the pattern `countUpserts` in the
fuzz spec's `describe('announce snapshot merge caps')` block already uses), not on the absence of a
crash. A cap that silently stopped applying would leave a passing no-crash test and an unbounded
per-message cost.

## Known complications — established, do not re-derive

- `handleAnnounce` **detaches** the merge, so an upsert count taken around the handler call is not
  deterministic. Wrap `mergeAnnounceSnapshot` on the instance to capture and await the promise it
  returns; the snapshot argument still arrives through the real parser that way.
- The neighbors handler's `onInbound` callback runs `noteInboundRpc(from)`, which **also upserts
  `from`** — detached, racing the merge's own first upsert. It is guarded by
  `if (!this.store.getById(id))`, so pre-seeding `from` into the store before the test makes it
  short-circuit and the count deterministic.
- `registerRpcHandlers` is private and registers all five protocols; it can be called directly on
  an unstarted service via a cast. **Do not `start()`** — stabilization and peerStore seeding drag
  their own upserts into the counter.
- The `fakeNode()` / `invoke(protocol, stream, remote)` rig at `test/rpc.handler-fuzz.spec.ts:214`
  records handlers instead of registering them, which is the cheap way to invoke one directly. Its
  node stub has **no `peerId`**, and `enforceCapacity` / `applyTouch` both reach
  `selfCoord()` → `hashPeerId(this.node.peerId)` — so either give the stub a real peer id or patch
  `handle` on a real mem node instead.
- `replyStream(reply)` and `nodeReplying(stream)` at `test/rpc.codec-properties.spec.ts:1772-1795`
  are the shape to copy for a stub node that serves exactly one framed reply.
- `test/announce-rate-limit.spec.ts:154-162` owns the caps-are-one-source-of-truth claim
  (a deep-equal against the literal Core/Edge numbers). Leave it alone; do not restate those
  numbers anywhere else.
