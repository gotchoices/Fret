## Design

### Validators are parsers, not type guards

```ts
type Parser<T> = (msg: unknown) => T | undefined;   // undefined = reject this message
```

**Not** `msg is T`. Two of the five messages must *normalize* as they check — truncate an over-long id
list, drop a malformed sample entry, drop an advisory field of the wrong type — and a type guard cannot
express that without mutating its argument. Returning the normalized message makes the narrowing and the
normalization one step, so no caller can consume an unnormalized value.

`validateRouteAndMaybeAct` is the one worth calling out: it normalizes nothing, so keeping it a type
guard is defensible. Its call site (`fret-service.ts:1152`) is `if (!validate(msg)) reject`, which works
identically against a `Parser` that returns the message on success. Converting it keeps the module
uniform; keeping the guard avoids touching the call site and the fuzz spec. **Pick one and say which in
the handoff** — either is acceptable; drifting between the two within one module is not.

They live in one new module, `src/rpc/validate.ts`, with the shared primitives (`isPeerIdString`,
`boundedStringArray`, `finiteNumberOr`). `validateRouteAndMaybeAct` **moves** there from `maybe-act.ts`
and `sanitizeReplacements` **moves** there from `leave.ts` — one module so a reader finds every
wire-shape rule in one place, and so the maybeAct-only `NOTE:` in that function can be deleted rather
than restated.

All are pure and O(message size): no hashing, no ring walks, no libp2p dialing. `isPeerIdString` calls
`peerIdFromString` in a `try`, which is parse-only and already what `sanitizeReplacements` does.

`v` is deliberately **not** checked on any message. Nothing negotiates versions today, and a hard reject
on an unexpected `v` would make a future v2 rollout fail closed at exactly the peers that have not
upgraded. Stated, not overlooked.

### Per-message parsers, and the reject rule for every field

**`NeighborSnapshotV1`** — `makeSnapshotParser(caps)`, a factory over
`{ successors: number; predecessors: number; sample: number }` so the truncation caps and the service's
merge caps cannot drift (`15.33` builds it from `mergeSnapshotCaps()`):

| field | rule | on violation |
|---|---|---|
| `from` | string **and** parses as a peer id | reject message |
| `timestamp` | finite number | reject message |
| `successors`, `predecessors` | absent → `[]`; array → **truncate to `caps.successors` / `caps.predecessors` first**, then drop non-string entries | truncate / drop entry |
| `sample` | absent → `[]`; array → truncate to `caps.sample`, then **skip-and-log per entry**: `id` string, `coord` decodes via `base64urlToCoord` to exactly 32 bytes, `relevance` finite | drop entry |
| `size_estimate`, `confidence` | optional finite numbers | drop the field (advisory; already gated by "both positive" downstream) |
| `metadata` | non-null non-array object | drop the field (matches today's `isPlainObject` receiver check) |
| `sig` | unchecked (unused; message signing is unimplemented) | — |

Truncate rather than reject for the id lists: the merge loops already `slice` to these exact caps, so
truncating at the parser changes **no** behavior — it only moves the cost before the parse+hash loop
instead of after. Rejecting the whole message would be a new behavior that punishes an honest peer
running a larger profile. The per-entry skip-and-log on `sample` is today's rule and is kept
deliberately (`importTable`'s all-or-nothing rule is the *other* case and is not touched).

**`LeaveNoticeV1`** — `parseLeaveNotice`: `from` string and parseable peer id, `timestamp` finite;
either wrong → reject message. `replacements` → the moved `sanitizeReplacements`.

**`RouteAndMaybeActV1`** — the existing checks, unchanged, plus one gap the plan named: `digest` is
type-checked but uncapped. Add `MAX_DIGEST_CHARS = 4096`, alongside the existing key / correlation-id
caps, and enforce it.

**Reply parsers.** The machinery to use them is `rpcRequest`'s `decode` callback, which `15.33` wires;
this ticket writes the parsers themselves.

- `parsePingResponse`: `ok` must be a **boolean** (replacing today's `Boolean(r.ok)` coercion — a legal
  value always encodes as a boolean, so the coercion only ever hid a malformed peer);
  `size_estimate` / `confidence` optional finite, dropped individually if not.
- `parseNearAnchor`: `anchors` and `cohort_hint` arrays of strings, capped at **8** and **16** — twice
  the largest lists the producers emit, so the cap cannot refuse our own legal output;
  `estimated_cluster_size` and `confidence` finite. Missing arrays normalize to `[]`, since an emptied
  anchor list already falls back to the local cohort.
- `parseMaybeActReply`: the reply is `NearAnchorV1 | { commitCertificate: string }` — discriminate on
  `commitCertificate` being a string first, else parse as a NearAnchor.

### Edge cases the parsers must survive

- **Round-trip property must hold**: every value `encodeJson` can produce from a legal message must
  survive its own parser. In particular `undefined` is dropped on encode, so an optional field can only
  ever arrive *absent* — a parser that rejects a missing optional, or that requires `null` where
  `undefined` was meant, breaks a valid round trip. Also: a legal `-0` arrives as `0` and a legal
  non-finite arrives as `null`; no field admits either, but a `Number.isFinite` check on a `null` must
  reject rather than throw.
- An array at exactly the cap (kept whole), one over (truncated to the cap, message still accepted), and
  one entry that fails to parse inside an otherwise valid array (that entry dropped, message still
  accepted). All three for `successors`, `predecessors` and `sample`.
- A `null` inside a `successors` array is a string-check failure (drop entry), not a throw.
- A `sample` entry whose `coord` decodes to the wrong byte length must be dropped by the parser. The
  store's write seam already throws on a non-32-byte coordinate, and a throw inside the merge loop is
  exactly the leak the handler seam was built to stop.
- No parser may **throw** on any input. A fuzzed field of any type returns `undefined` or a normalized
  value.

## Key tests to expect

Extend `test/rpc.codec-properties.spec.ts` (see *Verified facts* for why the existing arbitraries cannot

- The round-trip property: for generated **legal** instances of all five wire types plus both reply
