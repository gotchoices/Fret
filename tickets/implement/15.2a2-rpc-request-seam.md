## Contract under test (from the core ticket — the spec, not a suggestion)

`rpcRequest(node, peer, protocol, opts) → Promise<RpcOutcome<T>>` never throws for a network
outcome; it throws only for caller bugs (malformed peer id, `dial: 'if-addressed'` without
`isDialable`). Classification order on any transport failure (open/write/read): caller's signal
aborted → `cancelled`; `isUnsupportedProtocolError` → `foreign-protocol`;
`isFrameTruncationError` or message starting `payload too large` → `decode-error`; deadline
(`d.signal.aborted` / `DeadlineExpiredError`) → `timeout`; else `unreachable`. Decode phase
(including `decodeJson`'s `empty response` / `whitespace response` / `non-object JSON payload`
and the caller's `decode` callback throwing) → `decode-error`, with the caller-signal check
still first. Busy shape (`{busy: true}`) short-circuits **before** `opts.decode` runs.
`readFramed` is called with `timeoutMs: Infinity` + the helper deadline's signal — one clock.

## Key tests (`test/rpc.request.spec.ts`, new)

Drive `rpcRequest` against stub streams:

- **Failure shapes → variants:**
  - reset mid-stream (iterator rejects) → `unreachable`, error surfaced
  - tidy close mid-JSON (chunk then EOF mid-frame) → `decode-error`
  - EOF before any bytes → `decode-error` (proof of life — peer opened and closed cleanly;
    generalizes `sendPing`'s no-strike behavior)
  - empty frame (prefix `0x00`) → `decode-error` (`decodeJson` `empty response`)
  - non-object JSON top level (e.g. framed `[1,2,3]`) → `decode-error`
  - over-cap reply (declared length > `maxBytes`) → `decode-error` (`payload too large`)
  - bytes then silence until the budget → `timeout`, bounded (~budget, not eventual)
  - `UnsupportedProtocolError` thrown from the open → `foreign-protocol`
  - **`UnsupportedProtocolError` surfacing at the read** (negotiateFully: false defers it —
    the classification correction in the core ticket) → `foreign-protocol`, not `unreachable`
  - framed `{busy: true, retry_after_ms: 500}` → `busy` with `retryAfterMs === 500`, and a
    `decode` callback that throws if invoked proves busy short-circuits it
  - a `decode` callback that throws on a good frame → `decode-error`, stream not leaked
  - whole framed reply + `decode` → `ok` with the decoded value and `rttMs >= 0`
- **Cancellation vs timeout (must never swap):**
  - caller signal aborted **before** the call → `cancelled`, and **no dial issued** — assert
    the fake node's `getConnections`/`dialProtocol`/`newStream` were never called
  - abort **during the open** → `cancelled` (needs a signal-honoring `newStream` stub — one
    that ignores the passed signal hangs the test; reject from an `abort` listener on
    `opts.signal`)
  - abort **during the read** (stub `onNext` hook, call 2) → `cancelled`
  - budget expiry with a live caller signal → `timeout`
- **Release exactly once on every path above, with the arm deterministic** (single clock now):
  `timeout`/`cancelled` → `{ closes: 0, aborts: 1 }`; `ok`/`busy`/`decode-error`/`unreachable`
  → `{ closes: 1, aborts: 0 }`; `skipped` → `{ closes: 0, aborts: 0 }`. `halfCloseBeforeRead:
  true` adds one flush close (so `closes: 2` on its ok path). This is what lets `15.2b`
  collapse `rpc.stream-errors.spec.ts`'s two release-arm helpers into one expectation.
- **Dial modes:**
  - `'never'` with no connection → `skipped`, dial method never called
  - `'if-addressed'` with `isDialable` false + no connection → `skipped`, no dial attempt
  - `'if-addressed'` with `isDialable` false + an **existing connection** → proceeds (the
    connection is reused; dialability only gates the dial)
  - `'always'` with no connection → `dialProtocol` called
  - `'if-addressed'` without `isDialable` → throws (caller bug); malformed peer string →
    throws (rejects) rather than returning an outcome
- **Backpressure:** `send()` returning `false` is followed by a bounded drain wait —
  - a stub that never drains → `timeout` within the budget (not a hang)
  - one that fires `drain` (~20 ms) and clears `writableNeedsDrain` → proceeds to `ok`
  - one that fires `drain` while `writableNeedsDrain` stays `true`, then fires again after
    clearing it → still `ok` (pins the re-check loop)
  - a plain stub with no `writableNeedsDrain`/event surface and `send()` → `false` → the drain
    wait is skipped entirely (guard case; keeps old-style stubs viable)
- **Write-only** (`decode` absent): `ok` with `value === undefined`; body was written (stub
  `sends === 1`); a `send()` that throws → `unreachable` (write-side reset), released once.
- **No unhandled rejection escapes** any case — describe-scoped `unhandledRejection` hook.

Four contract details read off the landed code that sharpen the test expectations above — none
contradict the plan, they just say which branch applies where:

- **The release table's `cancelled` row has two cases.** A caller signal already aborted *before*
  the call returns `cancelled` having opened nothing, so the release counters are
  `{ closes: 0, aborts: 0 }`, not `{ closes: 0, aborts: 1 }`. The `aborts: 1` expectation holds
  only once a stream exists (abort during open / read). Assert per case, not one table row.
- **The write-only path returns before the read.** So `halfCloseBeforeRead: true` combined with a
  missing `decode` also yields `closes: 2` (the flush close plus the release close), same as the
  read path — the flush is not read-path-specific.
- **Busy is tested on the parsed value, `decode` still receives the raw bytes.** `decodeReply`
  parses with `decodeJson(bytes)`, checks the busy shape on that, and only then calls
  `opts.decode(bytes)` — so a `decode` that parses again is the accepted double parse, and a
  `decode` that throws-if-invoked genuinely proves the short-circuit.
- **A drain wait that never drains rejects rather than resolving**, so it lands in `writeBody`'s
  catch and goes through the shared `classify`: deadline expiry → `timeout`, caller abort →
  `cancelled`. That is the intended path for the "never drains" case; there is no separate
  drain-specific outcome to look for.
