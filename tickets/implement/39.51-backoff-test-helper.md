## Two cases to add to `probe-backoff.spec.ts`

Both came out of the review of `probe-backoff-class`: behaviours the class has today that the spec
describes nowhere.

- **Two failures inside one still-open window escalate.** `record` looks only at whether an entry is
  retained, not at whether its window is still open, so a second failure at the same instant doubles
  `factor` and pushes `until` further out. Faithful to the service code it was extracted from — the
  >= 500 ms spacing rule guards `contactFailures`, never the backoff map — but nothing asserts it,
  so a future "ignore a failure inside the open window" change would pass the suite. Pin today's
  behaviour: `record('a')` twice with no `clock.advance` between, assert `factor('a') === 2` and
  `until` (inferred via `isBackedOff` staying true well past the first window's `baseMs`) reflects
  the second call's later stamp.
- **`factor` after `clear` is 0, and the next failure restarts at 1.** The existing `clear` case
  (`forgetting` describe block, lines 185-196) checks `factor` is 0 but never records again, so it
  does not distinguish "forgotten" from "retained at 0". Add the follow-up `record` assertion after
  `clear`, mirroring what `forgets the escalation once retainMs elapses...` (lines 110-124) already
  does at its end.

**Ready-to-paste code for both cases** (add inside `describe('escalation', ...)` in
`probe-backoff.spec.ts`, after the `'doubles on each further failure...'` case at line 72, i.e.
insert before line 74's `it('caps at maxFactor...')`):

```ts
		it('two failures inside one still-open window both escalate', () => {
			const { backoff, clock } = makeBackoff()
			backoff.record('a')
			expect(backoff.factor('a')).to.equal(1)

			// No clock.advance — second failure lands inside the first window.
			backoff.record('a')
			expect(backoff.factor('a')).to.equal(2)

			// The second call's later stamp pushed `until` out too: still backed off well past
			// where the *first* call's window alone would have closed.
			clock.advance(BASE_MS - 1)
			expect(backoff.isBackedOff('a')).to.equal(true)
		})
```
