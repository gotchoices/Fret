## Discovery — read, don't re-derive

### The seam's drop paths (`src/rpc/protocols.ts`, `registerJsonHandler` implementation)

Request overload, in order:

- `readFramed(stream, opts.maxBytes)` throws (truncation, over-cap) → propagates into
  `registerRpcHandler`'s error arm → **abort**.
- `decodeJson(bytes)` throws → `opts.onMalformed?.('decode')`, log, `return` → seam's budgeted
  **close**, no reply.
- `opts.parse(decoded)` returns `undefined` → `opts.onMalformed?.('parse')`, log, `return` →
  **close**, no reply.
- `opts.serve(...)` returns `undefined` (the identity-mismatch drop) → `return` → **close**, no
  reply. `onMalformed` is *not* called on this path.

Reply-only overload reads no body: it has no decode, no parse, no `onMalformed` at all.

### Exact `register*` signatures (all positional)

```ts
registerLeave(
  node, onLeave, protocol = PROTOCOL_LEAVE,
  onIdentityMismatch?: (claimed: string, actual: string) => void,
  onMalformed?: (reason: 'decode' | 'parse') => void
)

registerPing(node, protocol = PROTOCOL_PING, getSizeEstimate?, onInbound?)   // reply-only

registerNeighbors(
  node, getSnapshot, onAnnounce?, protocols, maxBytes,
  onIdentityMismatch?, onInbound?,
  snapshotParser = makeSnapshotParser({successors: Infinity, predecessors: Infinity, sample: Infinity}),
  onMalformed?
)
```

`registerNeighbors` registers the *request* protocol reply-only and the *announce* protocol on the
request overload — so `snapshotParser` / `onMalformed` only ever affect announce. The `NOTE:` at
the defaulted `snapshotParser` states why it stays defaulted; do not change the signature.

**Consequence worth stating: ping and the neighbors request have no body-level drop path at all.**
Any "malformed message" case for those two protocols is necessarily frame-level (abort), never a
parser drop. That is why the field matrix in the sibling ticket covers only leave and announce.

### `src/rpc/validate.ts` — which field wrongness rejects vs normalizes

- `parseLeaveNotice`: rejects when `from` is not a parseable peer id, or `timestamp` is not finite.
  Normalizes `replacements` through `sanitizeReplacements` (non-array → absent; ≤ 12; each entry
  parse-checked; empty result → field deleted).
- `makeSnapshotParser(caps)`: rejects on unparseable `from` or non-finite `timestamp`. Normalizes
  `successors` / `predecessors` (`boundedStringArray`: non-array → `[]`, truncate to cap *then*
  drop non-strings), `sample` (`parseSample`: truncate to cap, then per entry require object +
  string `id` + string `coord` + finite `relevance` + `base64urlToCoord(coord)` not throwing,
  skip-and-log otherwise), and drops `size_estimate` / `confidence` / `metadata` individually when
  the wrong type. `v` and `sig` are deliberately unchecked.

## Tests to add

These are the three cases `15.32` most needs pinned — the pair of counters it has to keep distinct.

- **`onMalformed`'s `reason` argument, asserted by value and not merely by call count.**
  `'decode'` for a body that is not JSON *and* for one that decodes to a non-object (both go
  through `decodeJson` throwing); `'parse'` for a body that decodes to an object the parser
  rejects. Nothing currently pins which value each path passes, so the two could be swapped
  silently — and the service wires the hook to a counter it intends to split by reason later. One
  case per value, over the unit rig, on both `registerLeave` and the announce half of
  `registerNeighbors`. Assert the drop is a **close** (not an abort) and that no reply was sent.
- **`from` that is not a parseable peer id**: dropped, the malformed counter increments,
  `identityMismatch` does **not**. This is a `'parse'` rejection — the parser runs before `serve`,
  so `onIdentityMismatch` is never reached.
- **`from` that is a parseable peer id but not the authenticated sender**: dropped,
  `identityMismatch` increments, malformed does **not**. This is the `serve`-returns-`undefined`
  path, which calls neither `onMalformed` arm.
- **`registerNeighbors`' defaulted `snapshotParser` is exercised at least once.** Omitting the
  trailing parameters builds a parser with `Infinity` caps — "validate the shape, truncate
  nothing". Every production caller supplies one, so the default is untested today. Assert both
  halves: a malformed snapshot (unparseable `from`) is still rejected, so shape checking is live;
  and an id list far longer than any profile cap is merged **whole**, so nothing truncates.
  Omitting `snapshotParser` means also omitting `onMalformed` (it is the parameter after it), so
  assert the rejection through the drop's observable effects — close, no reply, `onAnnounce` never
  ran — rather than through the hook.
