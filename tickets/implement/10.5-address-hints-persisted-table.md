# Addresses in the saved routing table (restart half)

Fixes gotchoices/sereus#18: Optimystic's db-p2p saves and restores the FRET table (`exportTable` / `importTable`, `NodeOptions.persistence`), but the table holds no addresses, so two relay-only parties that restart re-import each other's ids, cannot dial them, and each ring contains only itself.

The prereq `address-hints-live-exchange` adds `PeerEntry.addressRecord?: { envelope: Uint8Array; confirmedAt: number }` (a verified libp2p signed peer record plus the local time it was accepted), `peekPeerRecord` in `src/service/address-records.ts`, and the `setAddressKnown` / `diag.rejected.addressHint` plumbing. This ticket serializes that field and restores it.

## Design

**Serialized shape** — `SerializedPeerEntry.addressRecord?: { envelope: string /* base64url */; confirmedAt: number /* unix ms, local clock */ }`. Optional, so tables written before this change still import. `SerializedTable.v` stays `1`.

**Export** (`FretService.exportTable`, post-processing `store.exportEntries()` — the store serializes the field mechanically; freshness is service knowledge):
- For a peer connected at export time, write `confirmedAt = now` (a live connection is the confirmation).
- Omit the record when `now - confirmedAt > ADDRESS_RECORD_PERSIST_MAX_AGE_MS`.
- New constant `ADDRESS_RECORD_PERSIST_MAX_AGE_MS = 14 days`, beside the forwarding window in `address-records.ts`. Reasoning, to state at the constant: a failed relayed dial costs seconds (Sereus measured up to 14 s at a 3 s link round trip), so dead addresses slow every restart; 14 days covers a node that was switched off for a holiday, which is the case #18 is about. No separate count cap: the table capacity (Core 2048 / Edge 512 max) already bounds it — see the tripwire below.

**Import** (`FretService.importTable`), keeping the rule that a corrupt table is refused whole and nothing is written:
1. Pre-pass over the (self-filtered) entries, before any store write: for each `addressRecord`, base64url-decode and `peekPeerRecord`; undecodable, or `signer`/`peerId` ≠ the entry's `id` → **throw** (corrupt table). A `confirmedAt` later than now is clamped to now (clock went backwards, or tampering — tampering is `tickets/backlog/23-debt-routing-table-export-signing.md`'s concern). Older than the persist age → drop the field (stale, not corrupt).
2. `store.importEntries` restores `addressRecord` (decoding happens in its existing decode-everything-first loop, so a malformed base64 still rejects before any write).
3. `enforceCapacity()` as today.
4. For each surviving entry with a record: `node.peerStore.consumePeerRecord(envelope, { expectedPeer })`. `true` → `setAddressKnown(id, true)`. Throw (bad signature — structure was fine, so this is tampering) → strip the record from the entry via `store.update`, count `diag.rejected.addressHint`, log; it never reaches the peerStore. `false` → the peerStore already holds an equal-or-newer record; keep the entry's copy.
   - The peerStore is not Startable, so this works whether `importTable` runs before or after `start()`.
   - Signature verification happens only here (inside `consumePeerRecord`), once per record — the pre-pass is structural and has no crypto.

**Self** is already dropped from an imported table; nothing changes.

## Edge cases & interactions

- **Restart, relay-only pair** — the reproduction. *Test* in `service.table-persistence.spec.ts` (memory transport is enough; the relay path is covered by the prereq): node A connects to B, the record is mirrored onto B's entry (identify), A exports; a fresh libp2p node A′ with its own new peerStore imports the table, and `A′.dial(B.peerId)` succeeds **with no network exchange before it**. Negative control in the same `it`: the same table with `addressRecord` stripped imports fine and the dial rejects with `NoValidAddressesError`.
- **Tampered envelope in the file**: structural damage → whole import refused, store untouched (*extend the existing corrupt-coordinate case into the same table-driven test rather than a new `it`*); valid structure but bad signature → that entry's record stripped, peerStore unchanged, rest of the table imported. The second arm is inspection-level unless the table-driven case takes it for free.
- **Record for a peer evicted by the post-import capacity pass**: not consumed (step 4 walks surviving entries). Inspection.
- **Pre-change table** (no `addressRecord` anywhere): imports exactly as before. Covered by existing persistence tests staying green.
- **Round trip**: `exportTable` → `JSON.stringify` → `JSON.parse` → `importTable` preserves the envelope bytes; extend the `SerializedTable` generator in `rpc.codec-properties.spec.ts` with the optional field rather than adding a test.
- **Import latency**: one signature verify plus one peerStore write per persisted record, awaited. Leave a `NOTE:` tripwire at the loop: if Edge start-up shows it, consume only the ring window around self synchronously and detach the rest.
