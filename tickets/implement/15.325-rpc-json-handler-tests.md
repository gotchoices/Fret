## What the prior run already established (don't re-derive)

**The seam.** `registerJsonHandler` is at `src/rpc/protocols.ts:193` (overload declarations) with
the implementation immediately below, stacked on `registerRpcHandler` at line 111. The body-level
drop path in the implementation is exactly:

- `decodeJson(bytes)` throws → `opts.onMalformed?.('decode')`, log, `return` (no reply).
- `opts.parse(decoded)` returns `undefined` → `opts.onMalformed?.('parse')`, log, `return`.
- `opts.serve(...)` returns `undefined` → `return` with no reply (the identity-mismatch drop).

All three fall through to `registerRpcHandler`'s budgeted success `close()`. Frame-level failures
(`readFramed` throwing: truncation, over-cap) propagate into the error arm, which `abort()`s.

**Who is on the seam.** neighbors *request* and ping take the reply-only overload (no body read at
all); announce (`makeSnapshotParser`) and leave (`parseLeaveNotice`) take the request overload.
maybeAct is deliberately **off** the seam — its rate-limit bucket must be taken before any
per-message work.

**`registerNeighbors`' signature**, positional, from `src/rpc/neighbors.ts`:
`(node, getSnapshot, onAnnounce?, protocols, maxBytes, onIdentityMismatch?, onInbound?,
snapshotParser = makeSnapshotParser({successors: Infinity, predecessors: Infinity, sample: Infinity}),
onMalformed?)`. The `NOTE:` at that defaulted parameter states why it stays defaulted.

## Tests to add

- For **every** inbound wire message and every field: wrong type, missing, and over cap. The
  message must be dropped without throwing out of the handler, without leaking the stream, and the
  existing release-exactly-once invariants must hold — **close** on a body-level drop, **abort** on
  a frame-level failure. Assert the *arm*, not merely the release count; the count alone passes for
  both arms and so proves nothing about the rule.
- A snapshot carrying more ids than the profile cap: assert the parse+hash+upsert loop runs exactly
  `caps.*` times, **by counting the loop's work** — a spy on the store's `upsert` or on the hash —
  rather than by inferring it from the absence of a crash.
- `from` that is not a parseable peer id: dropped, `diag.rejected.malformed` incremented,
  `identityMismatch` **not** incremented.
- `from` that is a parseable peer id but not the authenticated sender: dropped,
  `identityMismatch` incremented, `malformed` **not** incremented.
- A `sample` entry with a short `coord`: that entry dropped, the rest of the snapshot merged.
- **`onMalformed`'s `reason` argument is asserted, not just its call count.** `'decode'` for a body
  that is not JSON (or decodes to a non-object), `'parse'` for a body that decodes but the parser
  rejects. Nothing currently pins which value each path passes, so the two could be swapped without
  a test noticing — and the service wires the hook to a counter it intends to split by reason later.
  One case per value, over the existing rig.
- **`registerNeighbors`' defaulted `snapshotParser` is exercised at least once.** Omitting the
  trailing parameter builds a parser with `Infinity` caps — "validate the shape, truncate nothing".
  Every current production caller supplies one, so the default is untested: assert that a call
  omitting it still rejects a malformed snapshot (shape checking is live) and merges an over-cap id
  list whole (no truncation).

The last three are the pair of counters `15.32` has to keep distinct, so they are the tests most
worth writing first.
