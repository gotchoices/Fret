  `opts` is `{ closeBudgetMs?: number } & StreamCaps`, and the function passes

## The test to write

Register a handler at a deliberately small cap — call `registerRpcHandler` **directly** with e.g.
`maxInboundStreams: 2` — and drive N+1 concurrent inbound streams on **one** connection between two
in-memory nodes. Assert the excess stream is refused, and record what the sender's `RpcOutcome`
actually is.

This one case pins three things at once: that the caps reach `node.handle` at all; the exact
off-by-one; and that a remote's inbound refusal surfaces to the sender as `unreachable` — the
residual the sibling `local-limit-rpc-outcome` ticket documented — so if a future libp2p version
*does* propagate the reason, this test fails and the residual gets revisited.

**The off-by-one must be pinned by observation, not by reading libp2p's source.** The comparison is
`streamCount > limit` over `connection.streams` filtered by protocol and direction (`countStreams`
in libp2p's `connection.js`), and whether the stream being admitted is already in that collection at
check time was never verified — so whether the cap admits `limit` or `limit + 1` concurrent streams
is *unknown*. Write the assertion against what the run does. Do not derive the number from the
library source and then assert it.

## Test-harness facts already gathered

- `packages/fret/test/helpers/libp2p.ts` exports `createMemoryNode()` (TCP + noise + yamux),
  `createMemNode(addr?)` (memory transport + plaintext + yamux, auto-incrementing `/memory/...`
  listen addr), `createIdentifyNode()`, `connectLine(nodes)`, `stopAll(nodes)`,
  `toMultiaddrs(node)`. `createMemNode` is the cheap two-node option; `createMemoryNode` is the
  real-transport one if the memory transport turns out not to enforce per-connection stream
  counting.
- `packages/fret/test/helpers/rpc-fuzz.ts` holds the shared inbound fixtures used by the
  handler-fuzz / merge-cap specs: `inboundStub`, `json`, `peerIdStr`, `sampleCoord`, `sleep`,
  `NETWORK`, `P`, and the `InboundHandler` type.
- House pattern for a spec that must not leak rejections (copy, do **not** share-import — a shared
  hook would become a root hook covering the whole suite): a per-`describe`
  `const unhandled: unknown[] = []` with `before`/`after` installing and removing a
  `process.on('unhandledRejection', ...)`, and an `afterEach` that `await sleep(20)` then asserts
  the drained array is empty. See the top of `test/rpc.snapshot-merge-cap.spec.ts`.
- Holding N+1 streams concurrently needs a handler that blocks until released — gate the `serve`
  body on a deferred the test resolves, the way `test/inflight-concurrency.spec.ts` gates its
  activity handler.
