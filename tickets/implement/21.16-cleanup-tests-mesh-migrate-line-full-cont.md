## `proactive-announce.spec.ts` — migrate these four sites

All four rigs construct services **first**, then dial. Preserve that order exactly — dialing
after `start()` means the ring is discovered through `peer:connect`, and the file's own NOTE
(lines 9-15) says several specs depend on this ordering being deliberate. Use `buildMesh` +
`addServices` + `connect`, in that order, everywhere below (never `starMesh` — none of these
match its baked-in edge/k7/star shape verbatim, and all need `profile: 'core'`).

- **`:19-33`** (`on-start announce fires after first stabilization tick`) — 3 nodes, core-profile
  services bootstrapped off node 0, then a genuine line. →
  ```ts
  const mesh = await buildMesh(3)
  await mesh.addServices({ profile: 'core', k: 7, bootstraps: [mesh.ids[0]!] })
  await mesh.connect('line')
  ```
  Note: original bootstraps every node (including node 0) at `[nodes[0].peerId.toString()]`
  literally — i.e. node 0 bootstraps off itself. Preserve that literally (don't special-case
  `i === 0` the way `starMesh` does) since it's what the test exercised. Replace the trailing
  `Promise.all(services.map(s => s.stop())); stopAll(nodes)` with `mesh.stop()`.

- **`:51-66`** (`peer disconnect triggers proactive announcement to remaining neighbors`) — 5
  nodes, same bootstrap-off-node-0-literally pattern, then full mesh. Node 2 is stopped mid-test
  (`await nodes[2].stop()`), so teardown must skip it. →
  ```ts
  const mesh = await buildMesh(5)
  await mesh.addServices({ profile: 'core', k: 7, bootstraps: [mesh.ids[0]!] })
  await mesh.connect('full')
  ```

  the libp2p node, matching the original — the original never stops `services[2]` explicitly,
  it just stops the node out from under it). Replace `services[i]`/`nodes[i]` array indexing
  throughout the test body with `mesh.services[i]!`/`mesh.nodes[i]!`. Final teardown:
  `await mesh.stop({ skip: [2] })`.

- **`:96-125`** (`edge profile sends fewer announcements than core (bounded fanout)`) — two
