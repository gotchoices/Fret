### Two scaffold changes this ticket must make first

- **`Hooks.served` is a bare counter and `registerAnnounceWithHooks` passes
  `() => { h.served++ }`.** The normalizing rows need the snapshot that reached `onAnnounce`, so
  add `lastAnnounce?: NeighborSnapshotV1` beside `lastLeave` and widen the callback to
  `(_from, snap) => { h.served++; h.lastAnnounce = snap }`.
- **`snapshot(over)` already sets `successors: []`, `predecessors: []`, `sig: ''`,** so a
  "missing" row cannot be written by override alone — it needs a `delete`, the way the leave
  matrix's `without(field)` helper does it.

### Parser behavior per field (from `makeSnapshotParser`, verified)

A reject drops the whole message: the seam closes, no reply is sent, `onAnnounce` never runs.

- `from` — must satisfy `isPeerIdString`. Wrong type, missing, unparseable, empty → **reject**.
- `timestamp` — must be a finite `number`, with no coercion, so `'5'` and `null` both reject.
  Wrong type or missing → **reject**. (`NaN` is unreachable over the wire: JSON encodes it as
  `null`, which the `null` row already covers.)
- `successors` / `predecessors` — `boundedStringArray(value, cap)`: any non-array, including
  missing, → `[]`; otherwise **truncate to `cap` first, then drop non-strings**. That order is
  deliberate and is itself worth a row. **Normalizes.**

`registerAnnounceWithHooks` passes `makeSnapshotParser({ successors: 16, predecessors: 16,
sample: 8 })` explicitly, mirroring `FretService` — so 16 is the cap the over-cap rows are
written against.

### Constraint that does *not* apply here

`MatrixRow` in `malformedMatrix()` carries a `counts:` field that `runMatrix` requires on every
reject row. That is the **wire tier** (`describe('over the memory transport')`), a different
table. Rows added by this ticket live in the body-level drop-hooks describe and have no such
field.

## Tests to add

One row per field per way of being wrong. Every row must be handled without throwing out of the
handler, without leaking the stream, and with release-exactly-once holding. **Assert the release
arm, not merely the count** — every case here is a `close`, and the count alone passes for an
abort too, so it would prove nothing about the rule that body-level drops close.

- `from`: unparseable string, empty string, number, array, object, `null`, missing — all
  **reject**, all with `reasons: ['parse']` and no identity-mismatch count.
- `timestamp`: numeric string `'5'`, non-numeric string, boolean, `null`, missing — all
  **reject**. The numeric-string row is worth stating on its own precisely because nothing
  coerces.
- `successors` / `predecessors`: non-array (number, string, object, `null`), missing, and an
  array of non-strings — all **normalize to `[]`**. Over cap (20 ids against the cap of 16) keeps
  exactly the first 16, in order. A mixed valid/invalid array keeps the strings and drops the
  rest.
- One row for the truncate-then-filter **order**: a list of `cap` non-strings followed by a
  trailing valid string past `cap` must normalize to `[]`, with the trailing valid string
  *absent*. Filter-then-slice would keep it, so the row fails if the two are ever swapped. This
  mirrors the leave matrix's `validPastTheSlice` row.
