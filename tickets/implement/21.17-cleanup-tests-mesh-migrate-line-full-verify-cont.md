## What was done (already landed, no need to redo)

Ran `cd packages/fret && node --import ./register.mjs node_modules/mocha/bin/mocha.js
"test/proactive-announce.spec.ts" --timeout 30000`. All 4 tests passed on assertions, but the run
exited 1: the exit watchdog (`test/mocha-exit-watchdog.ts`, wired via `.mocharc.json`) reported the
process still alive 10s after the last test, with one dangling `Timeout` and no handles/requests.

Bisected with `--grep` per test. The culprit is `peer disconnect triggers proactive announcement
to remaining neighbors`: run in isolation it reproduces the same watchdog trip; the other three
tests (`on-start announce...`, and — by earlier full-file evidence — `edge profile...` /
`new peer discovery...`) do not.

Root cause, confirmed by diffing against the pre-migration version of the file (`git show
7074998:packages/fret/test/proactive-announce.spec.ts`): that test abruptly stops `nodes[2]`
mid-test (simulating an ungraceful disconnect) and only skips `nodes[2]` in teardown — the
*service* at index 2 was still stopped unconditionally in the old hand-rolled teardown
(`await Promise.all(services.map(s => s.stop()))`, no filtering). The migrated version's teardown,
`await mesh.stop({ skip: [2] })`, skips **both** the service and the node at that index (that's
`Mesh.stop`'s documented contract in `helpers/mesh.ts` — "Both the service and the node at each
index are skipped"). So service 2's `FretService` was left running forever with its stabilization
timers armed — the parent ticket's migration mapping dropped a call it shouldn't have, not a
premise or assertion.

Fix applied to `packages/fret/test/proactive-announce.spec.ts`, in the disconnect test's teardown
(right before `await mesh.stop({ skip: [2] })`):

```ts
// Node 2's libp2p node is already down, but its FretService is not — mesh.stop's `skip`
// leaves both alone, so the service must be stopped explicitly or its internal timers
// (stabilization interval, etc.) leak past the test.
await mesh.services[2]!.stop()
await mesh.stop({ skip: [2] })
```

This restores the original semantics (every service always gets `.stop()` called exactly once;
only the already-dead node is excluded from the node-stop pass) without changing `Mesh.stop`'s
general contract, which the jsdoc states deliberately and which other specs may rely on as-is —
so `helpers/mesh.ts` itself was **not** touched.
