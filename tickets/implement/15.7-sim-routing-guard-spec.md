Split (3 of 3) from `15.5-sim-router-realism` — the guard the whole effort exists to create.
Prereqs (`sim-churn-lazy`, `sim-route-local-selector`) have landed: the sim routes through the
shipped `chooseNextHop` over each peer's own store, and churn is lazy with a paired join per
leave. This ticket adds the measurement and corrects documentation.

### New spec: `packages/fret/test/simulation.routing.spec.ts`

- **Converged case**: seeded N≈200 uniform ring, m=8, k=15, no churn, run to convergence; then
  ~100 routes from random live sources to random target coordinates. Assert routing success ≥ a
  threshold and p90 hop count ≤ an O(log N) bound.
- **Churn case**: same shape at moderate churn, lower success threshold.
- **Set both thresholds from measured values, minus a stated margin — write the measured numbers
  into a comment beside them.** A threshold picked before running proves nothing.
- **Prove the guard bites before calling it done.** Temporarily swap `minDistance` for a broken
  metric in `src/ring/distance.js` usage (`clockwiseDistance` alone is the cheapest break) and
  confirm the new spec fails — success rate and/or hop count must visibly move. Record the
  observed broken-vs-healthy numbers in the spec's header comment as evidence the harness now
  guards the metric. Revert the swap; do not commit it.
- **Cover the originator-nearest case explicitly**: a route whose source is itself the peer
  nearest the target must succeed (the sim applies the strict-improvement floor only from hop 2;
  this case pins that).
- **Keep `capacity` unset** in this spec — with capacity set, eviction can fail routes that
  previously succeeded (expected, not a regression); the threshold must measure routing, not
  eviction.

Mechanics (all confirmed against current code):

- `FretSimulation.scheduleRoute(fromPeerId, targetCoord, atMs)` exists (`fret-sim.ts:313`);
  `run()` processes events until `durationMs`, so schedule routes at times within it. Random
  targets: 32-byte `Uint8Array` coordinates drawn from a seeded RNG (the sim's
  `DeterministicRNG` is importable from `test/simulation/deterministic-rng.js`).
- **p90 over successful routes only.** `MetricsCollector.recordRoute(success, hops)`
  (`sim-metrics.ts:145`) pushes `hops` into `routingHops` for failures too, and
  `avgRoutingHops` averages over all attempts. Take the percentile over successful routes' hop
  counts explicitly or failure partials skew the bound. `percentileSummary` helper exists in
  `sim-metrics.ts:62`; if per-route success/hops pairs are not reachable from `SimMetrics`,
  extend the collector minimally (e.g. a `successfulRouteHops` array) rather than inferring.
