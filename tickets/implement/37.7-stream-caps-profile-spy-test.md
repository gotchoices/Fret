## What already landed (do not re-derive — read and confirmed at HEAD)

- `FretService.streamCaps()` — private, `src/service/fret-service.ts:2087`. Returns
  `{ maxInboundStreams: 128, maxOutboundStreams: 256 }` for the `core` profile and
  `{ maxInboundStreams: 32, maxOutboundStreams: 64 }` otherwise. Hard-coded literals, no config knob.
- `registerRpcHandlers()` — `fret-service.ts:1273` — computes `const streamCaps = this.streamCaps()`
  at its top and passes it as the **last** positional argument to all four registrar calls
  (`registerNeighbors`, `registerMaybeAct`, `registerLeave`, `registerPing`). It is on the `start()`
  path, so a start→stop→start cycle re-applies it.
- Each registrar takes one optional trailing `streamCaps: StreamCaps = {}` and forwards it by
  spreading it into the handler-registration options object:
  - `registerNeighbors` (`src/rpc/neighbors.ts:47`) — spreads `...streamCaps` into **both**
    `registerJsonHandler` calls it makes: the reply-only `PROTOCOL_NEIGHBORS` and, guarded by
    `if (onAnnounce)`, `PROTOCOL_NEIGHBORS_ANNOUNCE`.
  - `registerLeave` (`src/rpc/leave.ts:29`) and `registerPing` (`src/rpc/ping.ts:32`) — spread into
    their single `registerJsonHandler` call.
  - `registerMaybeAct` (`src/rpc/maybe-act.ts:27`) — spreads into `registerRpcHandler`'s options
    (`{ ...streamCaps }`, last argument of the call).
- The five protocol ids come from `makeProtocols(networkName)` in `src/rpc/protocols.ts`:
  `${prefix}/neighbors`, `${prefix}/neighbors/announce`, `${prefix}/maybeAct`, `${prefix}/leave`,
  `${prefix}/ping`, where `prefix = /optimystic/${networkName}/fret/1.0.0`.

## The test to write

A new spec (suggested `test/rpc.stream-caps-profile.spec.ts`) with a cheap spy on `node.handle`,
asserting the service passes Core 128/256 and Edge 32/64 through for **all five** protocols — in
the spirit of the acceptance-cap specs in `test/rpc.snapshot-merge-cap.spec.ts`, which count real
calls rather than inferring a bound from the absence of a crash. Counting real `node.handle` calls
is what actually pins the profile split.

It must also cover the **start→stop→start** case: `stop()` unhandles all five protocols and
`start()` re-registers them, so assert the caps are still applied after a full cycle rather than
assuming it.

Note the announce protocol is only registered when `onAnnounce` is supplied — `FretService` always
supplies it, so all five should appear, but a spy asserting "five distinct protocols" catches it if
that ever changes.

Verify first whether `registerJsonHandler` / `registerRpcHandler` in `src/rpc/protocols.ts` forward
`maxInboundStreams` / `maxOutboundStreams` into the `node.handle` options object under those exact
names — the spy asserts on what reaches `node.handle`, so that mapping is the thing under test.
