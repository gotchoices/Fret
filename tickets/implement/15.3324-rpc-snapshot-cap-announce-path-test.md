## The gap

The caps (Core 16 successors / 16 predecessors / 8 sample; Edge 8/8/6) live only at the snapshot
parser. `mergeSnapshotCaps()` (`src/service/fret-service.ts:1760`) feeds `makeSnapshotParser(...)`
at two call sites; neither merge loop slices any more. Read the `NOTE:` above that method first.

The tests that landed apply the parser **by hand inside the test body**
(`parsed()` in the `describe('announce snapshot merge caps')` block,
`test/rpc.handler-fuzz.spec.ts:1598`). That keeps the suite honest about the caps' *values*, but it
restates the wiring rather than proving it: unwire the parser at `fret-service.ts:1033` and every
existing test still passes.

Assert on **counted loop work** — a spy wrapping `store.upsert`, the existing `countUpserts` helper
(`test/rpc.handler-fuzz.spec.ts:1611`) — not on the absence of a crash. A cap that silently stopped
applying would leave a passing no-crash test and an unbounded per-message cost.

## Established facts — do not re-derive

Wiring, confirmed by reading:

- `registerRpcHandlers` (private, `fret-service.ts:1019`) passes `makeSnapshotParser(this.mergeSnapshotCaps())`
  as the **8th positional argument** to `registerNeighbors` (`fret-service.ts:1033`), the
  `snapshotParser` parameter. `registerNeighbors` (`src/rpc/neighbors.ts`) hands it to
  `registerJsonHandler` as `parse` on `protocols.PROTOCOL_NEIGHBORS_ANNOUNCE`.
- That handler's `serve` drops the message without replying unless `snap.from` equals
  `connection.remotePeer.toString()`. So the `remote` argument to the test rig's `invoke` must be
  the same id the body's `from` carries, or the merge never runs and the count is silently 0.
- `registerNeighbors`' `snapshotParser` **defaults to `Infinity` caps** ("validate the shape,
  truncate nothing"). That default is what a test gets if it registers the handler itself instead
  of going through `registerRpcHandlers` — which is precisely why this test must go through the
  service.

Complications, established by the prior run:

- `handleAnnounce` (`fret-service.ts:1772`) **detaches** the merge, so an upsert count taken around
  the handler call is not deterministic. Wrap `mergeAnnounceSnapshot` on the instance to capture
  and await the promise it returns; the snapshot argument still arrives through the real parser
  that way.
- The neighbors handler's `onInbound` callback runs `noteInboundRpc(from)`, which **also upserts
  `from`** — detached, racing the merge's own first upsert. It is guarded by
  `if (!this.store.getById(id))`, so pre-seeding `from` into the store before the test makes it
  short-circuit and the count deterministic.
- `registerRpcHandlers` is private and registers all five protocols; it can be called directly on
  an unstarted service via a cast. **Do not `start()`** — stabilization and peerStore seeding drag
  their own upserts into the counter.
- The `fakeNode()` / `invoke(protocol, stream, remote)` rig at `test/rpc.handler-fuzz.spec.ts:214`
  records handlers instead of registering them, which is the cheap way to invoke one directly. Its
  node stub has **no `peerId`**, and `enforceCapacity` / `applyTouch` both reach
  `selfCoord()` → `hashPeerId(this.node.peerId)` — so either give the stub a real peer id or patch
  `handle` on a real mem node instead. (A real mem node is what the existing caps block already
  builds via `createMemNode()`, so patching `handle` on it is likely the shorter route.)
- `test/announce-rate-limit.spec.ts:154-162` owns the caps-are-one-source-of-truth claim
  (a deep-equal against the literal Core/Edge numbers). Leave it alone; do not restate those
  numbers anywhere else.

Reusable fixtures already in the `announce snapshot merge caps` block
(`test/rpc.handler-fuzz.spec.ts:1559` onward): `FROM`, `OVER_SUCC` (40), `OVER_PRED` (40),
`OVER_SAMPLE` (20), `overCapBody()`, `countUpserts()`, and the `profiles` table pinning the
expected Core/Edge caps. Module-scope helpers: `peerIdStr`, `sampleCoord`, `framed`, `json`,
`decodeFramed`, `inboundStub`. The fetch-path ticket wants these too — if a fixture has to move to
a wider scope to be shared, moving it here (rather than copying it there) is the intended shape.
