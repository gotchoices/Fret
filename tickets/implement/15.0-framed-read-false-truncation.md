## Invariant to restore

A frame the remote actually wrote is never reported to the caller as truncated. `readFramed`
(`src/rpc/protocols.ts`) violates it: its 20 ms poll consults stream-level EOF state
(`remoteFinishedWriting`: `readBufferLength === 0 && remote/read status closed`) while delivered
bytes can still sit in two buffers *below* that layer (libp2p's iterator `it-pushable` +
`lp.decode`'s buffer), so it raises `FrameTruncationError` on a healthy connection carrying a
complete reply. Reproduced deterministically (two mem nodes, reply-only handlers, varying
microtask depth before the reply write); the failing depth is a phase alignment that MOVES
between runs — never build a depth-indexed test. Fix at the seam; do not constrain handler bodies.

## Recipe (every decision settled; follow verbatim)

**Dependencies** (`packages/fret/package.json`): add `"@libp2p/utils": "^7.0.10"` to
`dependencies` (installed transitively at 7.0.10 via libp2p 3.x — same tree). For varint decode
either add `uint8-varint` (also transitively installed; read its installed version from
`node_modules/uint8-varint/package.json` for the caret) or hand-roll the ≤8-byte decode loop —
adding the dep preferred. `yarn install` after editing; confirm `@libp2p/utils` still resolves
7.0.10. One remaining lookup: the `byteStream` export subpath in
`node_modules/@libp2p/utils/package.json` `exports` (implementation lives at
`dist/src/stream-utils.js`; subpath likely `@libp2p/utils/stream-utils`).

**`readFramed` becomes two implementations behind the unchanged signature**
`(stream, maxBytes, timeoutMs = RPC_TIMEOUT_MS, opts: { signal? })` — pinned public export
(`test/package-exports.spec.ts`). Keep the three entry checks verbatim: Infinity-mode requires
`opts.signal` (throw), `!(timeoutMs > 0)` (throw, catches NaN), already-aborted signal (throw
`abortReasonError`). Delete `EOF_POLL_MS`, `remoteFinishedWriting`, `ReadEndState`, `POLL_TICK`,
and the poll loop.

**Dispatch** — take the real-stream path iff ALL six are functions on the object: `closeRead`,
`addEventListener`, `removeEventListener`, `send`, `push`, `log` (stream-utils' `isValid`
surface + `closeRead`, which its `isEOF` needs — `isEOF` takes its stream branch only via
`typeof obj?.closeRead === 'function'`, so a stream passing `isValid` but lacking `closeRead`
makes `byteStream.read` hang until the signal fires). Everything else → iterable path. This
keeps every existing test stub on the iterable path (rpc.request.spec's drain stubs define
`addEventListener` but lack `closeRead`/`push`/`log`; rpc.stream-errors.spec stubs have none).

**Clock plumbing** (both paths): finite `timeoutMs` → `const d = deadline(timeoutMs,
opts.signal)` (`src/utils/deadline.js`), read under `d.signal`, `finally d.cancel()`. On a read
error: `opts.signal?.aborted` → `throw abortReasonError(opts.signal)` (caller checked first);
else `d.signal.aborted` → `throw new Error(\`read timed out after ${timeoutMs}ms\`)` (prefix
pinned by `payload-bounds-ttl.spec.ts:101,117`); else rethrow. `timeoutMs === Infinity` → use
`opts.signal` directly, abort → `abortReasonError(signal)` (`rpc.protocols.spec.ts:557-560` pins
that an Infinity-mode abort does NOT surface 'read timed out').

**Stream path** — `const bs = byteStream(stream)`. Facts from the installed source:
`bs.read({ bytes: N, signal })` with `bytes` set NEVER returns null; clean EOF throws
`UnexpectedEOFError`. Do NOT call `read()` bare — a bare read returns the whole buffer, not one
byte.
- Prefix loop: read 1 byte at a time, append to a buffer, try varint decode after each byte:
  - Partial varint → uint8-varint `decode` throws `RangeError('Could not decode varint')`
    (mechanism: reads at most 8 slots; undefined bytes fall through to the throw). Buffer < 9
    bytes → keep reading; ≥ 9 → `throw new PayloadTooLargeError(`payload too large: declared
    length exceeds ${maxBytes} byte limit`)` (any ≥9-byte varint declares ≥ 2^56 > every FRET
    cap; message keeps the pinned 'payload too large' prefix).
  - Decode succeeds → `declared`. No MAX_SAFE_INTEGER guard needed: an 8-byte varint decodes
    imprecisely up to ~2^56 without throwing, and the very next check subsumes it. If
    `declared > maxBytes` → `throw new PayloadTooLargeError(`payload too large: ${declared}
    exceeds ${maxBytes} byte limit`)` — EXACT message pinned by `rpc.request.spec.ts:411`.
    Buffer is exactly the varint (stop at first success), so no over-read to hand back.
  - `UnexpectedEOFError` (match by `err.name`) during prefix: 0 bytes accumulated →
    `FrameTruncationError('stream ended before a framed message arrived')`
    (`payload-bounds-ttl.spec.ts:121-129` pins the NAME for close-without-any-frame); partial
    prefix → `FrameTruncationError('stream ended before a whole framed message arrived')`.
- `declared === 0` → return `new Uint8Array(0)` (empty frame is valid here; `decodeJson` rejects
  it downstream).
- Body: `(await bs.read({ bytes: declared, signal })).subarray()`. A truncated body's
  `UnexpectedEOFError` propagates unchanged — `isFrameTruncationError` already matches that name,
  and `rpc.stream-errors.spec.ts:386` accepts either name.
- `finally`: `try { bs.unwrap() } catch { /* unwrap() pushes unread trailing bytes back via
  stream.push(), which throws StreamStateError when readStatus is 'closed' — listeners are
  already removed before the push, so swallowing is safe */ }`.

**Iterable path** (plain async iterables — tests, non-libp2p sources): keep `lp.decode` with the
`onLength` cap and the existing `InvalidDataLengthError` → `PayloadTooLargeError` mapping; one
held `pending = iter.next()` (never re-issued) raced against the ABORTED sentinel and, in finite
mode, one deadline timer — no poll, no stream-state consultation. `done` →
`FrameTruncationError('stream ended before a framed message arrived')`; value →
`result.value.subarray()`. Keep the abort-listener-removal `finally` and the
`pending.catch(() => {})` belt-and-braces.

**Docs in protocols.ts only** (external docs belong to the companion ticket): replace the
"race-free because the poll fires on a macrotask" paragraph and the `EOF_POLL_MS` NOTE with what
the fix guarantees — stream path reads frames at the same layer as the stream's own EOF state
(one buffer, no blind spot, no timer), iterable path ends on iterator EOF alone.

**Callers need no changes**: `rpcRequest` (`src/rpc/request.ts`) already calls
`readFramed(stream, maxBytes, Infinity, { signal: d.signal })`; inbound handlers use the finite
default. Signature and both modes preserved.
