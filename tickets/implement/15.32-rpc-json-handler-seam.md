## Design — `registerJsonHandler`

Two overloads over `registerRpcHandler`. Two of the five protocols read no request body (ping, and
the neighbors *request*); forcing a body-less protocol through a decode step would be worse than the
repetition it removes.

```ts
interface JsonRequestHandlerOpts<Req, Res> {
	maxBytes: number;
	parse: Parser<Req>;
	/** Return `undefined` to drop without replying (the identity-mismatch case). */
	serve: (msg: Req, connection: Connection) => Promise<Res | undefined> | Res | undefined;
	/** Counter hook for a body-level drop; the service wires it to `diag.rejected.malformed`. */
	onMalformed?: (reason: 'decode' | 'parse') => void;
	closeBudgetMs?: number;   // test-only pass-through to registerRpcHandler
}

interface JsonReplyOnlyHandlerOpts<Res> {
	serve: (connection: Connection) => Promise<Res> | Res;
	closeBudgetMs?: number;
}

export function registerJsonHandler<Req, Res>(node: Libp2p, protocol: string, opts: JsonRequestHandlerOpts<Req, Res>): Promise<void>;
export function registerJsonHandler<Res>(node: Libp2p, protocol: string, opts: JsonReplyOnlyHandlerOpts<Res>): Promise<void>;
export function registerJsonHandler(
	node: Libp2p,
	protocol: string,
	opts: JsonRequestHandlerOpts<unknown, unknown> | JsonReplyOnlyHandlerOpts<unknown>
): Promise<void> {
	return registerRpcHandler(node, protocol, async (stream, connection) => {
		if (!('parse' in opts)) {                      // reply-only: reads no body at all
			sendFramed(stream, await encodeJson(await opts.serve(connection)));
			return;
		}
		const bytes = await readFramed(stream, opts.maxBytes);  // frame-level failures propagate
		let decoded: unknown;
		try {
			decoded = await decodeJson(bytes);
		} catch (err) {
			opts.onMalformed?.('decode');
			log.error('%s: undecodable body - dropping - %e', protocol, err);
			return;
		}
		const msg = opts.parse(decoded);
		if (msg === undefined) {
			opts.onMalformed?.('parse');
			log.error('%s: body rejected by parser - dropping', protocol);
			return;
		}
		const res = await opts.serve(msg, connection);
		if (res === undefined) return;                 // drop without replying; seam still closes
		sendFramed(stream, await encodeJson(res));
	}, { closeBudgetMs: opts.closeBudgetMs });
}
```

`'parse' in opts` is the discriminator (TS narrows on it); the reply-only shape has no `parse` key.

### The drop/abort rule — document it once, at the function

- **Frame-level failure aborts.** Truncation, `PayloadTooLargeError`, a reset — the stream is already
  broken, or the remote is misbehaving at the framing layer. These propagate out of
  `registerJsonHandler` and `registerRpcHandler`'s error arm aborts, exactly as today.
- **Body-level failure closes.** Undecodable JSON, a non-object top level, a parser rejection, an
  identity mismatch. The peer framed correctly and is alive; the message is worthless. The handler
  returns normally without replying, so the seam's budgeted `close()` runs. `onMalformed` fires first
  so the drop is counted.

This is the plan's *"a validator failure must be a drop, never an abort"*, and it subsumes the
existing identity-mismatch behavior rather than adding a second path beside it.

### `registerNeighbors` signature — threading the parser without breaking test callers

Existing test callers pass 4–6 positional args and **must keep compiling**
(`test/churn.leave.spec.ts:431`, `test/identity-verification.spec.ts:81,102`,
`test/rpc.handler-fuzz.spec.ts:403`). TypeScript forbids a required parameter after an optional one,
so add two **trailing** params:

```ts
snapshotParser: Parser<NeighborSnapshotV1> = makeSnapshotParser({
	successors: Number.POSITIVE_INFINITY,
	predecessors: Number.POSITIVE_INFINITY,
	sample: Number.POSITIVE_INFINITY,
}),
onMalformed?: (reason: 'decode' | 'parse') => void
```

The `Infinity` default means "validate the shape, truncate nothing" — it copies **no** cap numbers,
and `Array.prototype.slice(0, Infinity)` is well-defined. `FretService` always supplies
`makeSnapshotParser(this.mergeSnapshotCaps())`, so production truncation is unchanged. Give
`registerLeave` an `onMalformed?` the same way (its 4 params are all in use; append a 5th).

### Ordering that must not move

- The rate-limit bucket stays **first** on maybeAct. `registerJsonHandler` parses inside the handler
  body, so a bucket taken at the top of `serve` would be too late — **maybeAct therefore stays on
  `registerRpcHandler`** with its parser call inside `handleMaybeAct` (already the case; that
  function needs **no** change). Put a `NOTE:` at the maybeAct *registration* so the asymmetry reads
  as deliberate.
- `staticReject()` stays the maybeAct parser-failure reply and still increments
  `diag.rejected.malformed`. Do not compute real anchors on a rejection.
- `validateTimestamp`'s ±30 s window equals `DEDUP_TTL_MS` on purpose. The parsers check that
  `timestamp` is a finite **number**; they do **not** check freshness. Freshness stays in
  `fret-service.ts`.
- Identity mismatch stays a **close-drop** and still increments `diag.rejected.identityMismatch`. It
  runs inside `serve` (which owns `connection`), after the parser has vouched that `from` is a
  parseable peer id.
- Ping and the neighbors request must **not** gain a `readFramed` call, and their `onInbound`
  membership promotion must still fire — call it inside the reply-only `serve`.

### Other edge cases

- **Release-exactly-once must hold unchanged** on every new drop path: a parser rejection returns
  normally, so one budgeted close and no abort; a truncated frame, so one abort and no close.
- No handler body may call `close()` itself — a bare close pre-empts the seam's budget.
- A `sample` entry whose `coord` decodes to the wrong byte length must be dropped by the parser, not
  reach `upsert` — the store's write seam throws on a non-32-byte coordinate, and a throw inside the
  merge loop is exactly the leak the seam was built to stop. `makeSnapshotParser` already does this.
