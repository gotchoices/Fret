**Determinism is the sharp trap.** All four scoring entry points default `now = Date.now()`.
Every call must pass sim time explicitly or same-seed replay diverges — surfacing as flaky
thresholds, not errors. `recencyScore` half-life is 60 s vs sim runs of 4–60 s, so recency is a
live term. Writing `lastAccess: simTime` in scoring patches *improves* determinism (upsert stamps
wall-clock) but reorders `reprobeDeadEntries` (sorts ascending `lastAccess`) — re-run
`test/simulation.partition.spec.ts`.

## Edge cases (all from the settled design; verify, don't re-derive)

- `capacity < 2m + 1`: protection outranks cap — store stays over capacity; current
  slice-based eviction can't loop, and must never evict a protected id
- store smaller than `m`: walk returns fewer per side; protection must not assume `m`
- churn: `contactSweep` prunes departed ids → a scoring call must tolerate `getById` returning
  `undefined` (relevant if a helper re-reads after remove)
- merge that skips a locally-`dead` entry skips its scoring too (else the skip's point —
  no resurrection, deterministic `lastAccess` — is lost)
- bus mode and instant mode take the same scoring path (sites 3 and 4 must not diverge — hence
  the shared-helper suggestion)
- `capacity` unset (every existing sim spec): scoring writes relevance but nothing evicts — **no
  existing threshold may move**
