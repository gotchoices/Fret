## Not in scope: changing `src/`

`src/store/relevance.ts` is consumed as-is. Exports, all pure over
`(PeerEntry, x, SparsityModel, now)`: `createSparsityModel`, `normalizedLogDistance`,
`observeDistance`, `sparsityBonus`, `initialRelevance`, `touch`, `recordSuccess`, `recordFailure`.
`touch` / `recordSuccess` / `recordFailure` return a **new entry object** (relevance, lastAccess,
counters updated); `initialRelevance` returns just the number. Write-back is
`store.getById(id)` -> score -> `store.update(id, patch)`.

Cross-module **type** imports must be `import type` (`verbatimModuleSyntax`; the runtime loader
strips types per file, so a plain type import throws at runtime while `tsc` stays silent).

## Determinism is the sharp trap

All four scoring entry points default `now = Date.now()`. Every call must pass sim time explicitly
or same-seed replay diverges — surfacing as flaky thresholds, not errors. `recencyScore`'s
half-life is 60 s against sim runs of 4–60 s, so recency is a live term. Writing
`lastAccess: simTime` in scoring patches *improves* determinism (`upsert` stamps wall-clock) but
reorders `reprobeDeadEntries`, which sorts ascending `lastAccess` — re-run
`test/simulation.partition.spec.ts`.

## Edit 1 — `test/simulation/liveness.ts` (seam widening)

Current exact signatures: `contactSweep(selfId, store, time)` (its failure and success calls both
have `entry` / `time` in scope); `recordContactFailure(store, entry, time)`;
`recordContactSuccess(store, entry)` — whose body is an early-out `if (entry.contactFailures > 0)`
under a stale doc comment reading "Written only when there is one to clear";
`reprobeDeadEntries(selfId, store, time)`. `LivenessDeps` currently holds only
`contactAllowed(a, b)` and `isAlive(id)`.

- Add to `LivenessDeps` (and the constructor + private fields): `modelFor(selfId: string):
  SparsityModel`, `coordOf(id: string): Uint8Array`, `now(): number`. Add
  `import type { SparsityModel }` and value imports
  `{ recordSuccess, recordFailure, normalizedLogDistance }` from `'../../src/store/relevance.js'`.
- `recordContactSuccess(selfId: string, store, entry)` — add `selfId`. Body: compute
  `x = normalizedLogDistance(this.coordOf(selfId), entry.coord)`, then `const scored =
  recordSuccess(entry, undefined, x, this.modelFor(selfId), this.now())` — latency deliberately
  `undefined`, since the sim models no link latency and `avgLatencyMs` must stay `null` — then
  `store.update(entry.id, { relevance: scored.relevance, lastAccess: scored.lastAccess,
  accessCount: scored.accessCount, successCount: scored.successCount, contactFailures: 0 })`.
  It now writes on **every** call, not only when a strike run exists — replace the stale doc
  comment. Add a comment noting that `contactSweep` calls this for every reachable non-dead entry
  every tick, so `accessCount` and KDE observations grow per tick per entry; that is intended
  shared-seam behavior (production's sweep is proven contact). State the magnitude in the review
  handoff.
- `recordContactFailure(selfId: string, store, entry, time)` — add `selfId`. Keep the existing
  strikes arithmetic and the dead transition exactly as they are, but score too: `const scored =
  recordFailure(entry, x, this.modelFor(selfId), time)`; the patch becomes
  `{ relevance: scored.relevance, failureCount: scored.failureCount, lastAccess: time,
  contactFailures: strikes }`, plus `state: 'dead'` on the threshold arm. (The old code stamped
  `lastAccess` only on the dead arm; scoring stamps it always — the re-probe-reordering caveat
  above.)
- `contactSweep` passes `selfId` through both calls.

## Edge cases (settled design; verify, don't re-derive)

- churn: `contactSweep` prunes departed ids, so a scoring call must tolerate `getById` returning
  `undefined` (relevant if a helper re-reads after a remove).
- `capacity` unset (every existing sim spec): scoring writes relevance but nothing evicts —
  **no existing threshold may move**.
