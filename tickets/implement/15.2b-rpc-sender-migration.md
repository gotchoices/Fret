```ts
/**
 * Ping `peer` over this network's namespaced protocol. Read-only request (the handler replies
 * without reading); dial 'always'. `ok.value.ok` is the peer's own pong flag; rttMs on the
 * outcome. Truncation/undecodable replies are `decode-error` — the service scores them as
 * proof of life.
 */
export async function sendPing(
	node: Libp2p,
	peer: string,
	protocol = PROTOCOL_PING,
	opts: { signal?: AbortSignal; timeoutMs?: number } = {}
): Promise<RpcOutcome<{ ok: boolean; size_estimate?: number; confidence?: number }>> {
	return rpcRequest(node, peer, protocol, {
		...opts,
		maxBytes: 1024,
		decode: async (b) => {
			const r = await decodeJson<PingResponseV1>(b);
			return { ok: Boolean(r.ok), size_estimate: r.size_estimate, confidence: r.confidence };
		},
	});
}
```

## Shape of the migration

**The five senders stay as thin named wrappers.** Each keeps its name, its protocol constant, its
per-protocol byte cap, its dial mode and its timeout default, and becomes a few lines over
`rpcRequest`. Their return types change to `RpcOutcome<…>`.

*Rejected:* having `FretService` call `rpcRequest` directly and deleting the wrappers. That
spreads the per-protocol byte caps, protocol constants and dial modes across ~8 service call sites
and gives each protocol no single owner — the property this whole ticket exists to establish.
`openRpcStream` / `releaseRpcStream` / `readFramed` / `sendFramed` also stay exported and
unchanged in signature (public surface, pinned by `test/package-exports.spec.ts`, documented in
docs/fret.md *Dialability*).

```ts
sendPing(node, peer, protocol?, opts?):
	Promise<RpcOutcome<{ ok: boolean; size_estimate?: number; confidence?: number }>>
	// rttMs moves onto the `ok` variant; `ok.value.ok` stays the peer's own `ok` field.
	// dial: 'always'. maxBytes 1024. Truncation/decode failures are now `decode-error`,
	// not `{ ok: false }` — the *service* keeps treating them as proof of life (see below).

fetchNeighbors(node, peer, protocol?, opts?): Promise<RpcOutcome<NeighborSnapshotV1>>
	// dial: 'never'. maxBytes 128 KB. `emptySnapshot()` is DELETED — no fabrication remains.

sendMaybeAct(node, peer, msg, protocol?, opts?):
	Promise<RpcOutcome<NearAnchorV1 | { commitCertificate: string }>>
	// dial: 'always'. maxBytes 512 KB. halfCloseBeforeRead: true.
	// `busy` leaves the union and becomes the `busy` variant.

announceNeighbors(node, peer, snapshot, protocol?, opts?): Promise<RpcOutcome<undefined>>
	// dial: opts.dial === true ? 'always' : 'never'. Write-only. STOPS SWALLOWING.

sendLeave(node, peer, notice, protocol?, opts?): Promise<RpcOutcome<undefined>>
	// dial: 'always'. Write-only. Still does not read a reply — see the parking note in 15.2a.
```

## Service-side: `noteRpcFailure` branches on the variant

`noteRpcFailure` (`fret-service.ts:669-680`) currently sniffs the error with
`isUnsupportedProtocolError` and books a contact strike for everything else. Replace it with a
variant-driven seam — same name, same "never throws" contract, same "records no backoff" rule:

| outcome | what the service does |
|---|---|
| `ok` | `applySuccess` (+ `rttMs` as a latency sample **only** on the ping paths) |
| `busy` | `recordBackoff`; no strike; alive |
| `decode-error` | relevance decay only (`applyFailure`) — **alive, never a strike** |
| `foreign-protocol` | `applyMembershipSignal(id, 'negotiate-failure')` |
| `unreachable` / `timeout` | `applyContactFailure` — the dead-state run |
| `cancelled` / `skipped` | **nothing at all**: no strike, no backoff, no decay, no `pingsFail` |

The headline behavior change: `sendMaybeAct` used to let `decodeJson`'s plain `Error`s propagate
(`maybe-act.ts:104`), so a peer that opened a stream and merely replied badly was counted
unreachable — three such replies marked it `dead`. It now lands in `decode-error` and is scored
exactly as the ping path already scores the same evidence.

Call sites to migrate (all in `fret-service.ts`): `probeNeighborLatency` (~1955),
`probeMembership` (~2110), `fetchAndMergeSnapshot` (~2165), `sendAnnouncementsRateLimited`
(~1300), `sendLeaveToNeighbors` (~1485-1525), `pingWarmupTargets` (~1385), `routeAct`'s forward arm
(~2430), and `iterativeLookup`'s probe and activity-resend arms (~2828, ~2889).

Three of them change behavior, not just shape:

- **`fetchAndMergeSnapshot`** — `skipped` (no connection, nothing attempted) must **not**
  increment `diag.snapshotsFetched`; only `ok` does. That ends the overcount `NOTE:`d at
  `fret-service.ts:2145-2160`. Delete that NOTE's "if snapshot counts are ever used for anything
  load-bearing" clause — it has been done. `foreign-protocol` now reaches `noteRpcFailure` on this
  path for the first time (today `fetchNeighbors` swallows it), so foreign classification finally
  works here.
- **`sendAnnouncementsRateLimited`** — the `wasCancelled(sig)` guard in its catch becomes
  reachable, because `announceNeighbors` no longer swallows. Rewrite the comment at
  `fret-service.ts:1300-1320` that says it "would never fire". Keep the top-of-loop
  `stopped || wasCancelled` break — it covers the stop()+start() case the outcome cannot see.
  `announcementsSent` must count only `ok`.
- **`probeNeighborLatency`** — today's `res.ok === false` branch fuses busy / empty / undecodable
  into one "peer answered badly" case. It splits into `busy` (backoff) and `decode-error` (decay
  only). `ok.value.ok === false` (the peer's own negative pong) keeps today's decay-only handling.

Everywhere a `wasCancelled(sig)` check guards a *helper result*, delete it — the `cancelled`
variant is the answer and two places agreeing on one fact is the bug class this ticket closes.
Keep `wasCancelled` itself and its uses on non-helper paths (loop tops, the `probeAndFetch` gate
between ping and fetch, `sendAnnouncementsRateLimited`'s top-of-loop break).

## Edge cases & interactions

- **A `stop()` landing mid-flight records nothing**, for every one of the nine call sites above,
  and for a pooled task the pool never started (`skipped` status from `runPooled` — a different
  thing from `RpcOutcome`'s `skipped`; do not conflate them in the code or the tests).
- **Tick-budget expiry** (`STABILIZE_TICK_BUDGET_MS`, a child of the run signal) behaves
  identically to `stop()`. Each pooled task is handed the *tick* signal explicitly, never
  defaulted from `runSignal` — preserve that.
- **The shutdown fan-out cannot reuse the run signal** (it runs after that aborts, by design) and
  carries its own `SHUTDOWN_BUDGET_MS` / `LEAVE_NOTICE_TIMEOUT_MS`. `sendLeave` returning an
  outcome must not change the `budget.signal.aborted` break at the top of both loops.
- **Write-only `ok` is not proof of receipt.** `sendLeave` / `announceNeighbors` returning `ok`
  means the body reached the transport. Do not let a service comment imply the peer acted on it.
- **Concurrent calls to the same peer** from the pooled tick: the four candidate sets are disjoint
  by construction (`test/stabilize-concurrency.spec.ts`) but `fetchAndMergeSnapshot`'s *merge* can
  still touch a peer another task is pinging. Do not make that race worse — in particular do not
  add a read-modify-write over `PeerEntry` counters that today's `applyTouch`/`applySuccess` avoid.
- **`routeAct`'s forward arm** must keep recording **no latency sample** on success: that call
  returns only once the whole downstream route completed, so `rttMs` there is the subtree's cost,
  not the link's. `ok.rttMs` being available now makes this easy to get wrong.
- **`iterativeLookup`'s `exhausted`** still covers cancellation (public `RouteProgress` has no
  `cancelled` variant — out of scope here). A `cancelled` outcome must reach the same `break` the
  `wasCancelled` check reaches today.
- **`isBusy` helpers** in `ping.ts` / `neighbors.ts` / `fret-service.ts` should collapse into the
  one place `rpcRequest` classifies busy. Do not leave a second copy behind.
