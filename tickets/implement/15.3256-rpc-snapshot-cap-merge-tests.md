## Where the work being counted actually lives

`onAnnounce` receives an **already-parsed** snapshot, so the parse + hash + upsert loop this ticket
counts is **not** inside `registerNeighbors` — it is `FretService.mergeAnnounceSnapshot`
(`src/service/fret-service.ts` ~1771; grep the symbol). Its caps come from
`FretService.mergeSnapshotCaps()` (~1751): Core `{successors: 16, predecessors: 16, sample: 8}`,
Edge `{successors: 8, predecessors: 8, sample: 6}`. The same numbers are handed to
`makeSnapshotParser`, which truncates before the loop ever runs — and that the two are the same
numbers is precisely what this ticket exists to pin.

Drive it at the service tier. The `handleMaybeAct validator consequences` describe (~727 in the
spec) is the model: stand up a real `CoreFretService` over `createMemNode()`, reach a private
method through a `DrivableService` cast, and keep the service **unstarted** so no stabilization
loop dials anything and every count is deterministic.

## Tests to add

- **A snapshot carrying more ids than the profile cap.** Assert the parse + hash + upsert loop runs
  exactly `caps.*` times **by counting the loop's own work** — a spy on the store's `upsert` or on
  the hash — rather than by inferring it from the absence of a crash. This is the test that proves
  the parser's truncation and the merge loop's `slice` are the same numbers.
- **A `sample` entry with a short `coord`.** That entry is dropped (it fails `base64urlToCoord`)
  and the rest of the snapshot still merges — skip-and-log per entry, not reject-the-message.
  Assert both halves: the bad id is absent from what `onAnnounce` received, and the good ones are
  present.

## Rig notes carried from Discovery

- `peerIdStr(seed)` (spec ~line 52) mints parseable base58btc peer ids from a byte seed; seeds must
  stay under 256 to stay distinct. Use it to build the over-long id lists.
- `registerNeighbors`' `snapshotParser` is the 8th positional parameter and defaults to
  `makeSnapshotParser(Infinity caps)` — supply it explicitly (as `FretService` does) whenever the
  case is about caps, since the default truncates nothing.
- `coordToBase64url` / `hashKey` are already imported by the spec for building coordinates.
