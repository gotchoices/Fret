## Verified library facts (trust these; sources were read)

- `lp.encode.single(bytes)` → `Uint8ArrayList` (varint prefix + body) — one `stream.send` per
  framed write. `@libp2p/interface` v3 `Stream.send` accepts `Uint8Array | Uint8ArrayList`.
- `lp.decode(source, opts)` is an async generator yielding one `Uint8ArrayList` per frame.
  Its `maxDataLength` check throws `InvalidDataLengthError` BEFORE the prefix is consumed and
  before `onLength` fires — so the declared length is unobservable there. `onLength(len)` fires
  immediately after the prefix is consumed, before any body byte is pulled or any further source
  pull (pull-count semantics identical to the library's own check).
- Zero-length frame (prefix `0x00`) IS yielded, as an empty list, in the same loop iteration.
- Clean EOF after the prefix was consumed but before any body byte: the generator completes
  silently (its buffer is empty, and the EOF throw is guarded by `buffer.byteLength > 0`).
  `UnexpectedEOFError` fires only for a partial varint or partial body still buffered at EOF.
- A varint of ≥ 9 bytes → `InvalidDataLengthLengthError`, surfaced as a rejection (not a hang).
- **The library's error classes are NOT importable** — its `exports` map exposes only
  `.`/`./decode`/`./encode`, and the root exports exactly `{ decode, encode }`. Match errors by
  `err.name` (each class sets `name`), same style as the existing `isUnsupportedProtocolError`.

```ts
/** Write one length-prefixed message. Single `send` on purpose — 15.2 owns write backpressure. */
export function sendFramed(stream: Stream, body: Uint8Array): boolean {
	return stream.send(lp.encode.single(body));
}

/** Thrown when the source ends before one whole framed message arrived. Stable name. */
export class FrameTruncationError extends Error { /* name = 'FrameTruncationError' */ }

/** FrameTruncationError, or lp's UnexpectedEOFError matched by err.name. */
export function isFrameTruncationError(err: unknown): boolean

export async function readFramed(
	stream: AsyncIterable<Uint8Array | Uint8ArrayList>,
	maxBytes: number,
	timeoutMs = RPC_TIMEOUT_MS,
	opts: { signal?: AbortSignal } = {}
): Promise<Uint8Array>
```

`readFramed` implementation (settled — no poll loop, one shot):

- Already-aborted signal → throw `abortReasonError(signal)` before anything.
- `const source = lp.decode(stream, { maxDataLength: Number.MAX_SAFE_INTEGER, onLength })` where
  `onLength = (declared) => { if (declared > maxBytes) throw new Error(`payload too large: ${declared} exceeds ${maxBytes} byte limit`) }`
  — the cap is enforced in `onLength` because the library's own check cannot see the declared
  length for the message (see facts above). Backtick-template literal, exact message: existing
  cap tests match `.include('payload too large')`.
- One `iter.next()` raced against a `setTimeout(timeoutMs)` sentinel and the abort sentinel
  (both resolve, never reject; the winner is turned into a throw by the reader). Attach
  `.catch(() => {})` to the pending next with the existing NOTE. `clearTimeout` + abort-listener
  removal in `finally`.
- Race rejection: if `err.name === 'InvalidDataLengthError'` (defensive — an 8-byte varint past
  2^53 trips the library before `onLength`), rethrow as
  `payload too large: declared length exceeds ${maxBytes} byte limit`; otherwise rethrow as-is
  (this lets `UnexpectedEOFError`, `InvalidDataLengthLengthError`, and source/reset errors
  propagate unchanged).
- Timeout won → throw `read timed out after ${timeoutMs}ms`. Abort won → `abortReasonError`.
- `result.done === true` → throw `FrameTruncationError('stream ended before a framed message arrived')`
  — covers both "ended before the prefix" and "prefix arrived, body never did, remote closed
  cleanly" (the silent-completion hole above).
- Otherwise `return result.value.subarray()` (empty frame → empty `Uint8Array`; callers'
  `decodeJson` then throws its existing `empty response` — do NOT special-case earlier).
