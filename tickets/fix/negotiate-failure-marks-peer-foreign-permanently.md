description: A peer that is merely slow to start is permanently classified as an outsider after one failed protocol negotiation, and is then excluded from the ring and from discovery with no recovery path in normal operation.
files: packages/fret/src/rpc/protocols.ts, packages/fret/src/service/fret-service.ts

Device-side correlate in gotchoices/Optimystic#11: drone logged "could not negotiate .../fret/1.0.0/ping" 9x against NAT'd peers that demonstrably served the network.

`isUnsupportedProtocolError` (`packages/fret/src/rpc/protocols.ts:32-42`) matches the "could not negotiate" message substring and is treated as a durable verdict about the peer: the call sites at `fret-service.ts:913`, `:1011`, and `:1259` respond with `markForeign(id)`. But "could not negotiate" only proves the remote had no answerable handler *at that moment* — a peer whose FRET service has not yet run `registerRpcHandlers()` (`start()` ordering), or that errored during startup and restarted, produces exactly the same failure as a genuinely foreign peer.

Once marked `foreign`, the peer is excluded from ring/cohort selection (`getNeighbors` is member-scoped, `fret-service.ts:1105-1111`) and from discovery emission (`peer-discovery.ts:76`, `fret-service.ts:1170`). The only way back is the slow foreign re-probe path, and observed field behavior (gotchoices/Optimystic#11) suggests peers can stay stuck: the always-on node logged 9x negotiate failures against cohort peers that were verifiably serving the network, and the mesh never closed.

Expected behavior: a negotiate failure is evidence, not a verdict — either retry-with-backoff before demoting, or make `foreign`-via-negotiate-failure expire so a peer that starts serving is re-admitted promptly. RPC-confirmed membership should outrank a single failed negotiation, the same principle as `fix/stale-identify-demotes-member` (identify-derived demotion of an RPC-confirmed member) — the two tickets are distinct sites in the same "foreign classification is too sticky" class and could share a fix shape (a classification-strength ordering).

Related earlier work: `complete/debt-foreign-reprobe-backoff-growth` tuned the re-probe backoff; this ticket is about the demotion being wrong in the first place.
