# Pre-existing failure: real-timer tests flake under full-suite load

## Command

From `packages/fret/`:

```
yarn test
```

(i.e. `node --import ./register.mjs node_modules/mocha/bin/mocha.js "test/**/*.spec.ts" --timeout 30000`, per `packages/fret/package.json`)

## Symptom

Two consecutive full-suite runs on the same working tree failed with **different** tests each
time. Every one of them passes when its spec file is run alone.

Run 1 — 436 passing, 2 failing:

```
1) dialability guard on outbound RPC
     routeAct forwards to the reachable candidate when nearer ones are undialable:
    forwarded to the reachable hop
    + expected - actual
    at Context.<anonymous> (test\dialability.spec.ts:222:100)

2) FRET simulation tests
     handles N=100, moderate churn (5%/s):
   Error: Timeout of 60000ms exceeded.
    at process.processImmediate (node:internal/timers:505:21)
```

Run 2 — 437 passing, 1 failing (the two above both passed):

```
1) DedupCache
     evicts an expired entry rather than a live one when at capacity:
   Error: expected live "b" to survive
    at Context.<anonymous> (test\dedup-cache.spec.ts:95:30)
```

Paths: `packages/fret/test/dialability.spec.ts:222`,
`packages/fret/test/simulation.spec.ts`, `packages/fret/test/dedup-cache.spec.ts:86-98`.

Isolated runs, same tree:

- `mocha "test/dialability.spec.ts"` → 11 passing
- `mocha "test/simulation.spec.ts" --timeout 60000` → 4 passing (the churn case took 36.9 s
  against its 60 s budget — a 1.6× margin)
- `mocha "test/peer-discovery.spec.ts"` → 17 passing

## Why this is pre-existing, not from the ticket

The ticket under review (`consolidate-discovery-emission`) is a discovery-emission change. Its
review pass touched only comments in `src/` (`fret-service.ts`, `peer-discovery.ts`), prose in
`docs/fret.md`, and added one test in `test/peer-discovery.spec.ts` — no runtime behavior
changed in this pass at all, and none of the three failing tests exercise the discovery path.
`dialability.spec.ts` also sorts before `peer-discovery.spec.ts`, so the added test cannot have
run before it.

## The shared cause

All three assert against **wall-clock timers with margins under 2×**, so they fail whenever the
machine is loaded enough to overshoot a `setTimeout`:

- `dedup-cache.spec.ts:86` builds a 150 ms TTL and sleeps 100 ms then 80 ms; if the first sleep
  overshoots to ~170 ms, entry `b` expires before the assertion that it survived.
- `simulation.spec.ts`'s churn case needs 36.9 s of a 60 s budget when the machine is otherwise
  idle.
- `dialability.spec.ts:222` routes over real libp2p nodes and dials.

This is a class, not three unrelated bugs: fake/injectable clocks in the cache and dedup tests,
and a budget matched to measured runtime for the simulation case, would retire all of it.
